status = {"web01": "up", "web02": "up", "db01": "down"}

for host, state in status.items():
    print(f"{host}: {state}")

status["db01"] = "up"            # fixed it
print(status.get("web09", "unknown"))   # no crash: unknown

Mental model: a dict is a lookup table. Lists answer "what's item number 3?"; dicts answer "what's the value for this name?" — hostnames to states, config keys to settings, container names to images.

Functions — Lesson 0005

TaskCodeNotes

Return a valuereturn f"ok: {host}"return ends the function immediately
Callmsg = check("web01")the returned value lands in the variable
Default parameterdef check(host, retries=3):caller can omit it: check("web01")
Named argumentcheck("web01", retries=5)clearer at the call site
No return statementdef log(msg): print(msg)returns None — print ≠ return
def service_report(name, state):
    if state == "down":
        return f"ALERT: {name} is down"
    return f"ok: {name}"

msg = service_report("nginx", "up")
print(msg)                     # ok: nginx

Key distinction: print() shows a value to a human; return hands a value back to the code that called the function. A function that only prints can't have its result reused, tested, or written to a file.

Reading files & string parsing — Lesson 0006

TaskCodeNotes
Open a file safelywith open("app.log") as f:auto-closes at the end of the block, even on errors
Loop over linesfor line in f:one line at a time — works on huge files
Trim whitespace/newlineline.strip()every line arrives with a trailing \n; strip it first

error_count = 0

with open("app.log") as f:
    for line in f:
        line = line.strip()
        if "ERROR" in line:
            print(line)
            error_count = error_count + 1

print(f"{error_count} errors found")

This loop is the skeleton of nearly every log-parsing task: open, iterate, strip, match, count. Learn it until you can type it without thinking.

Running commands — Lesson 0007

TaskCodeNotes
Importimport subprocessstdlib — nothing to install
Run a commandsubprocess.run(["echo", "hello"])pass command as a list of strings
Capture outputcapture_output=True, text=Trueoutput lands in result.stdout as a string
Exit coderesult.returncode0 = success; anything else = failure
Fail on errorcheck=Trueraises CalledProcessError if returncode ≠ 0
Strip trailing newlineresult.stdout.strip()command output usually ends with \n
import subprocess

result = subprocess.run(
    ["echo", "hello"],
    capture_output=True,
    text=True,
)

print(result.stdout.strip())   # hello
print(result.returncode)       # 0

Prefer a list of arguments over shell=True. A list avoids shell-injection bugs and is what interviewers expect.
