JSON

Config files and API responses are dicts and lists — written as text.

The one idea

JSON is a text format for structured data. Almost every API returns it; most config files use it. The key insight: once parsed, JSON is the Python you already know.

JSONPython
{"host": "db01"}dict
["web01", "web02"]list
"hello"str
42 / 3.14int / float
true / false / nullTrue / False / None

Parse it, then use dict keys, list loops, .get(), and if — nothing new after the parsing step.

Two functions: loads vs load

The names are easy to mix up. The s means string:

import json

# From a string — typical for API response bodies
text = '{"status": "ok", "count": 3}'
data = json.loads(text)
print(data["status"])   # ok

# From a file — typical for config on disk
with open("config.json") as f:
    cfg = json.load(f)
print(cfg["env"])

json.loads() takes a string. json.load() takes an open file object — usually inside a with open(...) block, same pattern as reading a log file.

Working with parsed data

Real configs nest objects and arrays. After parsing, walk them with skills you already have:

cfg = {
    "env": "prod",
    "timeout": 30,
    "db": {"host": "db01", "port": 5432},
    "services": [
        {"name": "nginx", "port": 80},
        {"name": "redis", "port": 6379},
    ],
}

print(cfg["db"]["host"])              # db01 — nested dict
print(cfg.get("retries", 3))          # 3 — key missing, default used

for svc in cfg["services"]:
    print(f"{svc['name']}: {svc['port']}")

In an interview, the task is rarely "parse JSON" in isolation — it's "read this config and do something with these fields." The parsing is one line; the logic is dicts and loops.
