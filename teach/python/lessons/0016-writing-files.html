Writing Files

Save a report to disk — the other half of file I/O after reading.

Recall first

From memory: what does with open("app.log") as f: do for you that a bare open() does not? Check the reference after answering.

The one idea

You have been opening files to read. Interview scripts also need to write: dump a status report, leave a summary for the next tool, save results for CI to pick up.

Same with open(...) pattern. Pass mode "w", then call write:

with open("report.txt", "w") as f:
    f.write("status: ok\n")
    f.write("checked: 3\n")

"w" means write. If the file does not exist, Python creates it. If it already exists, Python erases the old contents first, then writes. Official docs: Tutorial — Reading and Writing Files.

Include the newline yourself — write does not add one. "status: ok\n" is one line in the file.

Take the path from argv

Same CLI habit as always: the output path is an argument, not a hardcoded name.

import sys

if len(sys.argv) < 2:
    print("usage: write_report.py <outfile>")
    raise SystemExit(1)

path = sys.argv[1]

with open(path, "w") as f:
    f.write("status: ok\n")
    f.write("checked: 3\n")

print(f"wrote {path}")

Two modes you will hear about:

  • "w" — write (create or overwrite). Today’s default.
  • "a" — append (keep old contents; add at the end).

Reading still uses the default "r" (or omit the mode). Mixing them up is a common interview slip — "w" on a log you meant to read will wipe it.

Check yourself

1. What does open(path, "w") do if the file exists?

2. Which call writes one full line including newline?

3. You want to add to a file without wiping it. Mode?

Now type it for real

From memory, create write_report.py in exercises/:

  1. Import sys.
  2. If len(sys.argv) < 2, print usage: write_report.py <outfile> and exit with raise SystemExit(1).
  3. Set path = sys.argv[1].
  4. Open path with mode "w". Write exactly these two lines (each ending with \n): status: ok and checked: 3.
  5. Print wrote <path>.
  6. Run these checks:
python3 write_report.py
python3 write_report.py report.txt
cat report.txt
python3 write_report.py report.txt
cat report.txt

Expected output:

usage: write_report.py <outfile>
wrote report.txt
status: ok
checked: 3
wrote report.txt
status: ok
checked: 3

The second write must still show only those two lines — proof that "w" overwrote, not appended.
