List Comprehensions Filter Lines

One new shape today. A list comprehension builds a new list in a single expression — the interview-correct way to say “keep only the ERROR lines.”

Why this lesson

Last session (Lesson 23) you collapsed duplicates with a set. Today’s question is different: keep some items, throw the rest away, and end up with a list (order preserved). “Give me only the ERROR lines.” “Extract the hostname from each matching line.” You already know how to do this with an empty list, a for, an if, and .append(). A list comprehension is that same loop, written as one expression. One new idea, no escalation.

The one idea

A list comprehension is brackets containing an expression, a for clause, and optionally an if. It returns a new list. That is the whole pitch.

lines = [
    "INFO web-01 started",
    "ERROR db-01 connection failed",
    "WARN web-01 high load",
    "ERROR cache-01 timeout",
]

errors = [line for line in lines if line.startswith("ERROR")]
print(errors)
# ['ERROR db-01 connection failed', 'ERROR cache-01 timeout']

Read the brackets left to right:

  • line — what to put in the new list (the expression).
  • for line in lines — the loop, same meaning as a normal for.
  • if line.startswith("ERROR") — keep this item only when the condition is true.

Same job, two spellings

You already know the long form. The comprehension is a rewrite of it — not a different algorithm:

errors = []
for line in lines:
    if line.startswith("ERROR"):
        errors.append(line)

errors = [line for line in lines if line.startswith("ERROR")]

Same inputs, same outputs, same order. The long form is never wrong. The comprehension is the shape interviewers and idiomatic scripts expect when the body is one keep-or-transform step.

If the body needs two or three statements, keep the for loop. Comprehensions are for the simple case.

Change the left side to transform

The expression does not have to be the loop variable itself. Put whatever you want to keep on the left:

# keep the whole line
errors = [line for line in lines if line.startswith("ERROR")]

# keep just the hostname (second field)
hosts  = [line.split()[1] for line in lines if line.startswith("ERROR")]
print(hosts)   # ['db-01', 'cache-01']

Filter and transform in one pass: the if decides which items survive; the expression decides what each survivor becomes. Still one idea — same brackets, same for, same optional if.

Read a small script

Here is the shape you will type in a minute. Each block is tagged:

lines = [                                              # — log lines as a list
    "INFO web-01 started",
    "ERROR db-01 connection failed",
    "INFO web-02 ready",
    "ERROR cache-01 timeout",
    "WARN web-01 high load",
    "ERROR web-01 disk full",
]

hosts = [line.split()[1] for line in lines             # — transform + filter
         if line.startswith("ERROR")]

print(f"{len(hosts)} hosts with errors:")              # — count the new list
for host in hosts:                                     # — report, order kept
    print(host)

Read it top to bottom. Six log lines go in. The comprehension keeps only lines that start with ERROR, and for each survivor it stores field [1] — the hostname. The new list has three strings, in the same order the ERROR lines appeared. The report loop is ordinary; the new skill lived entirely inside the brackets.

The one trap to remember

A comprehension always builds a new list. It does not change the source:

lines = ["INFO a", "ERROR b", "ERROR c"]
errors = [line for line in lines if line.startswith("ERROR")]

print(len(lines))    # 3 — original untouched
print(len(errors))   # 2 — the filtered copy

Second trap: the if goes at the end, after the for — not at the front like a statement. [line if … for line in lines] is a different (ternary) shape and not what you want for filtering. Stick to [expr for item in xs if condition].

Nested comprehensions, dict/set comprehensions, and generator expressions are out of scope today. One pair of square brackets is enough.
