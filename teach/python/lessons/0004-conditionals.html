Conditionals

Scripts that decide: is this up or down, over threshold or fine, retry or give up.

From memory, before reading on: given cfg = {"port": 8080}, what's the difference between cfg["timeout"] and cfg.get("timeout", 30)? Answer, then check the reference if unsure.

The if statement

Same shape as the for loop you already know: a condition line ending in a colon, then an indented body that runs only when the condition is true.

state = "down"

if state == "down":
    print("ALERT: service is down")

The comparison operator is double equals. One = assigns, two == compares. Writing if state = "down": is a syntax error — Python catches it, but interviewers listen for whether you say it right.

The full comparison set: == equals, != not equals, and < > <= >= for ordering. Numbers compare as numbers: 9 < 80 is True.

elif and else

Chain checks with elif ("else if") and finish with a catch-all else. Python walks down the chain and runs the first branch whose condition is true — then skips the rest, even if they'd also be true:

load = 7.5

if load > 10:
    print("CRITICAL")
elif load > 5:
    print("WARNING")
else:
    print("ok")

# prints: WARNING  (10 > 5 is checked first; order matters)

Combining conditions

Python spells the logic operators as words: and, or, not. And the in keyword you know from lists works as a condition anywhere:

if state == "down" and env == "prod":
    print("page the on-call")

if host in maintenance_list:
    print("skip — planned downtime")

Where it clicks: inside a loop

The pattern behind half of all DevOps scripts — loop over things, act on the ones that match:

status = {"web01": "up", "web02": "down", "db01": "up"}

for host, state in status.items():
    if state == "down":
        print(f"ALERT: {host}")

Note the two levels of indentation: the if is inside the loop, and the print is inside the if.
