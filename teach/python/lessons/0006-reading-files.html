Opening a file: the with block

The standard way to read a file uses with open(...) — the same colon-plus-indented-body shape as for, if, and def:

with open("app.log") as f:
    for line in f:
        print(line.strip())

Three things happening:

  • open("app.log") opens the file; as f names the file object.
  • The with block closes the file automatically when the block ends — even if something crashes inside. This is why you'll rarely see a bare open() in professional code.
  • Looping over a file gives you one line at a time, so a 10 GB log works as easily as a 10-line one — the file is never loaded whole into memory.

Why .strip()

Every line arrives with its trailing newline character (\n) still attached. Print it as-is and you get double spacing; compare it as-is and matches fail. .strip() returns the string with whitespace removed from both ends:

line = "ERROR disk full\n"
line.strip()          # "ERROR disk full"

Stripping first is a habit worth building — subtle newline bugs are a classic way to lose minutes in an interview.

Finding and dissecting lines

Two string tools do most log-parsing work. in, which you know from lists and dicts, also tests substrings. And .split() cuts a string into a list:

line = "2026-07-04 14:02:11 ERROR disk full on /dev/sda1"

"ERROR" in line       # True
parts = line.split()  # splits on whitespace:
# ["2026-07-04", "14:02:11", "ERROR", "disk", "full", "on", "/dev/sda1"]
parts[2]              # "ERROR"  — the level
parts[0]              # "2026-07-04"  — the date

.split(",") splits on a comma instead — handy for CSV-ish data. Related and often useful: line.startswith("2026-").

The skeleton loop

Put it together and you get the shape of nearly every log-analysis script ever written:

error_count = 0

with open("app.log") as f:
    for line in f:
        line = line.strip()
        if "ERROR" in line:
            print(line)
            error_count = error_count + 1

print(f"{error_count} errors found")

Open, iterate, strip, match, count. Interviewers ask for exactly this, in some costume, more than almost anything else.

Now type it for real

First, create the practice log — paste this into a file named app.log (pasting is fine here; the drill is the parser, not the data):

2026-07-04 13:58:01 INFO service started
2026-07-04 13:59:14 WARN high latency on /api/users
2026-07-04 14:02:11 ERROR disk full on /dev/sda1
2026-07-04 14:02:45 INFO retry scheduled
2026-07-04 14:03:02 ERROR connection refused to db01
2026-07-04 14:05:19 INFO recovery complete

Then, from memory, in a new file parse_log.py:

  1. Open app.log with a with block and loop over its lines, stripping each one.
  2. If a line contains "ERROR", print it and count it.
  3. After the loop, print 2 errors found using the counter — then run it and check against the expected output below.
  4. Refine the output: for error lines, print only the time and the message — use .split() and remember you can slice into the resulting list. Aim for 14:02:11 — disk full on /dev/sda1 style, or simpler: print parts[1] and the original line. Any readable format counts; the goal is using .split() on real data.

Expected output after step 3:

2026-07-04 14:02:11 ERROR disk full on /dev/sda1
2026-07-04 14:03:02 ERROR connection refused to db01
2 errors found
