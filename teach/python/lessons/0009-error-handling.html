Error Handling

Scripts that touch the real world fail — catch predictable errors instead of crashing.

Recall first

The one idea

When something goes wrong — missing file, bad JSON, wrong dict key — Python raises an exception and stops unless you handle it. A try/except block lets you run a fallback instead of crashing.

try:
    with open("config.json") as f:
        cfg = json.load(f)
    print(cfg["env"])
except FileNotFoundError:
    print("config missing — using defaults")

Code under try: runs normally. If a matching error happens, Python jumps to the except block and continues after it. If no error, the except block is skipped entirely.

Catch the error you expect

Name the exception type after except. DevOps scripts hit the same few over and over:

What went wrongException
open("missing.json")FileNotFoundError
Invalid JSON textjson.JSONDecodeError
cfg["missing_key"]KeyError

Multiple except blocks handle different failures with different messages:

import json

try:
    with open("config.json") as f:
        cfg = json.load(f)
    print(f"env: {cfg['env']}")
except FileNotFoundError:
    print("error: config file not found")
except json.JSONDecodeError:
    print("error: config is not valid JSON")
except KeyError:
    print("error: required key missing from config")

Order matters: Python uses the first matching except. Put specific errors before broad ones.

Prefer prevention when you can

except is for failures you can't avoid. For optional dict keys, .get() with a default is still cleaner than catching KeyError. Use try/except when the whole operation might fail — opening a file, parsing JSON, calling an external command.
