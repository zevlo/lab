Script Entry Point

Run CLI code only when the file is executed — the pattern interviewers expect to see.

Recall first

From memory: what does mode "w" do to an existing file? Check the reference after answering.

The one idea

Every Python file has a built-in string called __name__. When you run the file (python3 show_host.py), Python sets __name__ to "__main__". When another file imports it, __name__ is the module name (here, "show_host") — not "__main__".

That difference lets you fence off “do the CLI work” so it runs on execute, but not on import:

if __name__ == "__main__":
    main()

Official docs: Tutorial — Executing modules as scripts and __main__ — top-level code environment.

The idiomatic shape

Put reusable logic in functions. Put argv checks and the real work in main(). Call main() only under the guard:

import sys

def status_line(name):
    return f"host: {name}"

def main():
    if len(sys.argv) < 2:
        print("usage: show_host.py <name>")
        raise SystemExit(1)
    name = sys.argv[1]
    print(status_line(name))

if __name__ == "__main__":
    main()

Why bother? Interview scripts get read by others — and later you may import a helper without wanting the CLI to fire. The docs recommend keeping the block under the guard small and calling a main function (Idiomatic usage).

Now type it for real

From memory, create show_host.py in exercises/:

  1. Import sys.
  2. Define status_line(name) that returns f"host: {name}" (does not print).
  3. Define main(): if len(sys.argv) < 2, print usage: show_host.py <name> and raise SystemExit(1); otherwise take name = sys.argv[1] and print(status_line(name)).
  4. End with if __name__ == "__main__": and call main() inside it.
  5. Run these checks from exercises/:
python3 show_host.py
python3 show_host.py web-01
python3 -c "import show_host; print('imported ok')"

Expected output:

usage: show_host.py <name>
host: web-01
imported ok

That third line is the proof: import defined the functions but did not print usage or a host line.
