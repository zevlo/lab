Sets Dedupe a List

One new shape today. A set is a collection that silently throws duplicates away — exactly what “list the unique hosts” asks for.

Why this lesson

Last session (Lesson 22) you tallied log levels with a dict — you needed to know how many of each. Today’s question is the other half: which ones, with the count thrown away. “List every host that appeared in this log, once.” “What log levels did we see?” “Drop duplicate IPs from this list.” All the same shape — and Python has a built-in for it. The set is the interview-correct answer. One new idea, no escalation.

The one idea

set(xs) returns a new collection built from xs with all duplicates removed. That is the whole pitch.

hosts = ["web-01", "web-02", "web-01", "db-01", "web-02"]

unique = set(hosts)
print(unique)         # {'db-01', 'web-01', 'web-02'}  — dups gone
print(len(unique))    # 3

Read it line by line:

  • set(hosts) — takes any iterable (list, tuple, dict keys, file lines) and returns a set.
  • Duplicates collapse silently. You do not have to check “is this already in there?” before adding.
  • The result prints with curly braces — which is why the trap below is worth a minute.

Two ways to spell it

You will see both forms in real code:

set(hosts)              # — from an existing iterable
{"web-01", "web-02"}    # — literal: braces, commas, NO colons

The literal looks like a dict literal ({...}) but has no key: value pairs — just values. If there is a colon inside the braces, it is a dict. If there is not, it is a set.

Empty braces {} are a dict, not a set. To make an empty set, write set(). There is no {}-for-empty-set spelling — the braces were taken first.

Membership works the same as lists

The in operator you already use on lists and dict keys works on a set too:

unique = set(hosts)
if "web-01" in unique:
    print("saw web-01")

Two practical differences from in on a list:

  • Speed. "x" in some_set is roughly instant regardless of size; "x" in some_list scans every element. For thousands of items this is the difference between fast and slow. (Interview trivia interviewers love.)
  • Same syntax. You do not have to remember a different operator — just put a set on the right side when membership is what you need.

Read a small script

Here is the shape you will type in a minute. Each block is tagged:

hosts = [                                                # — list with repeats
    "web-01", "web-02", "web-01", "db-01",
    "web-02", "cache-01", "web-01", "db-01",
]

unique = set(hosts)                                     # — dedupe

print(f"{len(hosts)} total entries")                    # — uses list len
print(f"{len(unique)} unique hosts:")                   # — uses set len

for host in sorted(unique):                             # — sorted for predictable order
    print(host)

Read it top to bottom. The list hosts has 8 entries with repeats. set(hosts) collapses them to 4 unique values. Two len() calls — one on the list, one on the set — give you “total” and “unique” counts side by side. The report loop wraps the set in sorted() so the output is deterministic; this is the key habit, explained next.

The one trap to remember

Sets are unordered. The order things come back from for h in unique: is not the order they went in, and not necessarily the same between Python versions or runs:

print(set(hosts))                # {'db-01', 'web-01', 'web-02'} — maybe. order varies.

for h in set(hosts):             # — order NOT guaranteed
    print(h)

for h in sorted(set(hosts)):     # — deterministic: alphabetical here
    print(h)

For a one-off glance, raw print(set(...)) is fine. For any output a human, a test, or a downstream script will read, wrap the set in sorted() before iterating. The habit is small and it kills a whole class of “works on my machine” bugs.

Need order preserved and dedupe? Look up dict.fromkeys(xs) later — not today. sorted(set(xs)) covers the interview cases.

From memory, create unique_hosts.py in exercises/. Use the small script above as your guide, then close it and type your own. Required shape:

  1. Define a list called hosts with eight string entries and intentional duplicates: "web-01", "web-02", "web-01", "db-01", "web-02", "cache-01", "web-01", "db-01".

  6. Run it from exercises/:

Expected output:

cache-01
db-01
web-01
web-02

Then — the trap check — add one extra line at the bottom: print(set(hosts)). Re-run the script and look at that last line. You should see the four hostnames inside braces, but in an order that is not alphabetical and may differ from the sorted block above it. That visual is the point: the raw set does not promise you an order. Once you have seen it, delete that line. Wrapping in sorted() — as your real loop does — is the vaccine.
