Objects Hold Data

One idea only: a class is a blueprint; each instance is its own bag of data.

Why this lesson

Lesson 18 asked you to hold too many new ideas at once (blueprint, self, methods, CLI). This session slows down. No methods. No sys.argv. Just: create two objects and see that each keeps its own data.

Recall first

From memory: how do you read the value for key "name" from a dict called host? Check the reference after answering.

You already know a bag of data

A dict groups related values under keys:

host = {"name": "web-01", "status": "up"}
print(host["name"])     # web-01
print(host["status"])   # up

An instance (object) is the same idea with different spelling — values live on the object, and you reach them with a dot:

host = Host("web-01", "up")
print(host.name)        # web-01
print(host.status)      # up

Dict key host["name"] ≈ attribute host.name. Same job: “get the name belonging to this host.”

The one idea

class Host is the blueprint. Calling Host(...) builds one new instance. Inside __init__, assignments like self.name = name put data onto that instance. Official docs: creating an instance and filling it in __init__ is how objects get their starting state (Tutorial — Class Objects, Instance Objects).

class Host:
    def __init__(self, name, status):
        self.name = name
        self.status = status

Read that line by line:

  • Host("web-01", "up") — make a new empty Host, then run __init__.
  • self — that new Host (Python passes it in; you do not write it at the call site).
  • self.name = name — store "web-01" on this Host.
  • self.status = status — store "up" on this Host.

See two bags side by side

web = Host("web-01", "up")
db = Host("db-01", "down")

print(web.name)    # web-01
print(db.name)     # db-01

web.status = "restarting"
print(web.status)  # restarting
print(db.status)   # down  ← unchanged

web and db are two different objects. Changing one does not change the other. That is the whole mental model for today.

web ──► name: "web-01"    status: "restarting"
db  ──► name: "db-01"     status: "down"

Check yourself

1. What is Host in class Host:?

2. After web = Host("web-01", "up"), what is web?

3. web.status = "down" then print db.status — if db was "up"?

Now type it for real

From memory, create two_hosts.py in exercises/:

  1. Define class Host with __init__(self, name, status) that sets self.name and self.status only. No other methods.
  2. Create web = Host("web-01", "up") and db = Host("db-01", "down").
  3. Print f"{web.name} is {web.status}" and f"{db.name} is {db.status}".
  4. Then set web.status = "restarting" and print web.status and db.status on their own lines.
  5. Run:
python3 two_hosts.py

Expected output:

web-01 is up
db-01 is down
restarting
down

That last down is the win: changing web left db alone.
