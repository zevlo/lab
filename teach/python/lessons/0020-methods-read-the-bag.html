Methods Read the Bag

One idea only: a method is a function inside the class that reads the instance’s own data through self.

Why this lesson

Last time you proved each Host(...) call makes its own bag of data (self.name, self.status). Today you add one method — a function that reads that bag. No sys.argv, no main, no entry guard. Just: bundle a format into the object and call it.

Recall first

From memory: in Lesson 19 you built a Host and reached its data with a dot. How do you print web’s name and status as web-01: up without a method — just an f-string at the call site? Write it down, then check the reference.

You already format by hand

In Lesson 19 you wrote the format wherever you printed:

web = Host("web-01", "up")
print(f"{web.name}: {web.status}")   # web-01: up

That works. But every place that prints a host has to remember the format. A method moves the format inside the object, so the object knows how to describe itself:

print(web.summary())   # web-01: up  — same result

The one idea

A method is a def living inside the class. Its first parameter is always self. Through self it reads the data on this instance. Official docs: methods are functions defined inside a class that operate on the instance (Tutorial — Method Objects).

class Host:
    def __init__(self, name, status):
        self.name = name
        self.status = status

    def summary(self):
        return f"{self.name}: {self.status}"

Read summary line by line:

  • def summary(self): — a function inside Host; self comes first, always.
  • self.name — the name stored on this instance.
  • self.status — the status stored on this instance.
  • return — hands the formatted string back to whoever called it.

The trick: self is filled in for you

When you call web.summary(), Python sees the object before the dot and passes it in as self automatically. You never write self at the call site:

web = Host("web-01", "up")

# These two lines do the SAME thing:
print(web.summary())          # you write this
print(Host.summary(web))      # what Python runs under the hood

So inside summary, self is web. That is why self.name gives "web-01" — it is reading web’s bag.

Two objects, two bags, one method

web = Host("web-01", "up")
db = Host("db-01", "down")

print(web.summary())   # web-01: up
print(db.summary())    # db-01: down

Same method, different result — because self points at a different bag each time. When you call db.summary(), self is db, so self.name is "db-01".

Now type it for real

From memory, create host_summary.py in exercises/:

  1. Define class Host with __init__(self, name, status) that sets self.name and self.status (same as Lesson 19).
  2. Add a method summary(self) that returns f"{self.name}: {self.status}".
  3. Create web = Host("web-01", "up") and db = Host("db-01", "down").
  4. Print web.summary() and db.summary() on separate lines.
  5. Then add the “under the hood” check: print Host.summary(web) on its own line.
  6. Run:
python3 host_summary.py

Expected output:

web-01: up
db-01: down
web-01: up

That third line is the win: Host.summary(web) gives the same answer as web.summary() — proof that self is just the object before the dot.
