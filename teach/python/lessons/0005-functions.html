Defining and calling

A function wraps a block of logic behind a name. Define it with def — same shape you know: a header line ending in a colon, an indented body.

def greet(host):
    print(f"connecting to {host}")

greet("web01")     # connecting to web01
greet("db01")      # connecting to db01

host is a parameter — a variable that gets its value from whoever calls the function. Defining the function runs nothing; the body only runs when it's called.

return: the part that matters

Printing shows a value to a human and throws it away. Returning hands the value back to the calling code, where it can be stored, compared, counted, or written to a file:

def service_report(name, state):
    if state == "down":
        return f"ALERT: {name} is down"
    return f"ok: {name}"

msg = service_report("nginx", "up")   # msg is now "ok: nginx"
print(msg)

Two things to notice:

  • return ends the function immediately. If the if branch returns, the second return never runs — so no else is needed. This early-return style is everywhere in real code.
  • A function with no return gives back None. If you write msg = greet("web01"), then msg is None — a classic interview gotcha. Print is not return.

Default parameters

A parameter can have a fallback value, making it optional for the caller:

def check(host, retries=3):
    print(f"checking {host} with {retries} retries")

check("web01")               # checking web01 with 3 retries
check("web01", retries=5)    # checking web01 with 5 retries

Naming the argument at the call site (retries=5) is optional but makes the intent readable — you'll see this constantly in real scripts and library calls.
