Classes Enough to Read

Recognize Thing(...) and obj.method() in other people’s code — without learning deep OOP.

Recall first

You already use classes

This is not new syntax in disguise — it is the same shape you used with Path:

from pathlib import Path

path = Path("app.log")   # create an instance
print(path.is_file())    # call a method on it
print(path.name)         # read an attribute

Path is the class (the blueprint). path is one instance (a concrete object). is_file is a method (a function attached to that object). Official framing: a class bundles data and functionality together (Tutorial — Classes).

The one idea

When you read unfamiliar Python — a CI helper, a cloud SDK snippet — you will see that same shape. Today you learn to read it, and write one tiny class so the words stick.

class Host:
    def __init__(self, name, status):
        self.name = name
        self.status = status

    def summary(self):
        return f"{self.name}: {self.status}"

host = Host("web-01", "up")
print(host.summary())   # web-01: up
print(host.name)        # web-01

Three moving parts only:

  • class Host: — define the blueprint.
  • __init__ — runs when you call Host(...); stores values on self.
  • self — “this instance.” On a call like host.summary(), Python passes host in as self automatically.

You do not need inheritance, design patterns, or “OOP philosophy” for interview reading. If you can translate obj = Thing(a) / obj.do() into “make an object, call its method,” you are done for this mission slice.

See it side by side

Loose values (what you already write):

name = "web-01"
status = "up"
print(f"{name}: {status}")

Same data, bundled (what library code often looks like):

host = Host("web-01", "up")
print(host.summary())

Same print result. The class keeps name and status together on one object, and gives you a named action (summary) that uses them.

Now type it for real

From memory, create host_status.py in exercises/:

  1. Import sys.
  2. Define class Host with __init__(self, name, status) that sets self.name and self.status.
  3. Add method summary(self) that returns f"{self.name}: {self.status}".
  4. Define main(): if len(sys.argv) < 3, print usage: host_status.py <name> <status> and raise SystemExit(1); otherwise host = Host(sys.argv[1], sys.argv[2]) and print(host.summary()).
  5. End with if __name__ == "__main__": calling main().
  6. Run these checks from exercises/:
python3 host_status.py
python3 host_status.py web-01 up
python3 -c "from host_status import Host; print(Host('db-01', 'down').summary())"

Expected output:

usage: host_status.py <name> <status>
web-01: up
db-01: down

The third command proves the class is importable on its own — same entry-point habit as Lesson 17.
