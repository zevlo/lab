Lists

A list is Python's array, and it's the workhorse of every DevOps script: hosts to ping, log lines to scan, containers to restart.

hosts = ["web01", "web02", "db01"]

hosts[0]        # "web01"   — first (zero-indexed, like bash arrays)
hosts[-1]       # "db01"    — last (negative counts from the end)
len(hosts)      # 3
hosts.append("cache01")     # now 4 items
"db01" in hosts # True      — membership test, one keyword
Bash bridge — hosts=(web01 web02 db01) becomes hosts = ["web01", "web02", "db01"]: square brackets, commas, quotes. And where bash needs "${hosts[@]}" incantations, Python lists are just… normal values. You can print them, pass them around, and put anything in them — strings, numbers, even other lists.

The for loop

hosts = ["web01", "web02", "db01"]

for h in hosts:
    print(f"pinging {h}")
print("done")
pinging web01
pinging web02
pinging db01
done

Compare with what your fingers know: for h in "${hosts[@]}"; do … done. Python drops do and done entirely. Instead:

  • The for line ends with a colon.
  • The loop body is everything indented underneath (4 spaces is the convention).
  • The first line back at the left margin — print("done") — is outside the loop.

This is the big one: in Python, indentation is not style, it's syntax. Where the indent ends, the block ends. Interviewers watch for this.

Looping N times: range()

Bash's for i in $(seq 0 4) becomes:

for i in range(5):
    print(f"attempt {i}")
# attempt 0, 1, 2, 3, 4 — five times, stops BEFORE 5

range(5) gives 0 through 4. Off-by-one confusion here is the classic beginner trap: range(5) is five numbers, and 5 is not one of them.
