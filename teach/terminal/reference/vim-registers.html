Registers & system clipboard

Registers are vim's clipboards (plural). Every yank and delete targets one; every paste reads one. The + register bridges to the macOS pasteboard. OSC 52 bridges across SSH.

The register concept

Every y, d, c, x writes the affected text to a register. Every p reads from one. Vim has dozens of slots, addressed by a " prefix followed by a single character.

:regList all registers and their contents
:reg a b +Inspect specific registers only
""pPaste from the unnamed register explicitly (same as p)
When you name a register explicitly, vim also writes the unnamed register ". So "ayy fills both a and ". The named register is your persistent copy; " is the volatile working slot.

The register families

RegisterContents
"Unnamed — default for plain y/d/p. Volatile: the next yank or delete overwrites it.
0Last yank. Never written by deletes. Recovery slot for "I yanked, then deleted, and now I want the yank back."
1–9delete/change history. 1 = most recent line-or-more delete; older shifts down to 9. 1 covers ~every real case.
-Small-delete — deletes/changes of less than one line. Read-only in practice.
a–zNamed, persistent across edits (until you overwrite them or end the session). Stash slots.
A–ZAppend to the lowercase slot instead of replacing it.
+System clipboard (CLIPBOARD on X11, pbcopy/pbpaste on macOS, clipboard on Wayland).
*Primary selection (X11 middle-click). On macOS, * and + are the same register — no PRIMARY concept exists.
_Black hole — writes discarded. Delete without clobbering ".
.Read-only — last inserted text.
%Read-only — current filename.
:Read-only — last :-command.
#Read-only — alternate file (the file you'd reach with :e #).

Using a register

The pattern is always "{register} followed by the operator (or motion). The " tells vim "the next character names a register."

"ayyYank current line into a
"apPaste from a
3"ayyYank 3 lines into a (count works as usual)
"AyAppend the next line to a
"0pPaste last yank, even after a delete clobbered "
"_ddDelete line into the black hole — " untouched
"_ciwChange inner word without saving the old one
"+yYank to system clipboard
"+pPaste from system clipboard
vip"+yYank the paragraph to system clipboard (composition)
Registers compose with everything from the grammar reference: counts, motions, text objects, visual mode. ci" becomes "aci" to send the changed text into a; vip becomes vip"+y to ship the paragraph to the OS clipboard.

System clipboard on macOS — local vim + ghostty

When vim is built with clipboard support, the + register bridges directly to the macOS pasteboard via pbcopy/pbpaste. No config, no plugin.

:echo has('clipboard')Returns 1 if your vim can talk to the system clipboard. Verify once.
:versionLook for +clipboard (not -clipboard) in the feature list.
"+yyCopy current line into the macOS clipboard
"+pPaste from the macOS clipboard
"+yiWYank a single WORD (token, URL, secret value) into the clipboard
If has('clipboard') returns 0. Your vim was built without pasteboard support (common on stripped server builds, rare on Homebrew vim). Fallback for one-off copies: select the text with the mouse, Cmd-C / Cmd-V through ghostty's terminal selection. + won't work until you install a clipboard-enabled vim.

Remote clipboard over SSH — the OSC 52 bridge

The devops-critical case: when you SSH to a remote host and run vim there, "+y puts text in the remote's clipboard — invisible to your local machine. Useless for "copy a URL from the remote vim into my local browser."

The fix is OSC 52: an ANSI escape sequence (ESC ] 52 ; c ; <base64> BEL) that means "set the system clipboard." Modern terminals — ghostty included — translate it to a host clipboard write.

set-clipboardtmux option. external (the tmux 3.7b default) forwards copy-mode yanks to the terminal as OSC 52.
tmux show -g set-clipboardVerify the option's current value.
tmux copy-mode yankInside remote tmux: select, copy. The yank flows through SSH as OSC 52, lands in ghostty, and reaches your local macOS clipboard.
Workflow: in remote tmux, Ctrl-b [ to enter copy-mode, select text, copy. Cmd-V in any local app pastes it. Full tmux copy-mode curriculum lives in the tmux phase; this reference just confirms the bridge exists and works on your stack.

Beyond the pareto

1–9 rotationEach new line-or-more delete shifts the previous into the next slot down. "1p then . replays the second-most-recent, etc. Rarely useful in practice — u or a named register is cleaner.
"=Expression register — evaluates vimscript and inserts the result. Power tool for computed inserts; out of scope until fundamentals lock.
".Last inserted text. ".p re-inserts what you just typed in insert mode — occasionally useful for repeating a snippet.
"% idioms:w !cp % /tmp/ copies the current file; :!chmod +x % makes it executable. The register itself isn't used here, but % as an ex-range or shell-argument is the same idea.
set clipboard=unnamedplusConfig that makes y/d/p target + by default. Deliberately omitted from this workspace — the user has chosen defaults-only, so all clipboard ops use the explicit "+ prefix.
