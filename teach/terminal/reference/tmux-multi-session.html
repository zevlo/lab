Multi-session habits

Named sessions as workspaces. Switch without destroying. Detach/reattach stays the same.

Mental model

one tmux server (per machine)
  ├── session ops     — incident / multi-host panes
  ├── session edit    — vim configs
  └── session logs    — long-running tails

A session is a named, persistent workspace. Windows and panes live inside it. Switching sessions moves your client; nothing is killed.

Shell (create / list / attach)

CommandDoes
tmux new -s opsCreate and attach session ops
tmux new -s logs -dCreate logs detached (stay where you are)
tmux lsList sessions
tmux attach -t opsAttach to ops
tmux switch -t logsFrom inside tmux: jump to logs

Prefix keys (stock)

From DEFAULT KEY BINDINGS in man tmux.

KeysDoes
C-b sInteractive session picker (choose-tree -Zs)
C-b (Previous session
C-b )Next session
C-b LLast session (toggle back)
C-b $Rename current session
C-b dDetach (sessions keep running)
Naming habit. Prefer short task names (ops, db, vpn) over 1/2. After SSH drop: tmux ls then tmux attach -t ops.

Beyond the pareto

kill-session, nested tmux, separate sockets (-L), fuzzy Tab picker extras. Destroy sessions only on purpose.
