Visual & block mode

When an operator + motion isn't enough — select first, then act. Block mode is the surgical tool for column-shaped edits across many lines.

Why this matters

Devops patterns that visual mode solves cleanly:

  • Comment out (or uncomment) a YAML stanza you're troubleshooting.
  • Append a suffix to every item in a list (e.g., add -v2 to every plugin name).
  • Uppercase / lowercase / case-flip a region without retyping it.
  • Substitute inside one block only — when :%s would over-match elsewhere in the file.
  • Re-indent a JSON blob you just pasted.

Knowledge 1 — three visual modes

vChar-wise — a range of characters
VLine-wise — always whole lines
Ctrl-vBlock-wise — a rectangular column

Move the cursor to extend the selection. Press Esc (or Ctrl-[) to leave.

Two essentials inside visual mode:

  • o — move the cursor to the other end of the selection. Use when you overshoot one side and don't want to start over.
  • gv — re-select the last visual selection (works from normal mode too).

Knowledge 2 — the grammar extends: operator + selection

Lesson 0001's grammar was operator + motion. Visual mode gives you a second shape: operator + selection. After selecting a region, apply any operator:

d / xDelete the selection
cChange the selection (delete + insert)
yYank (copy)
> / <Indent / dedent
=Auto-indent (format a JSON paste)
U / uUppercase / lowercase
~Toggle case of each char in the selection

Visual mode lets you see the target before the operator lands. Use it when the motion is hard to predict — large ranges, irregular boundaries, or when you're still building intuition.

Knowledge 3 — text objects as visual selectors

Any text object from Lesson 0001 doubles as a visual selector — prefix with v:

viwvisually select inner word
vi"inside a quoted string
vi(inside parens (function args)
vipinside paragraph

Use vi(...) when you want to see the region before acting, or apply an operator other than c/d/y — e.g., vi(U uppercases a function's arguments.

Knowledge 4 — block mode: the surgical column tool

Block-wise visual (Ctrl-v) selects a rectangle — the same columns across multiple lines. After selecting:

IInsert before the block on every line. Type once; Esc propagates to all lines.
AAppend after the block on every line.
cChange each line's segment; same replacement on every line after Esc.
r{x}Replace every char in the rectangle with {x}.
x / dDelete the rectangle.
The classic idiom — comment out a block: Ctrl-v select the first column of the lines, I, type # , Esc. Each line gets # prepended. To uncomment: Ctrl-v select the # column, d.

Knowledge 5 — operating on the last selection: '<,'>

After leaving visual mode, the markers '< and '> point at the start and end of the last selection. Vim auto-fills the range when you press : from visual mode — so to substitute only inside a region:

  1. Select the region (e.g., V4j for 5 lines)
  2. Press : — vim fills in :'<,'>
  3. Type s/old/new/g<Enter>

The substitution applies only inside the selection. This is the scoped version of Lesson 0003's :%s.

gv re-selects the same region for another operation. :'<,'>!sort sorts the selected lines. :'<,'>w /tmp/snip.txt writes just the selection to a file.

Drill (~10 min)

Create the file from bash:

cat > /tmp/config.yaml <<'EOF'
service: api
features:
  - rate-limiting
  - auth
  - logging
  - metrics
  - tracing
  - cache
  - circuit-breaker
plugins:
  - redis
  - postgres
  - s3
EOF
vim /tmp/config.yaml

Tasks

  1. Comment out the four middle features (auth, logging, metrics, tracing) using block insert. Each line should start with # .
    show two ways — pick the one that fits

    Option A — block insert (the classic): cursor on the - of auth (column 3), press Ctrl-v, extend down with 3j to cover all four lines, then I to insert at the start of the block on each line. Type # and press Esc. After a brief pause, all four lines get the prefix.

    Option B — line-wise + substitute: cursor on auth line, V3j to select 4 lines, press : (vim fills :'<,'>), type s/^/# /<Enter>.

    Block insert is shorter and the canonical idiom; line-wise + :s is more transparent. Same result, ~6 keystrokes either way once you're fluent.

  2. Uncomment them again. Use block delete.
    show answer

    Cursor on the # of the first commented line. Ctrl-v, 3j to extend down, l to extend right one column (cover # ). Press d. The two-column block is gone from all four lines.

  3. Append -v2 to every plugin name (redis, postgres, s3).
    show two ways

    Option A — line-wise + substitute: cursor on redis, V2j to cover all three plugin lines, : (auto-fills :'<,'>), s/$/-v2/<Enter>. $ anchors to end of line.

    Option B — block append: cursor on the s of redis (last char of the word — but wait, plugin names have different lengths). Block mode struggles here because the rectangle would be uneven. Option A wins decisively for varying-length lines.

    Takeaway: block mode shines when the column is consistent; line-wise + :s/$/.../ wins when content varies in length.

  4. Uppercase the word redis using a visual text-object.
    show answer

    Cursor anywhere on redis. viw — visually select inner word. U — uppercase. Result: REDIS-v2 (the suffix from Task 3 stays since it's past the cursor).

    Compare to Lesson 0001's gUiw — same outcome, fewer keystrokes. Visual mode's advantage is seeing the selection before applying the operator.

  5. Recall the last selection with gv and toggle its case back.
    show answer

    gv — re-selects REDIS. Press ~ — toggles case of each char. Result: redis-v2 again.

    This is the canonical "apply a second operator to the same region" pattern.

  6. Bonus — scoped substitution. Visually select the entire plugins: block and downgrade them all from -v2 back to -v1, only inside that selection.
    show answer

    Cursor on redis, V2j, : (auto-fills :'<,'>), s/-v2/-v1/g<Enter>. Only the three plugin lines change; if -v2 appeared elsewhere in the file, it would be untouched.

    This is the scoped version of Lesson 0003's :%s — reach for it when a global substitution would over-match.

Tool-matching recap. Three ways to comment code: block insert (Ctrl-v I), line-wise + :s/^/# /, or for the whole file :%s/^/# /. Pick by scope (whole file vs region) and shape (consistent column vs varying lengths). There's no "right" answer — only the one that fits.
