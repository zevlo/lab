Lesson 0007 · Phase shell — coreutils

The 20% that does 80%

A mental map of the commands that actually carry DevOps work — then one pipeline you will reuse forever for log triage.

Why this matters

Your mission needs fluent POSIX pipelines for incident triage, not encyclopedic knowledge of every binary in /usr/bin. Roughly twenty commands, in five families, cover most bare-metal shell work. Everything else waits until a real job demands it — same pareto discipline you asked for in vim.

Knowledge 1 — five families

Memorize the map, not every flag. Full cheat sheet: pareto shell commands.

FamilyJobPareto set
navigateWhere / filespwd cd ls mkdir cp mv rm cat less
inspectRead / pickhead tail grep
filterReshape stream| cut sort uniq wc tee

macOS vs remote. ss is Linux — use it over SSH. Local Mac listening ports: lsof / netstat. Prefer portable flags; half your work is remote.

Knowledge 2 — filters and the pipe

From Shotts (I/O redirection / TLCL ch. 6): a pipeline connects stdout of one command to stdin of the next with |. Programs that reshape the stream are filters.

FilterDoes
grep PATKeep lines matching PAT
cut -d D -f NKeep field N (split on D)
sortOrder lines (needed before uniq)
uniq -cCount adjacent duplicates
sort -nrRank numeric counts high→low
wc -lCount lines
tee FILESave a copy mid-pipe; keep flowing

Mission shape — source → narrow → extract → sort → count → rank:

tail -n 200 app.log \
  | grep ERROR \
  | cut -d' ' -f1 \
  | sort \
  | uniq -c \
  | sort -nr
uniq needs sorted input. It only collapses runs of identical adjacent lines. Skip sort and your counts lie. Always sort | uniq -c, then optionally sort -nr to rank.

Knowledge 3 — pipe vs redirect

| feeds another program. > / >> feeds a file. Merge errors into the stream you are capturing with 2>&1 (bash redirection; see man bash).

cmd >out.txt 2>&1          # both streams into out.txt
cmd 2>&1 | tee out.txt     # both streams into pipe + file

Drill — one log, one recipe

Do this in bash (Ghostty is fine; tmux optional). Create the sample log with a heredoc — do not paste into vim for this drill.

  1. Write a tiny fake access log: 
    cat > /tmp/app.log <<'EOF'
10.0.0.1 GET /health 200
10.0.0.2 GET /api 500 ERROR timeout
10.0.0.1 GET /api 200
10.0.0.3 POST /login 401 ERROR auth
10.0.0.2 GET /api 500 ERROR timeout
10.0.0.2 GET /api 500 ERROR timeout
10.0.0.4 GET /api 200
10.0.0.3 POST /login 401 ERROR auth
EOF
    show answer

    wc -l /tmp/app.log should print 8. If not, re-run the heredoc — the closing EOF must be alone on its line.

  2. Narrow to error lines only: 
    grep ERROR /tmp/app.log
    show answer

    Five lines. grep is inspect and filter — same binary, used mid-pipe or on a file.

  3. Extract the client IP (field 1, space-delimited) and rank frequencies: 
    grep ERROR /tmp/app.log \
  | cut -d' ' -f1 \
  | sort \
  | uniq -c \
  | sort -nr
    show answer

    Expect 10.0.0.2 with count 3, then 10.0.0.3 with count 2. If counts look wrong, you likely forgot sort before uniq.

  4. Save the ranked table while still viewing it: 
    grep ERROR /tmp/app.log \
  | cut -d' ' -f1 \
  | sort | uniq -c | sort -nr \
  | tee /tmp/top-err-ips.txt
    Confirm with cat /tmp/top-err-ips.txt.
    show answer

    tee is the T-junction from Shotts: copy to a file without breaking the pipeline. Here the pipeline ends at tee, so you see the same text on screen and in the file.

  5. Optional muscle: follow a live file. In one pane/window run tail -F /tmp/app.log. In another, append a line: 
    echo '10.0.0.9 GET /x 500 ERROR boom' >> /tmp/app.log
    Watch it appear. Stop with Ctrl-c.
    show answer

    tail -F (capital F) follows across rotation; day-to-day log watching. Pair later with grep --line-buffered when you need live filtered follow — not required today.

Pareto cut (not this lesson). Deep find/xargs, sed/awk, jq, archives, and permission surgery stay on the reference’s “Beyond the pareto” list. Navigate/ops families are on the map — drill them when an incident needs them, not all at once.
