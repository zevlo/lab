Part 1 — The catalog: each control, and the attack it blunts

MitigationWhat it doesWhat it blunts
SegmentationDivide the network into zones that cannot reach each other freely.Lateral movement and pass-the-hash spread (0014). Zero trust's threat scope reduction, implemented.
IsolationCut a system off entirely — an air gap or a sandbox.Everything outside the boundary. The strongest, costliest answer — for unpatchable crown jewels.
Permission restrictions / allow listOnly approved identities and applications may act; everything else is refused.Malware execution and unauthorized tools (0013).
EncryptionMake data unreadable without the key — at rest and in transit.Disclosure on capture: stolen laptops, on-path reading (0014).

Masking / tokenizationShow or store less real data in the first place.Exposure through support views and nonproduction copies.

Part 2 — Boot integrity and the persistence-killers

The exam's specialty hardening terms cluster in one job: keep malware from surviving a reboot or hiding in the boot chain. Note the last column — blocking and detecting are different promises.

TechniqueMechanismBlocks or detects
Secure bootFirmware checks each boot component's signature before running it.Blocks — a bootkit or boot-persistence rootkit (0013) is refused outright.
Safe bootApple's version of the signed boot chain.Blocks — same promise on macOS hardware.
Measured bootThe TPM (trusted platform module) records a fingerprint of each boot step.Detects — the record shows tampering after the fact.
Boot attestationA central verifier reviews the measured-boot record before granting access.Detects — remotely, before the machine joins.
Immutable systemsNever modified after deployment; replaced from a clean build.Blocks persistence — there is nothing to infect that survives.
Non-persistenceAny change vanishes on reboot; the baseline returns.Blocks persistence — malware's modifications do not survive.
Resting memory rebootsScheduled reboots clear RAM.Evicts — fileless malware (0013) lives only in memory, and the reboot takes its home away.

Part 3 — The discrimination pairs

PairThe dividing line
Segmentation vs. isolationWalls inside the network versus removal from the network. Isolation is the stronger and costlier claim.
Secure boot vs. measured bootRefuse-to-run versus record-and-report. Block versus detect.
Immutable vs. non-persistentNever changes versus changes-discarded-at-reboot. Both kill persistence by design — different mechanisms.
Encryption vs. hashingHides content versus proves integrity. Confidentiality versus tamper detection.
Masking vs. tokenizationPartial display of the real value versus replacement by a vaulted token.

Practice — 8 questions, timed

Four marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better. Budget: 11 minutes for 11 questions — the exam's pace. Stopwatch: 0:00

QUESTION 1

A public kiosk is locked down so only the two applications the vendor approved can run; every other executable is refused. Which mitigation is deployed?

Application allow list. Default-deny execution: only what is approved runs. It blunts malware installation and unauthorized tooling at the execution step (Lesson 0013's malware families) — no scanning required, just refusal.

QUESTION 2 MULTI-HOP

The organization replaces passwords with passkeys everywhere. Which Lesson 0014 attack does this eliminate at the root?

Password spraying; nothing exists to spray. Passwordless removes the shared secret itself — the one password the spray relied on is gone for every account. Spraying and brute force lose their target, not just their success rate. (Lesson 0014 applied.)

QUESTION 3

At boot, the TPM records a fingerprint of every startup step, and a central server reviews that record before the machine joins the network. Which techniques are in play?

Measured boot with boot attestation. Recording = measured boot; the central review of the record = boot attestation. Together they detect a tampered boot chain. Secure boot would have blocked the tampered component before it ran — a different promise.

QUESTION 4 MULTI-HOP

Lesson 0013's fileless species lives only in RAM — nothing on disk to scan. The team schedules automatic nightly restarts. Which mitigation is this?

Resting memory reboots. The reboot clears RAM, and the fileless malware's only home disappears with it. Non-persistence is the close cousin — changes revert to baseline — but the named exam term for scheduled reboot hygiene is resting memory reboots. (Lesson 0013 applied.)

QUESTION 5 MULTI-HOP

A zero-day is announced for your database's exact version (Lesson 0012). No patch exists yet. Which mitigation do you reach for first?

Segmentation, as a compensating control. A zero-day has no patch — "patch now" is the trap answer, as is everything unrelated. The playbook from Lesson 0012: emergency process plus compensating controls — wall the system off — until the patch ships.

QUESTION 6

A container fleet is redeployed from clean images on every release; nothing is ever edited while running. Which property does the fleet have?

Immutable systems. Never modified in place, replaced from a clean build — that is immutability's exact definition. Non-persistence is the near miss: it describes changes being discarded at reboot, not a system that is never changed.

QUESTION 7 MULTI-HOP

A nation-state actor (Lesson 0008) wants months of quiet dwell time. Which mitigation family exists to shrink exactly that window?

Telemetry, monitoring, and logging. An advanced persistent threat's whole strategy is staying quiet longer than anyone is looking. Detection is the counter — the detective family that turns dwell time from months into minutes. (Lesson 0008 applied; control types from 0001.)

QUESTION 8 BEST ANSWER

A factory line is controlled by an unpatchable legacy Windows machine. Which mitigation is best?

Isolation from the main network. Segmentation is the tempting defensible option — it limits the blast radius. But an unpatchable crown jewel has no compensating patch path ever coming: isolation removes the network path entirely, which is the stronger claim. Both appear in the objective; the scenario's "cannot ever patch" detail is the tell.
