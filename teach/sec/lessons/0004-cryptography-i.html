Part 1 — Hashing: the integrity tool

A hash is a one-way fingerprint. Any input — a sentence, a file, a disk image — goes into a hash function, and a fixed-length fingerprint comes out. Change one character of the input and the fingerprint changes completely. And there is no way to run it backward: a fingerprint cannot be turned back into the file.

PropertyPlain meaning
One-wayYou cannot reverse a hash back into the input.
Fixed lengthA one-line note and a 4 GB image produce the same-size fingerprint.
Collision-resistantTwo different inputs should never share a fingerprint.
DeterministicThe same input always produces the same fingerprint.

Salt is a random value mixed into a password before hashing, so two users with the same password get different stored hashes — and attackers cannot use precomputed tables of common hashes. Your systems already do this: bcrypt and argon2 store passwords as salted hashes.

Hashing answers one question: has this changed? It is the integrity tool (Lesson 0002). It hides nothing and decrypts to nothing.

Part 2 — Symmetric encryption: the speed tool

Symmetric encryption uses one shared secret key. The same key locks and unlocks. It is fast, and it is what bulk encryption actually uses — AES is the standard you will see on the exam.

Its weakness is key distribution: the key must be shared secretly with every party. Ten partners who all talk securely to each other need 45 separate keys. Across an internet, sharing that first key secretly is the chicken-and-egg problem cryptography had to solve.

Part 3 — Asymmetric encryption: the pairing tool

Asymmetric encryption solves key distribution with a key pair: a public key you share with the world, and a private key that never leaves your device. They are mathematically linked: what one key locks, only its partner unlocks.

You use…Only this can unlock…What you get
Recipient's public keyThe recipient's private keyConfidentiality — only they can read it
Your private key (signing)Your public key (verifying)Integrity, authenticity, non-repudiation

The two golden rules

  1. Public encrypts → private decrypts. (Hiding a message for one reader.)
  2. Private signs → public verifies. (Proving who wrote it and that it is untouched.)

Everything else in cryptography questions is a variation on these two rules. RSA is the classic algorithm name; ECC (elliptic-curve cryptography) is its smaller-key modern cousin.

Real systems combine both tools: Transport Layer Security (TLS) uses asymmetric crypto for a moment to agree on a fresh session key, then uses fast symmetric AES for the traffic. Slow and careful to introduce; fast for the bulk.

Part 4 — Digital signatures: non-repudiation, paid in full

In Lesson 0002 you took the word non-repudiation on trust. Here is the machinery. Signing does not encrypt the document — it proves three things about it:

  1. The developer's system hashes the release. (Fingerprint of the content.)
  2. The developer's private key encrypts that hash. The result is the digital signature.
  3. You download the release and hash it yourself.
  4. You decrypt the signature with the developer's public key, which recovers their hash.
  5. The hashes match → the content is untouched (integrity), it came from the key holder (authentication), and only that private key could have produced the signature — so the signer cannot deny it (non-repudiation).

Exam trap: a digital signature provides no confidentiality. The signed document is still readable by everyone. If the scenario needs secrecy, add encryption.

Practice — 8 questions, instant feedback

QUESTION 1

Any input produces a fixed-length fingerprint that cannot be reversed. What is this called?

Hashing. One-way, fixed-length, integrity-checking. Encryption is reversible with a key; a hash never is.

QUESTION 2

A random value mixed into a password before hashing, so identical passwords store differently, is called what?

Salt. It defeats precomputed tables of common password hashes.

QUESTION 3

One shared secret key both encrypts and decrypts, very fast — AES works this way. Which model?

Symmetric. One shared key, high speed, and a key-distribution problem at scale.

QUESTION 4

You encrypt a message with the recipient's public key. Which key decrypts it?

Recipient's private key. Golden rule one: public encrypts, its private partner decrypts.

QUESTION 5

A developer signs a release. Anyone can verify that signature using what?

The developer's public key. Golden rule two: private signs, public verifies. The private key never leaves the developer's device.

QUESTION 6

A valid digital signature on a document proves which three properties?

Integrity, authenticity, non-repudiation. Not confidentiality — a signed document is still readable by everyone.

QUESTION 7

A download page lists the SHA-256 fingerprint beside the file. What is that fingerprint for?

Verifying file integrity. You hash the download and compare: equal means unmodified.

QUESTION 8

Two databases share one AES key for nightly replication traffic. Which model, and its main weakness?

Symmetric; key distribution. Fast and simple — but that one key must be shared and protected by both ends.
