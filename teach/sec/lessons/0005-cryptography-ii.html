Cryptography II: Certificates, PKI, and Obfuscation

One win today: explain how a stranger's public key becomes trustworthy — the certificate chain — and pick the right hiding technique for sensitive data. Difficulty is up this lesson: multi-hop questions, and one where two answers sound right and you must choose the better.

Why this matters to your mission

Public key infrastructure (PKI) is not exotic in the DoD world — it is issued to every employee. The Common Access Card (CAC) that a DoD 8140 role badges in with carries digital certificates and their private keys. Logging into DoD systems with a CAC is a live PKI handshake. This lesson explains what is inside the badge you will carry.

Confidentiality. Golden rule one: public encrypts, only the private partner decrypts — nobody else can read it. (Lesson 0004.)

Part 1 — The problem certificates solve

Lesson 0004 gave you key pairs. New problem: someone hands you a public key and says "this is Mehdi's." How do you know? A public key by itself is a label with no proven owner. A digital certificate fixes this: it binds a public key to an identity, and a trusted third party — the certificate authority (CA) — signs that binding with its own private key (Lesson 0004's signature machinery, applied to identity).

How a certificate comes to life:

  1. You generate a key pair on your machine. The private key never leaves it.
  2. You send the public key plus your identity details to a CA. This is a certificate signing request (CSR).
  3. The CA verifies you are who you claim (domain control, organization documents).
  4. The CA issues the certificate: your public key + identity + validity dates, signed by the CA.
  5. Anyone who trusts that CA can now trust that this public key is really yours.

Part 2 — The chain of trust

LevelPlain meaningLives where
Root CAThe anchor of trust. Its certificate is pre-installed in browsers and operating systems — it is trusted because it is already there.Offline, in a vault. Signs nothing except intermediates.
Intermediate CAThe working layer, issued by the root. Keeps the root offline by doing the daily signing.Online, issues leaf certificates.
Leaf certificateThe end certificate for a site, service, or person.On your server or smart card.

Verification walks the chain from leaf up to a root the verifier already trusts — each level's signature checked by the level above. A self-signed certificate is a chain of one: your own key vouching for itself. Fine in a lab; in a browser it fails trust because no installed root stands behind it.

Part 3 — Revocation: un-trusting a live certificate

Certificates expire on schedule. Revocation is for the off-schedule problem: the private key leaked, or the CA issued wrongly. Two mechanisms:

MechanismHow it worksWeakness
Certificate revocation list (CRL)The CA publishes a list of revoked certificate serial numbers. Clients download and check it.Can be large; goes stale between downloads.
Online Certificate Status Protocol (OCSP)The client asks the CA's responder in real time: "is this serial still good?"Slower browsing; every visit leaks a query to the CA.
OCSP staplingThe server fetches its own fresh OCSP proof and staples it to the handshake.Best of both — the exam's favorite answer when a scenario says the server presents proof of valid status.

Part 4 — Obfuscation: hiding instead of encrypting

Encryption transforms data with keys. Obfuscation hides or replaces data so exposure is limited — no key, no math, just concealment or substitution:

TechniquePlain meaningClassic use
SteganographyHides data inside another medium — a message inside a photo's pixel values.Covert channels; data exfiltration by insiders.
TokenizationReplaces a sensitive value with a meaningless token; the real mapping lives in a separate, tightly guarded vault.Payment cards: systems store tokens, so a breach exposes nothing spendable — and shrinks audit scope.
Data maskingShows only part of the value.Support staff see "**** **** **** 1234."

Part 5 — Blockchain: hashing at scale

A blockchain is an append-only ledger copied across many machines. Each block contains transactions and the hash of the previous block — Lesson 0004's fingerprint, chained. Tamper with an old block and its hash changes, which breaks the next block's recorded hash, and the break cascades forward. The chain is tamper-evident by construction. That is all the exam needs.

Practice — 8 questions, difficulty raised

Three questions marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better.

QUESTION 1 MULTI-HOP

A browser validates the certificate for shop.example.com. In which order does the chain get checked?

Leaf, intermediate, root. Verification starts with what was presented and climbs to an anchor your system already trusts. Issuance goes the other direction — root signs intermediate, intermediate signs leaf.

QUESTION 2 MULTI-HOP

A root CA's signing key sits on a machine in a bank vault, powered off, guarded. Which control category and type best describes this protection?

Physical; preventive. Lesson 0001 through a PKI lens: the vault and air gap are tangible barriers that stop the key from being reached. Detective would notice misuse; preventive stops the attempt.

QUESTION 3

You send a CA your public key and identity details, and it returns a signed certificate. What is that request called?

Certificate signing request (CSR). The application paperwork for a certificate. The revocation list and status protocol both come later, for un-trusting.

QUESTION 4

During the handshake, a web server hands the browser fresh CA-signed proof that its certificate has not been revoked. Which technique?

OCSP stapling. The server staples its own status proof to the handshake — no per-visit query to the CA. Scenario says "server presents proof" → stapling.

QUESTION 5 MULTI-HOP

A retailer replaces stored card numbers with meaningless tokens; the real mapping sits in a vendor's vault. Which technique, and which security goal does it mainly serve?

Tokenization; confidentiality. The sensitive value is not present to be exposed — and systems holding only tokens fall outside the strictest audit scope. Encryption would keep a recoverable ciphertext in place instead.

QUESTION 6

Support staff can see only the last four digits of a customer's card number. Which technique?

Masking. Partial display of a real value. Tokenization would substitute a fake value; salting and hashing are password and integrity tools.

QUESTION 7

A message is hidden inside the pixel values of a vacation photo. Which technique?

Steganography. Concealment inside another medium — the photo still looks like a photo.

QUESTION 8 BEST ANSWER

A public web app's TLS certificate expired an hour ago; users see browser warnings. Which action is best?

Renew the certificate. The tempting distractor is "revoke" — but revocation is for suspected key compromise or mis-issuance, not expiry. An expired certificate needs renewal; a self-signed replacement would trade the warning for a total trust failure.
