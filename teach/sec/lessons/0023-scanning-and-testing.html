Find It, Then Prove It

One win today: name the right scan for the question being asked — and walk a penetration test through its phases without skipping authorization. This is 4.3's scanning half: scan types, credentialed versus not, false positives, fuzzing, and the pentest lifecycle. The intelligence, scoring, and remediation half is Lesson 0024.

Why this matters to your mission

Defense networks are scanned on a schedule by directive — compliance scans against STIGs, vulnerability scans feeding a rolling risk list — and penetration testing happens only under signed rules of engagement. The line between authorized testing and a federal crime is a document. The exam's 4.3 questions sit exactly on that line.

Part 2 — Penetration testing: authorized attack

The line between a pentest and a crime is written permission. Everything below happens inside rules of engagement: the signed document defining scope, targets, methods, and timeline.

PhaseWhat happens
ReconnaissanceLearn the target. Passive (OSINT — open-source intelligence, no touching) or active (probing that could be noticed).
Scanning and enumerationPart 1's toolkit, aimed at the scope.
ExploitationProve a weakness is real by using it.
Escalation and persistenceTurn the foothold into privileges; establish a way back.
PivotingUse the first compromised box as a launchpad into networks it can reach and you could not.
Cleanup and reportingRemove evidence and tools; deliver findings with severity and fixes.

PathThe arrangement
Responsible disclosureThe finder reports privately; release waits for the vendor's fix. The ethical default.
Bug bountyResponsible disclosure with a paycheck — a formal program paying for verified findings.
Full disclosurePublication regardless — the controversial pressure tactic.

PairThe dividing line
Credentialed vs. non-credentialedLogged-in depth versus attacker's-eye breadth. Accuracy versus realism.
Vulnerability scan vs. pentestFind versus prove. Broad, repeatable, automated versus deep, manual, expensive.

Practice — 8 questions, timed

Four marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better. Budget: 11 minutes for 11 questions — the exam's pace. Stopwatch: 0:00

QUESTION 1

A scanner authenticates to each server with a service account and reads the exact installed versions and configurations before comparing them against known flaws. Which scan mode is this?

A credentialed scan. Logging in turns guessing into reading: exact versions and settings instead of fingerprints from the outside. The trade: deeper and more accurate, but the scanner now holds credentials worth protecting. Non-credentialed shows the attacker's view — shallower, noisier.

QUESTION 2 MULTI-HOP

The scanner flags a library version as vulnerable, but Lesson 0020's patch process had already replaced it — the file name just kept the old version string. What is this finding, and what must happen before anyone remediates?

False positive; validate first. Flagged but not real — the scanner guessed from the outside (or from a stale string). Acting on unvalidated findings wastes the maintenance window; skipping validation is how noise drowns signal. The mirror danger is the false negative: a real weakness never flagged, quietly exposed.

QUESTION 3

A file parser is fed thousands of mutated, malformed inputs — oversized fields, broken headers, truncated strings — while engineers watch for crashes. Which technique?

Fuzzing. Automated chaos with a purpose: feed the program inputs no test suite imagined and watch what breaks. It hunts the input family's cousins — Lesson 0011's injection relatives — at the parser level. Static analysis reads source; DAST tests a running app with structured intent.

QUESTION 4 MULTI-HOP

A contractor is hired to test a defense network's perimeter. Before any packet is sent, both parties sign a document defining targets, methods, and the testing window. What is the document, and what is it the difference between?

Rules of engagement; authorized and criminal. Written permission with scope, methods, and timeline — without it, the identical actions are a federal offense. The exam pairs 4.3 with exactly this line. (Lesson 0006's change discipline is the sibling: nothing significant happens undocumented.)

QUESTION 5

During an authorized test, the tester uses a compromised jump host as a launchpad to reach an engineering subnet that was never exposed to the internet. Which phase?

Pivoting. The first box becomes the new attack origin — reaching networks the tester could never touch directly. It is Lesson 0018's jump server viewed from the other side, and the reason segmentation quality gets proven by testing, not by diagram.

QUESTION 6 BEST ANSWER

Leadership wants evidence for an annual compliance report: every one of 2,000 hosts checked against a known-flaw catalog, repeatably, with the same evidence next quarter. A penetration test is on the shelf too. Which is the better fit?

A recurring vulnerability scan. Broad, automated, repeatable, evidence-producing — exactly what compliance needs. The defensible near miss: a pentest proves exploitability in depth, but it is manual, narrow, and different every time — the wrong shape for a repeatable annual control. Find versus prove (Lesson 0022's audit thinking).

QUESTION 7 MULTI-HOP

Every quarter, the team must show each server's configuration matches the organization's STIG-derived known-good state — with pass/fail evidence per rule. Which scan type, and which Lesson 0020 concept does it audit?

A compliance scan; the baseline. It measures reality against the benchmark — the baseline configuration from Lesson 0020, now with pass/fail per rule instead of trust. Discovery maps what exists; port scans list doors; neither audits configuration.

QUESTION 8 MULTI-HOP

A researcher privately reports a flaw in a vendor's authentication library and waits for the patch before publishing. The vendor runs a formal program that pays for verified findings like this. Name the ethics path and the program type.

Responsible disclosure; a bug bounty. Report privately, release after the fix — the ethical default — and the vendor's paid program makes it a bounty. Full disclosure publishes regardless, the pressure tactic. Lesson 0012's supply-chain flaws get patched because this path exists.
