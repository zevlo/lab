Vulnerabilities II: The Platform Catalog

One win today: name the platform-level weaknesses the exam lists — and pick the right response when no patch exists. This is predicted home turf, so it runs compressed: tables carry the theory, the quiz carries the proof.

Why this matters to your mission

Two items in this catalog decide audit outcomes in DoD environments: end-of-life systems — running software the vendor no longer patches fails inspections outright — and zero-days, the flaws that force the emergency decisions you met in change management. A DoD 8140 role spends real time hunting both: retiring the first, surviving the second.

Part 1 — The catalog, in one table

WeaknessMechanism in one sentenceScenario tell
Operating system vulnerabilitiesFlaws in the OS itself — unpatched or unsupported."The server has not been patched since March."

Cloud-specificExposure unique to shared cloud platforms: denial of service, authentication bypass, directory traversal on internet-facing apps.Traversal path ../../etc/passwd walking out of a web root.
Mobile deviceJailbreaking (Apple) and rooting (Android) strip the vendor's controls; sideloading installs apps from outside the official store.Staff installing cracked apps on managed phones.

Supply chainWeakness at any stage from vendor to deployment: tampered hardware, compromised update pipelines, Trojaned dependencies.Signed vendor updates carrying an implant.
Zero-dayA flaw with no patch available — zero days of protection since discovery."Actively exploited in the wild; vendor patch pending."
End-of-life / legacyThe vendor ended support: no patches will ever come.An OS version whose support ended last year, still in production.

Part 2 — Three pairs the exam loves

PairThe dividing line
Zero-day vs. knownDoes a patch exist? Known flaw → patch through change management. Zero-day → emergency process plus compensating controls until a patch ships.
VM escape vs. resource reuseEscape is an active break (guest attacks the hypervisor); reuse is passive leakage (yesterday's tenant's data arrives with the hardware).
End-of-life vs. zero-dayEnd-of-life will never be patched — replace or isolate it. Zero-day will be patched eventually — survive until then.

One cross-link worth its weight in exam points: zero-day + internet-facing + actively exploited is the exact combination that jumps the emergency queue from Lesson 0006 — and when no patch exists at all, segmentation (Lesson 0003) is the compensating control that buys time.

Practice — 8 questions, timed

Four marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better. Budget: 11 minutes for 11 questions — the exam's pace. Stopwatch: 0:00

QUESTION 1

A guest virtual machine breaks out of its hypervisor and starts reading the host's memory — and every sibling VM's. Which weakness?

Virtual machine escape. The guest actively defeats the isolation boundary. Resource reuse is the passive sibling — data left behind by a prior tenant, no attack required.

QUESTION 2 MULTI-HOP

An internet-facing service is being exploited through a flaw with no vendor patch available. Which response pairing fits best?

Emergency change plus segmentation. Zero-day + internet-facing + actively exploited jumps the queue (Lesson 0006), and with no patch to apply, isolating the exposure is the compensating control that buys time (Lesson 0003). Waiting leaves the exploitation running; backups repair data, not exposure.

QUESTION 3 MULTI-HOP

A cloud customer finds a decommissioned disk reallocated to their tenant still holding the previous tenant's readable records. Weakness, and which triad goal is harmed?

Resource reuse; confidentiality. Someone else's data arriving with your hardware — a confidentiality leak with no active attack at all. (Lesson 0002's triad applied.)

QUESTION 4 MULTI-HOP

Attackers find a storage bucket left public by a copy-paste error, found while scanning the internet at random. Vulnerability category, and which actor class most likely found it?

Misconfiguration; unskilled attacker. The self-inflicted category meets the opportunistic scanner — loud, random, and exactly what script-kiddie tooling automates (Lessons 0010 and 0008). No sophistication required when the door is simply open.

QUESTION 5

Staff install applications from outside the phone vendor's official store on managed devices. Which term?

Sideloading. Installing from outside the official store. Jailbreaking (Apple) and rooting (Android) are the deeper step — stripping the vendor's operating-system controls.

QUESTION 6

The vendor ended support for your database platform's version last year; no patches will ever arrive. Which condition?

End-of-life. The distinguishing feature is permanent: no patch will ever come, so the answer is replace or isolate — in a DoD setting, this fails inspections outright.

QUESTION 7 MULTI-HOP

A supplier ships servers whose management chips were tampered with before delivery. Vulnerability category, and which stage does it attack?

Supply chain; procurement. The weakness entered before you ever powered the hardware on — the supply chain is every stage from vendor to deployment, and tampered hardware attacks its very first link.

QUESTION 8 BEST ANSWER

Which vulnerability category causes the most successful breaches in most organizations?

Misconfigurations. Zero-day is the tempting distractor — famous, rare, and expensive. The open buckets and default credentials organizations create themselves are the everyday breach source. The exam consistently rewards "most common → misconfiguration."
