Protect Data. Survive Failure.

One win today: name the state data is in and pick the protection that fits it — and when anything fails, pick the backup, the site, and the metric without hesitating. Domain 3 closes here. Everything after the warm-up that is not review is genuinely new vocabulary: restore chains, RAID, site types, and the four metrics.

Why this matters to your mission

In a DoD 8140 role you inherit both halves of this lesson. The data half: where data may legally live, how long it must be kept, who may see it. The recovery half: which site, which backup cadence, which metric the mission owner signs. A defense system that cannot be recovered is not defensible — and the exam's 3.4 questions are exactly that arithmetic in scenario form.

Part 1 — The data half (3.3): states, labels, protection

Most of the protection toolkit you already own from Lessons 0004 and 0005. What is new: the state taxonomy, the classification labels, and the location and lifetime rules.

The three states

StateWhere the data isThe protection that fits
At restOn storage — disk, database, backup tape.Encryption at rest. The drive walking out the door reads as noise.
In transitCrossing a network.TLS, VPN (Lessons 0004 and 0018). The on-path attacker sees ciphertext.
In useIn memory, being processed right now.Trusted execution environment (TEE), secure enclave — the processor family from Lesson 0017.

The exam's tell: where is the data at the moment the question describes? Processing it is in use; storing or copying it is at rest; sending it is in transit.

Classification labels

GovernmentCommercialThe dividing idea
Top secret → secret → confidentialRestricted → confidential → internalLabels rank damage if disclosed. The name differs by world; the ranking is the point.
UnclassifiedPublicNo damage on release — but verify before trusting.

Know both columns. The exam can use either set, and asks which label fits which data more often than it asks for definitions.

The protection toolkit — review plus three new tools

ToolWhat it doesThe dividing line
EncryptionReversible with the key.Confidentiality when the data must come back. (Lesson 0004.)
HashingOne-way fingerprint.Integrity and passwords, never display. (Lesson 0005.)
MaskingShows part of the value, keeps the format.Realistic but safe test data and displays. Irreversible by design.
TokenizationSwaps the value for a stand-in, vault maps it back.Reversible through the vault — the business can get the real value back.
Data minimizationCollect only what is needed, keep only as long as needed.New. The cheapest protection is data you never held.
Geolocation restrictionData may live only in approved locations.New. Enforced by the provider or by policy. Under it sits data sovereignty: data is subject to the laws of the country where it resides — the reason a defense contract blocks the cheap foreign region.
Retention policyKeep for the defined lifetime, then destroy securely.New. Data kept past its purpose is stored risk. Destruction methods arrive with Domain 4.

Part 2 — The redundancy half (3.4a): no single point of failure

RedundancyWhat it does
ClusteringMultiple nodes act as one service; one dies, the service answers on.
Load balancingSpreads traffic and health-checks members out — Lesson 0018, already banked.
Multi-cloud / platform diversityThe same design in two providers — one burns, one serves. No shared failure mode.
Geographic dispersalCopies far enough apart that one disaster cannot reach both.
Uninterruptible power supply (UPS)Battery ride-through for seconds to minutes — bridges the gap until power returns.
GeneratorFuel-driven, sustains hours to days. UPS holds the line; the generator holds the day.

Redundant Array of Independent Disks (RAID)

LevelLayoutDisksSurvives
RAID 0Striping — split across disks.2+Nothing. Speed only. Any disk dies, all data dies.
RAID 1Mirroring — identical copies.2One disk.
RAID 5Striping with parity.3+Exactly one disk.
RAID 6Striping with double parity.4+Any two disks.
RAID 10Stripes of mirrors.4+One per mirror pair — sometimes two, never guaranteed.

The exam classic

RAID is availability, not a backup. It answers a disk failing. It does not answer fire, theft, ransomware, or a mistaken delete — the array faithfully reproduces all four. Every redundancy tool on this page protects against failure; only Part 3 protects against loss.

Part 3 — Backups, sites, and the metrics (3.4b)

Backup types — the restore chain is what gets tested

TypeWhat it copiesRestoring requires
FullEverything.The full alone. Slowest to make, simplest to restore.
IncrementalChanges since the last backup of any kind.Full plus every incremental since, in order. Fast backups, long restores.
DifferentialChanges since the last full.Full plus the latest differential — two pieces, always. Differentials grow through the week.
SnapshotA point-in-time marker on the same storage.Instant rollback — but not an independent copy. Same array dies, snapshot dies.
ReplicationA live copy at a second site.No restore at all — near-zero data loss. But it replicates corruption and ransomware with the same speed.

Copy direction matters more than copy speed: online backups are reachable from the network (convenient, reachable by attackers too); offline copies are not. Immutable backups — write once, read many (WORM), object lock — cannot be changed or deleted for a set period. The classic rule of thumb: 3 copies, 2 different media, 1 offsite.

Site types

SiteWhat is standing byBack in hours?Cost
Hot siteA running replica, data synced.Minutes.Highest.
Warm siteEquipment and connectivity in place; data restored at failover.Hours to days.Middle.
Cold siteSpace, power, cooling. Bring everything.Days to weeks.Lowest.
Mobile siteA trailer you tow to the disaster.Days.Situational.
Cloud region failoverInfrastructure as code brings the environment up elsewhere on demand.Minutes to hours.Pay when used.

The four metrics

MetricMeasuresWhat it sets
Recovery point objective (RPO)How much data the business can lose.Backup or replication frequency. Nightly backup = 24-hour RPO.
Recovery time objective (RTO)How much downtime the business can take.Redundancy and site choice. One-week RTO means no hot site needed.
Mean time to repair (MTTR)Average time to fix a failed component.Operational readiness — spares, staff, runbooks.
Mean time between failures (MTBF)Average time a component runs before failing.Purchasing and design — reliability of the thing itself.

Two of the four set requirements (RPO, RTO — the business decides); two measure equipment (MTTR, MTBF — the vendor proves). Capacity planning rides along: people, technology, infrastructure — sized for peak, not average.

StepWhat happens

The discrimination pairs

PairThe dividing line
Incremental vs. differentialSince the last backup of any kind versus since the last full. Restore: many pieces versus always two.
RPO vs. RTOData you can lose versus time you can be down. One sets backup frequency; the other sets the site.
Snapshot vs. replication vs. backupMarker on the same storage versus live second copy versus protected independent copy.

Practice — 8 questions, timed

Four marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better. Budget: 11 minutes for 11 questions — the exam's pace. Stopwatch: 0:00

QUESTION 1

While an application processes a customer record in memory, what state is that record in — and what protects it there?

Data in use; secure enclaves. Being processed in memory is in use — protected by trusted execution environments and secure enclaves, the processor family from Lesson 0017. Stored is at rest; crossing the network is in transit.

QUESTION 2 MULTI-HOP

A copy of the production database goes to developers for testing. It must look realistic — right shapes, right formats — but developers must never be able to recover the real customer values. Which protection fits?

Data masking. Format-preserving and irreversible — realistic test data with no road back. Tokenization stays reversible through the vault (defensible, but "never recover" rules it out); hashing destroys the format; encryption hides everything, and one key brings it all back. (Lesson 0004 applied to objective 3.3.)

QUESTION 3 MULTI-HOP

The compliance officer blocks a move to a cheaper cloud region: personal data must remain under home-country law. Which concept, and which mechanism enforces it?

Sovereignty; geolocation restriction. Data sovereignty — data is subject to the laws of the country where it resides — enforced by restricting where the data may live. The tempting distractor pairs a right mechanism with the wrong concept. This is the DoD reality: the cheap foreign region is not on the menu.

QUESTION 4 MULTI-HOP

Backups run: full every Sunday, incremental each weeknight. Friday night the server's disks fail. Which set restores to end of Thursday?

Sunday's full plus every incremental. An incremental chain restores full first, then each incremental in order. A differential scheme would need exactly two pieces — that is its whole selling point. Trade: incrementals back up fastest and restore longest.

QUESTION 5

A storage array must keep serving through any two simultaneous drive failures. Which RAID level is required?

RAID 6. Double parity survives any two disks. RAID 10 sometimes survives two — but only when they land in different mirror pairs; "sometimes" fails an "any two" requirement. RAID 5 survives exactly one.

QUESTION 6 BEST ANSWER

A flood destroys the data center. Leadership accepts up to one week of downtime and wants the cheapest option that honors that promise. Which site type?

Warm site. Equipment and connectivity standing by, data restored at failover — hours to days, comfortably inside a week. The defensible near miss: the cold site is cheaper, but days-to-weeks can overrun the promise. The divider is the bounded week: spend to it, not past it.

QUESTION 7

Leadership asks how much transaction data the business can afford to lose if a system fails. The agreed answer — no more than 15 minutes — defines which metric, and what does it set?

RPO; the backup frequency. The recovery point objective measures acceptable data loss — 15 minutes of RPO rules out nightly backups and demands near-continuous copying. Question 6 was the RTO twin in disguise: downtime tolerance set the site.

QUESTION 8 MULTI-HOP

Ransomware from Lesson 0013 encrypts the file servers — including the backup target mounted on the same network. Which property would have kept restorable copies?

Immutable offline backups. Replication copies the encryption just as faithfully as the data; encryption was no barrier to the attacker's admin reach; the schedule is irrelevant. Copies the network cannot touch and cannot change — WORM, object lock, air gap — are the ransomware answer. (Lesson 0013 plus the 3-2-1 rule.)
