Secure by Default

One win today: start every system from a documented, hardened baseline — and know the six hardening habits the exam expects you to name. This is the exam's largest domain (28 percent). Today is the half of 4.1 you already live in: baselines, images, patching, key and secret custody, code analysis. The wireless and mobile half — genuinely new vocabulary — is Lesson 0021.

Why this matters to your mission

In a DoD 8140 role the baseline is not a habit, it is a requirement: Security Technical Implementation Guides (STIGs) define the known-good state, machines are deployed from hardened images, and measured boot proves they have not drifted. An auditor does not ask "is this machine secure?" — they ask "does it match the baseline, and can you prove it?" That question is this entire lesson.

Warm-up — typed recall, no choices

W1 is the site-type reframe from Lesson 0019's miss. The ladder: hot = running and synced, minutes · warm = racked and cabled, data restored at failover, hours to days · cold = an empty room, days to weeks. Cost runs exactly inverse to recovery time. The rule the miss taught: filter sites by the promise, then buy the cheapest one inside it.




Part 1 — The baseline: deploy from known-good, prove you never left

ConceptWhat it isThe dividing line
Baseline configurationThe documented known-good state: every setting, patch, and service.A document plus an image. Drift is measured against it, not against memory.
Hardened imageThe baseline baked into a ready-to-deploy template — patched, minimal, locked down.Machines are born hardened, never born default. Your golden image.

Boot integrity — the baseline of the boot chain (banked, one look)

TechniqueWhat it does
Measured bootThe trusted platform module (TPM) records a fingerprint of every boot step — detection, not blocking.
Boot attestationA central verifier reads that record before granting network access — remote proof of a clean boot.
Secure bootFirmware refuses to run unsigned boot code — a boot-level rootkit is blocked, not just noticed.

You typed measured boot cold yesterday — it graduates at the week-3 review. Boot integrity is a named 4.1 exam topic, so it appears here as content, not as practice.

Part 2 — Hardening targets and the six habits

The exam's hardening questions are one habit applied to one target. The targets: servers, workstations, network devices, embedded and IoT systems, mobile (mobile's full treatment is Lesson 0021). The habits:

HabitThe moveExam tell
Remove unnecessary softwareEverything installed is attack surface. Bloatware gets removed, not tolerated.Shrink the surface — Lesson 0010's answer.
Close ports and servicesDefault deny; run only what the role needs."Which is the hardened configuration?" — the one with fewest doors.
Change default credentialsDefault passwords are published passwords.The first fix on any new device.
Patch managementEvaluate, test, schedule, deploy, verify.Automated for speed at scale; manual for the fragile few.
Trusted operating systemAn OS built and formally evaluated to enforce separation and access guarantees.Security by construction, not configuration.
Software self-healingThe system detects its own failure and restores itself — restart, replace, rebuild.Your orchestrator restarting a sick container, named in exam vocabulary.

Legacy and end-of-life (EOL) platforms break the patch habit — no patches will ever come. The answer is never "wait": it is replace, or isolate (Lesson 0012's ICS answer, now in hardening clothing).

Two sleep states, two protections

StateWhere memory goesThe protection it needs
Suspend to disk (hibernate)Written to storage — the data is now at rest.Encryption at rest. The hibernation file reads like any other file.
Suspend to RAM (sleep)Stays in powered memory.Physical custody. Contents vanish on power loss — but live extraction works while it sleeps.

Part 3 — Cryptographic techniques, and the two custody problems

Encryption, hashing, and salting are banked from Lessons 0004 and 0005. TLS and IPsec are banked from Lesson 0018. What 4.1 adds is the custody question — where the keys and secrets live:

PracticeGuardsThe shape of it
Key managementCryptographic keys.The full life: generate, exchange, store (hardware security module, TPM), rotate, revoke, destroy.
Secrets managementMachine credentials — API keys, database passwords.Central vault, access control, automatic rotation, audit trail. Nothing in plaintext environment variables or code.

The dividing line: keys are for cryptography; secrets are for authentication. Both fail the same way when pasted into a pipeline file — and both are your daily work, now with exam names.

Practice — 8 questions, timed

Four marked MULTI-HOP combine frameworks from earlier lessons. One marked BEST ANSWER has two defensible options — pick the better. Budget: 11 minutes for 11 questions — the exam's pace. Stopwatch: 0:00

QUESTION 1

Every new server arrives from a template: patched, unnecessary services removed, identical to a documented known-good state. What is that starting state called?

A baseline configuration. The documented known-good state every machine is deployed from and measured against. Baked into a template it becomes a hardened image; held automatically it is configuration enforcement. Drift is the departure from it — not a starting state.

QUESTION 2 MULTI-HOP

A factory's controllers run an operating system the vendor stopped supporting years ago. Production cannot stop for a replacement this quarter. Which pair — the platform's status, and the control that contains it?

End of life; isolation. EOL means no patches will ever come (Lesson 0012's glossary) — so patch management has nothing to manage. Until replacement, the exam's paired answer is isolation: segmentation or air gap, the ICS answer from Lessons 0012 and 0018. A zero-day, in contrast, will be patched eventually.

QUESTION 3

Field laptops hibernate overnight — memory contents land on the internal drive. Which protection does that sleep state need?

Encryption at rest. Suspend to disk writes memory to storage — the data's state changes to at rest, and Lesson 0019's table says what at rest needs. Suspend to RAM keeps contents in powered memory: it needs physical custody instead.

QUESTION 4 MULTI-HOP

An update server signs every package it ships; clients refuse to install anything the signature does not verify. Which technique, and which Lesson 0012 attack does it kill?

Code signing; malicious updates. The developer's private key signs the binary; the client verifies with the public key before running it. A poisoned or substituted update fails the check — supply-chain integrity at the installer. Input validation is the consumer-side mirror: proves what arrived is acceptable, not that what shipped is authentic.

QUESTION 5 MULTI-HOP

Audit finds the deployment pipeline carrying the database password in a plaintext environment variable. Which practice replaces it — and what is the dividing line against its nearest neighbor?

Secrets management. A central vault for machine credentials with access control, rotation, and an audit trail. The dividing line against key management: secrets authenticate machines (API keys, database passwords); keys are for cryptography. Both fail the same way when pasted into a file — but only one belongs in a vault per pipeline credential.

QUESTION 6 BEST ANSWER

A team must find flaws in code that has not shipped — there is no running system yet, and findings are needed before tomorrow's deployment. Both analyzers are on the shelf. Which do you run tonight?

Static analysis (SAST). It reads source without running it — exactly what a pre-deployment, no-live-system window allows. The defensible near miss: DAST probes a running instance and catches what source-reading misses (configuration, environment) — but it requires a system to run, and tonight there is none. Fuzzing is a DAST cousin with the same requirement.

QUESTION 7

Boot integrity: which technique makes firmware refuse to run unsigned boot code — blocking, not just noticing?

Secure boot. The firmware refuses — a boot-level rootkit is blocked. Measured boot records fingerprints for later reading (the TPM writes it down); attestation is someone reading that record remotely. Detect, verify, block — three different verbs, three different names. You typed the detect half cold yesterday.

QUESTION 8 MULTI-HOP

After Lesson 0014's session-hijacking incident, the web team hardens the session cookie. Which pair of cookie flags closes the route scripts took to the tokens?

Secure and HttpOnly. Secure confines the cookie to HTTPS — never plain HTTP. HttpOnly bars scripts from reading it — which is exactly how cross-site scripting (Lesson 0011) escalated into session theft (Lesson 0014). Not to be confused with the Secure Boot of Question 7 — different universe, same adjective.
