Core Commands & The Lifecycle

The image ⇄ container loop, and every command that moves you around it.

01The mental model in one line

An image is an immutable, layered filesystem template, stopped and stored. A container is a running Linux process — isolated — created from an image, plus a thin private writable layer on top. One image, many containers. Delete a container, its writable layer dies with it; the image is untouched.

image (on disk / registry) ─ docker run → container (running) ─ docker stop → container (stopped) ─ docker rm → gone

Stopped containers still exist (files intact) until removed. Only rm destroys the writable layer.

02Containers

commandwhat it does
docker run FLAGS IMAGECreate a container from an image and start it. Pulls the image first if missing.
docker psList running containers. Add -a to include stopped ones.
docker exec -it NAME shStart an extra process (a shell) inside an already-running container.
docker logs NAMEPrint the main process's output. -f to follow.
docker stop NAMESends SIGTERM (graceful), then SIGKILL. Container persists, stopped.
docker rm NAMEDelete a (stopped) container and its writable layer. -f = stop+remove.

03Images

commandwhat it does
docker pull IMAGEDownload an image from a registry to local storage.
docker imagesList images stored locally.
docker rmi IMAGEDelete a stored image (only if no container uses it).
docker image history IMAGEShow the layers the image is built from, newest first.
Full image names have structure: HOST/NAMESPACE/REPO:TAG. Plain nginx secretly means docker.io/library/nginx:latest. The tag latest is just a default name — nothing more magical than that.

04The flags you'll actually use

docker run -d              # detached — run in background
           --name web      # human name instead of random one
           -p 8080:80      # host port 8080 → container port 80
           -it             # interactive + tty — for shells
           --rm            # auto-remove container when it exits
           nginx

docker exec -it web sh   # "give me a shell in there"

05Gotchas worth taping to the wall

  • macOS/Windows: containers are Linux — they run inside a hidden Linux VM (Docker Desktop or OrbStack). ps on your Mac will not show them.
  • Removing a container ≠ removing an image. The image is the template; it survives every container's death.
  • Files written inside a container vanish with it. Persistent data needs volumes (Module 4).
  • A stopped container still exists. It holds disk space and its name — docker run --name web twice fails until you docker rm web.
