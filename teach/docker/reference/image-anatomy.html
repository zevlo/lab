Image Anatomy — Layers, Tags, Digests

What an image is made of, how it's named, and which names you can trust.

01The image in one line

An image is an ordered stack of read-only layer diffs plus a small config blob (entrypoint, env, exposed ports), everything named by sha256: content digest. The container's private writable layer is added at run time and is not part of the image.

config — CMD, EXPOSE, ENV0 B
layer 4 — + nginx config, scripts4.6 kB
layer 3 — + apt-get install nginx61 MB
layer 2 — + Debian base filesystem74 MB
writable layer (container's, not the image's)runtime

Stacked diffs reconstruct the filesystem. Metadata instructions create no layer — that's the 0 B rows in history.

02The name has five parts

ghcr.io/weaveworks/flagger:1.28.0@sha256:9c3f…   # the whole anatomy

docker pull nginx   # secretly means…
docker pull docker.io/library/nginx:latest
partmeaningif omitted
registrywho stores and serves itdocker.io (Docker Hub)
namespaceowner — user or orglibrary (official images)
repothe image name properrequired
tagmovable version labellatest (just the default name)
@digestexact content fingerprintyou get whatever the tag points at today
Tag ≠ version control. A tag is a pointer the publisher can re-point at any time; latest guarantees nothing about age. A digest (@sha256:…) is computed from the bytes — same digest, same layers, forever. Production pins digests or exact version tags.

03Layer rules that matter

  • Content-addressed: a layer's true name is its sha256 digest — identical bytes, identical ID.
  • Shared across images: images on the same base store the base layers once. Already exists during a pull = you already have those bytes.
  • Pull = manifest, then missing layers: the registry hands over a JSON list of layer digests; the client downloads only what it lacks, verifying each against its digest.
  • tag is free: it pins another label onto the same layers — no copy. Two tags, one IMAGE ID.
  • rmi removes references: prints Untagged: for labels; layer bytes are deleted only when the last reference goes.

04Commands

commandwhat it shows / does
docker imagesLocal images: repo, tag, IMAGE ID (config digest, short), size. Same ID on two rows = same image, two labels.
docker image history IMAGEThe layers + metadata rows, newest first — the build's birth certificate. 0 B rows changed config, not files.
docker image inspect IMAGEFull JSON. Useful fields: .Id (config digest), .RepoDigests (the registry's content pin), .RootFS.Layers (ordered layer digests).
docker tag SRC NEWAdd a label. Zero bytes copied.
docker rmi REFRemove a reference. Untagged: = label gone, layers kept while referenced.

05Worth taping to the wall

  • The image is a manifest: a config blob plus an ordered list of layer digests. No magic — checksums in JSON.
  • IMAGE ID (from docker images) is the config digest. The content pin is RepoDigests — use image@sha256:… to re-pull the exact same thing in 2030.
  • Small images = fewer/smaller layers (fewer diffs, slimmer base). How to get there: Module 3, Dockerfile optimization.
  • "Just re-pull latest" is how a Tuesday becomes an incident.
