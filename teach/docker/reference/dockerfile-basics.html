Dockerfile Basics

Every instruction, the RUN-vs-CMD line, and the cache rules that decide build speed.

01The instructions you'll actually use

instructiondoeslayer?
FROM imageBase image. Always first.inherits its layers
WORKDIR /appWorking directory for RUN/COPY/CMD.0 B — config
COPY file .File from build context into the image.file's size
RUN cmdExecute at build time; result frozen into the image.bytes changed
ENV k=vSet an environment variable in the image.0 B — config
EXPOSE portDocument the port for humans. -p does the real mapping.0 B — config
CMD ["exe","arg"]What a container runs at start. Exec form (quotes) is the default choice.0 B — config
RUN vs CMD. RUN: once, at build, frozen in. CMD: every container start, saves nothing. RUN makes the image; CMD runs it. Your CMD process becomes PID 1 (Lesson 0004 field note).

02The build cache rules

  • Cache stops at the first change. Docker walks top to bottom; the first instruction whose inputs changed breaks the chain. Above it: reused. From it down: rebuilt.
  • Content, not timestamps. COPY's cache is keyed on file checksums. touch does nothing; a one-character edit rebuilds that layer.
  • Order stable → changing: base image → system packages → dependency install (pip install / npm ci after copying only the lockfile) → your code, last.
  • A Dockerfile edit busts everything below it too — instruction text itself is an input.
  • Escape hatches: docker build --no-cache rebuilds all layers; --pull fetches a fresh base image even if one is cached.

03Build context and .dockerignore

docker build -t name . — the dot is the build context: the folder the CLI sends to the daemon. COPY paths are relative to it. Keep it small: a .dockerignore file (gitignore syntax) keeps .git, node_modules, and secrets out of the context — and out of the image.

04The canonical ordering (copy this shape)

FROM python:3.12-slim          # 1. base — changes rarely
WORKDIR /app                   # 2. layout
COPY requirements.txt .        # 3. dependency list only
RUN pip install -r requirements.txt   # 4. slow step — cached until the list changes
COPY . .                        # 5. your code, last — changes every day
EXPOSE 8000
CMD ["python", "app.py"]

05Worth taping to the wall

  • One instruction = one layer. docker image history IMAGE shows your Dockerfile as rows — the birth certificate (Lesson 0002).
  • Slim bases, pinned versions. python:3.12-slim beats python:latest: smaller, and predictable. Tags are mutable pointers (Lesson 0002); pin versions you've tested.
  • Chain RUN cleanups: RUN apt-get update && apt-get install -y pkg && rm -rf /var/lib/apt/lists/* — one layer, no leftover cache.
  • Slow steps belong high (early), fast steps low (late). Rebuild cost = everything below your first change.
