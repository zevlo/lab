Isolation & Namespaces

Eight filtered views, one shared kernel — and the Docker flags that poke holes in each.

01The model in one line

A container's "isolation" is a set of namespaces: kernel wrappers that give a process a private view of one global resource. Nothing is copied or virtualized — one kernel holds every process, interface, and mount; namespaces just narrow the window. (Limits — CPU, memory — are the other half: cgroups.)

container A: sees pid 1 · own eth0 · own hostname
container B: sees pid 1 · own eth0 · own hostname
↕ namespaces narrow the view ↕
one shared kernel: all processes · all interfaces · all mounts

The kernel's own words: a namespace makes it appear that processes have "their own isolated instance" of a global resource — namespaces(7).

À la carte is the whole point. Each *=host flag shares exactly one dimension and leaves the others private. --network=host still gets a private PID table and filesystem — but it now shares one network stack, so host ports collide first-come-first-served.

03Rules worth taping to the wall

  • One kernel, many views. Every container's "PID 1" is an ordinary high-numbered process on the shared kernel. --pid=host proves it by showing neighbors.
  • Every =host flag is a hole in the wall. Handy for debugging; an attack surface by habit. Seeing other containers' processes or sharing their network is something to justify, not default to.
  • "Host" on macOS = OrbStack's Linux VM — the kernel containers always shared. Never macOS itself.
  • Port publishing is hole-punching between NET namespaces. -p 8080:80 forwards host:8080 → container:80 across the boundary that --network=host would erase.
  • Namespaces die with the process. Kernel tears the views down when the container's last process exits — no separate cleanup exists.
  • User namespaces are off by default — containers run as root-in-container mapped to root-on-host unless configured. Why that matters: Module 5.

04The demos, condensed

docker run --rm busybox ps                  # a universe with one process (fresh PID ns)
docker run --rm --pid=host busybox ps       # the truth: all containers' processes, one kernel
docker run --rm busybox hostname            # 12-char id — its own UTS slot
docker run --rm alpine ip addr              # own lo + one private eth0 (fresh NET ns)
docker run --rm --network=host alpine ip addr # the VM's whole wiring instead
