CPU profilers

Lecture 4 slice — sampling vs tracing, perf + flame graphs, Valgrind callgrind. Grounded in Debugging and Profiling.

Sampling vs tracing

KindRecordsUse
samplingperiodic stacks (often ~1 ms)production — low overhead
tracingevery function callshort tests — exact counts, caller/callee

Linux sampler: perf. Linux tracer in this lecture: Valgrind callgrind.

perf

# Overview (software events work in Docker-on-Mac; hardware often does not):
perf stat ./slow

# Stacks — this box: software timer. Bare-metal Linux: omit -e to use cycles.
perf record -e cpu-clock -g ./slow
perf report --stdio

# MS flame graph:
perf script | stackcollapse-perf.pl | flamegraph.pl > flame.svg

callgrind (tracing)

valgrind --tool=callgrind ./tiny
callgrind_annotate --auto=no --inclusive=yes --show-percs=yes callgrind.out.*

Self cost = instructions in that function. Inclusive = self + callees (main ≈ 100%). Writes callgrind.out.<pid>. --cache-sim=yes and kcachegrind: named. Shrink the workload — Valgrind is tens of times slower.

Compile line (MS slow.c)

gcc -g -O2 -fno-omit-frame-pointer slow.c -o slow -lm
# callgrind: -DOUTER=4 -DWORK=50  (lesson knobs; MS defaults 100 / 1000)

Drill box

mkdir -p /tmp/ms-cpu
docker run --rm -it --privileged -v /tmp/ms-cpu:/work -w /work --name ms-cpu debian bash
apt-get update && apt-get install -y gcc valgrind linux-perf git ca-certificates

SVG lands on the Mac: open /tmp/ms-cpu/flame.svg. Named only: cProfile, py-spy, go tool pprof, cargo-flamegraph.
