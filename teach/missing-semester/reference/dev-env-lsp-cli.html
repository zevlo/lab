Language Server Protocol (LSP)

A language server is a long-running program that understands a language semantically. An editor talks to it over LSP. Typical features: completion, hover docs, jump-to-definition, find-references, import help, plus format / lint / type diagnostics.

IDEs wire this in via extensions (MS examples: Pylance, gopls). Under this mission: no vim plugin managers — do not install an in-editor language client tonight.

Stock commands used in the lesson

python3 -m py_compile broken.py   # nonzero on syntax error
gofmt -w main.go                  # rewrite formatting
go vet ./...                      # report suspicious constructs
python3 -m pip install --user mypy
mypy typed.py                     # nonzero on type errors
Checkers fail with nonzero status → compose with && / CI. Point tools at the right interpreter/module path the same way IDEs need an “environment” (packaging lecture goes deeper).
