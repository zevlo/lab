Redirection

Stdout, stderr, overwrite vs append, merge order, and tee. Portable forms preferred (>file 2>&1).

Three streams

NamefdDefault
stdin0keyboard
stdout1terminal
stderr2terminal

Results go to stdout. Diagnostics go to stderr. Both look the same on screen until you redirect.

Operators (pareto)

FormDoes
cmd > fileOverwrite file with stdout
cmd >> fileAppend stdout to file
cmd 2> fileOverwrite file with stderr only
cmd > file 2>&1Both streams into file (order matters)
cmd 2>&1 | tee fileMerge, then pipe; see + save
|Stdout of left → stdin of right (not a file)

Order of 2>&1

From bash Redirections: 2>&1 means “point fd 2 at whatever fd 1 currently points to.” Apply it after you retarget stdout.

cmd >out.txt 2>&1     # GOOD — both in out.txt
cmd 2>&1 >out.txt     # BAD  — stderr still on terminal
Memory aid. Redirect the destination first (>file), then duplicate stderr onto it (2>&1). Left-to-right, destination before merge.

tee

From Shotts / info coreutils: tee copies stdin to a file and to stdout — a T-junction on the pipe.

cmd 2>&1 | tee /tmp/capture.txt
cmd 2>&1 | tee -a /tmp/capture.txt   # append to the capture file

Demo command

ls /tmp /no-such-path
# stdout: listing of /tmp
# stderr: “No such file or directory”

Beyond the pareto

Bash-only &>file / &>>file, |& (pipe both), n>&m fd juggling, process substitution <(…), /dev/null deep patterns. Prefer >file 2>&1 on bare remotes for POSIX-lean muscle.
