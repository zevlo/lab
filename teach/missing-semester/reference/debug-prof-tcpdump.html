Network debugging — tcpdump

Lecture 4 slice — packets as the neutral witness: the observation-point ladder, command shapes, the libpcap filter language, and reading a TCP capture. Grounded in Debugging and Profiling.

The observation ladder

Four tools, four observation points, one incident:

ToolObservation pointSees
curl -i (L0008)the clientthe conversation — request, status, headers
ss -tlnp (L0010)the boxthe sockets — listeners, owning processes
strace (L0032)the kernel boundarythe syscalls — socket/bind/accept4
tcpdumpthe wirethe packets — both directions, the raw fact

Capturing needs raw interface access — sudo on shared boxes (root in your own container). Not Linux-only: macOS ships tcpdump (lo0/en0; -i any on recent macOS). tcpdump -D lists interfaces when unsure.

The filter language (libpcap)

Same language Wireshark uses; compiles to BPF, runs in the kernel — filtered-out packets never reach userspace. Primitives: host, port, net, src/dst, tcp/udp/icmp. Combinators: and/or/not. Man-page examples:

tcpdump -n 'port 8080'
tcpdump -n 'host 192.0.2.1'
tcpdump -n 'src host 192.0.2.1 and port 53'
tcpdump -n icmp

Reading a TCP capture

11:04:07.113501 lo In IP 127.0.0.1.51732 > 127.0.0.1.4444: Flags [S],  seq 3847561023, win 65495, options [mss 65495,…], length 0
11:04:07.113544 lo In IP 127.0.0.1.4444 > 127.0.0.1.51732: Flags [S.], seq 2309310903, ack 1, win 65483, options […], length 0
11:04:07.113568 lo In IP 127.0.0.1.51732 > 127.0.0.1.4444: Flags [.],  ack 1, win 65495, length 0
11:04:07.113701 lo In IP 127.0.0.1.51732 > 127.0.0.1.4444: Flags [P.], seq 1:79, ack 1, win 65495, length 78: HTTP: GET / HTTP/1.1

Anatomy: timestamp interface dir IP src.port > dst.port: Flags […], seq …, ack …, length N. Sequence numbers print relative to the conversation’s start after first sight (-S for absolute). Flags on sight:

FlagMeans
[S] / [S.]SYN / SYN+ACK — the handshake’s first two lines
[.]ACK — receipt, no data
[P.]PSH+ACK — carries payload (the GET, the body)
[F.]FIN — orderly close, one per side
[R.]RST — abort: nothing listening / broken stream
UDP lines look simpler — no flags, e.g. IP 127.0.0.11.42331 > 127.0.0.11.53: 45051+ A? example.com. (31) — a DNS question. The A? annotation is tcpdump decoding the payload, same as HTTP: GET above.

The HTTPS caveat (MS). Encryption makes tcpdump less useful for HTTPS: connection shape (handshake, sizes, resets) visible, payload ciphertext. Content is browser dev tools / mitmproxy territory. Plaintext HTTP, by contrast, reads in full under -A.

Where to run it

Everywhere — Linux remotes and macOS alike (unlike strace). The lesson drill uses the L0030 container posture (docker run --rm -it -p 4444:4444 --name ms-net debian bash, apt-get install -y tcpdump python3 curl) for a quiet, disposable, root network. Note for reading captures back: tcpdump -r file resolves names by default — -nr keeps numbers.

Beyond this slice

  • Wireshark — GUI analysis of the same .pcap files: follow-stream, protocol decodes, same filter language. Named, not on the defaults-only terminal stack.
  • mitmproxy — intercepting proxy for encrypted-traffic content (MS-linked for the HTTPS problem).
  • Header-slicing filters — pcap-filter(7) can match inside headers, e.g. 'tcp[tcpflags] & (tcp-syn|tcp-fin) != 0' (SYN/FIN packets only) or portrange 0-1023.
  • -s snaplen — capture fewer bytes per packet (default 262144); -e — link-layer header (MAC addresses).
  • ICMP / ARP lines — ping/reply shapes and arp who-has … tell … for local-Layer-2 questions; natural next reads once TCP flags are fluent.
