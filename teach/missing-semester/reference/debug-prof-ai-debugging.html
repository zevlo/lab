AI for debugging

Lecture 4 slice — an LLM as a reader of tool output, not a replacement for the tool. Distinct from L0029 form factors (authoring). Grounded in Debugging and Profiling.

Not L0029

L0029 named how AI writes code: autocomplete, inline chat, agent — the boundary was how much existing code the model can touch. This slice is how an LLM reads a diagnosis you already know how to produce (ASan, strace, a compiler wall, a bt). Limitations (first-class)

  • Hallucinate a fluent, wrong explanation.
  • Suggest a fix that masks the bug (e.g. delete free on uaf.c — silences the use-after-free, leaves a leak).
  • Always verify with the tool that produced the artifact (ASan, g++, strace). Exit status is still the verdict (L0023).
  • Complement, not replacement, for understanding the code.

Same gate as L0028 / L0029: draft, not verdict.

Debug symbols (why the paste is readable)

gcc -g -fno-omit-frame-pointer …

-g writes DWARF so stacks name file:line instead of addresses. -fno-omit-frame-pointer keeps a frame-pointer chain the unwinder can walk — complete stacks, and the same habit the profilers will want. Without these, you paste hex. Matters for native binaries (C / C++ / Rust); Python and Java already ship symbolic traces. L0034’s ASan report said uaf.c:12 because of -g.

Drill artifacts

L0030 container: docker run --rm -it --name ms-ai-dbg debian bash, then apt-get install -y gcc g++ strace vim.

ASan paste — L0034 uaf.c, gcc -fsanitize=address -g. Competent read: heap-use-after-free, write at :12, freed at :10, allocated at :6. Invented race / double-free = hallucination. “Delete the free” = mask.

Compiler wall — std::sort on a Widget with no operator<. Typical first useful line:

error: invalid operands to binary expression ('const Widget' and 'const Widget')
    return __lhs < __rhs;
…
note: in instantiation of function template specialization 'std::sort<…>' requested here
    std::sort(w.begin(), w.end());

Debian g++ is often noisier (no match for 'operator<' plus a candidate list). Either fix is fine if g++ exits 0: add operator< on Widget, or pass a comparator lambda to sort.

strace paste — strace -e trace=file cat /no/such/file. The line is openat(…, "/no/such/file", …) = -1 ENOENT (L0032). If the model blames permissions or a missing .so, that is a hallucination.
