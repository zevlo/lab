dig and ss

DNS lookup and listening sockets — the mission pair for “where does this name go?” and “what is bound on this host?”

dig — DNS lookup

From man dig (BIND). Default type is A. Uses resolvers in /etc/resolv.conf unless you name a server with @.

CommandDoes
dig nameFull answer (status, ANSWER section, timing)
dig name +shortAnswer data only (IPs, etc.)
dig @1.1.1.1 nameQuery that resolver, not system default
dig name AIPv4 address (default)
dig name AAAAIPv6 address
dig name MXMail exchangers
dig -x IPReverse lookup (PTR)
Status line. In full output look for status: NOERROR (ok) vs NXDOMAIN (name does not exist). Empty +short with NXDOMAIN means “no such name,” not “tool failed.”

ss — sockets (Linux)

From man ss (iproute2). Mission flag set: ss -tlnp.

FlagMeans
-tTCP
-lListening only
-nNumeric (no service-name lookup)
-pShow process (may need root for others’ procs)
-uUDP (use with -lnp as needed)
 
ss -tlnp
# Local Address:Port  — e.g. 0.0.0.0:22 or *:443
# Process             — e.g. users:(("sshd",pid=…,fd=…))
macOS. ss is not installed. On Linux remotes use ss. Local Mac preview only: lsof -nP -iTCP -sTCP:LISTEN.
