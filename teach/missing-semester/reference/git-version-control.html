Git data model and commands

Lecture 5 — objects + refs. Grounded in Version Control and Git.

Data model

blob   = file bytes
tree   = map of name → blob | tree
commit = parents + author + message + snapshot (a tree)
object = blob | tree | commit     # stored by SHA-1
ref    = mutable name for a commit hash
HEAD   = “where we are” (usually a branch ref)
repo   = objects + references

History is a DAG, not a line. A merge commit has two parents. Commits are immutable; “editing history” means new commits + moving refs.

git cat-file -p HEAD
git cat-file -p HEAD^{tree}
git log --all --graph --decorate --oneline

Three trees

PlaceWhat it is
working directoryfiles you edit
staging area (index)what the next commit will contain
HEAD commitlast snapshot on this branch

git add copies working → index. git commit turns the index into a new commit and moves the current branch (and HEAD).

Command map (MS)

CommandDAG move

git add / commitnew commit object; move branch ref
git branch / switchcreate / move HEAD to a ref
git mergecommit with two parents (or fast-forward)
git rebasereplay commits as new objects on a new parent
git fetchdownload objects + remote-tracking refs
git pullfetch then merge
git pushsend objects; update remote ref
git reset FILEunstage (MS)
git restorediscard working-tree changes
git stashpark uncommitted work on a side ref
git blame / showwho last touched a line; show that commit
