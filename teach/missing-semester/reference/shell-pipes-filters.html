Pipes & core filters

Lecture 1 composition slice. Grounded in Introduction to the Shell.

Pipe vs redirect

FormFeeds
cmd1 | cmd2Stdout → another program (stdin)
cmd > fileStdout → file (overwrite)
cmd >> fileStdout → file (append)
cmd < fileFile → stdin
Most filters read a file argument or stdin when no file is given. That is why pipes work.

Core filters (MS simple tools)

CommandDoes
cat filePrint file contents
head [-n N] fileFirst N lines (default often 10)
tail [-n N] fileLast N lines
grep PAT fileLines matching PAT (regex)
sort fileSort lines
uniqDrop adjacent duplicate lines
uniq -cCount adjacent duplicates
sort -nrNumeric reverse sort (rank counts)
tee fileCopy stdin to file and stdout
uniq needs sorted input. It only collapses runs of identical adjacent lines. Always sort | uniq -c, then optionally sort -nr.

Ranking recipe

sort file \
  | uniq -c \
  | sort -nr \
  | head -n 5

With a mid-pipe save:

sort file | uniq -c | sort -nr | tee /tmp/ranked.txt | head -n 5
