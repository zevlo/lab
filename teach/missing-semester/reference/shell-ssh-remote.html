SSH / remote machines

Lecture 2 Remote Machines slice. Grounded in Command-line Environment.

Connect & remote commands

ssh user@host
ssh user@host 'hostname; whoami'

# ls remote, wc local
ssh user@host ls | wc -l

# both remote (quote the pipeline)
ssh user@host 'ls | wc -l'
Unquoted | is parsed by your local shell. Quote (or escape) when the whole pipeline should run on the server.

Keys

PieceRole
~/.ssh/id_ed25519Private key — secret, never share
~/.ssh/id_ed25519.pubPublic key — safe to install on servers
~/.ssh/authorized_keysOn the server — which pubkeys may log in
 
ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519
ssh-keygen -y -f ~/.ssh/id_ed25519          # print matching pubkey

ssh-copy-id -i ~/.ssh/id_ed25519 user@host
# or: cat ~/.ssh/id_ed25519.pub | ssh user@host 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'

Files: scp / rsync

scp local.txt user@host:remote/path/
scp user@host:remote/path/file.txt ./

rsync -av local.txt user@host:remote/path/
rsync -av --partial big.bin user@host:~/
rsync skips identical files and can resume with --partial. Both honor ~/.ssh/config Host aliases.

~/.ssh/config

Host vm
    User alice
    HostName 172.16.174.141
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host *.example.com
    User alice
Then ssh vm, scp file vm:, rsync -av . vm:proj/ all use the same defaults. Permissions: config and private keys should be mode 600.
