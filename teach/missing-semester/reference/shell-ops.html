Reference · shell ops

pgrep, kill, curl, cut

Find a process, signal it, probe HTTP, extract a field. The incident reflex from the mission’s ops success criteria.

cut — pick fields

From info coreutils (cut invocation). Fields are 1-indexed.

FormDoes
cut -d D -f NSplit on delimiter D; keep field N
cut -d' ' -f1First whitespace-separated field
cut -d' ' -f2Second field (e.g. HTTP status code)
cut -d: -f1,3Fields 1 and 3 (comma list)
Spaces. Default delimiter is tab, not space. For space-separated text always pass -d' ' (or -d " ").

pgrep — find by pattern

CommandDoes
pgrep -f PATTERNPIDs whose full argv matches (portable)
pgrep -lf PATTERNmacOS: PID + full command line
pgrep -af PATTERNLinux (procps): PID + full command line
Name vs args. Without -f, match is against the short process name only. Prefer -f when hunting something like http.server in the argv.

kill — send a signal

From man kill: default signal is TERM (15). Prefer TERM before KILL (9).

CommandDoes
kill PIDSend TERM — polite stop; allows cleanup
kill -TERM PIDSame, explicit
kill -9 PIDKILL — cannot be caught; last resort
kill -0 PIDCheck PID exists (no signal sent)
 
PID=$(pgrep -f 'http.server 8765')
kill "$PID"          # TERM first
sleep 1
kill -0 "$PID" 2>/dev/null || echo gone

curl — probe HTTP

CommandDoes
curl -i URLResponse headers + body (mission flag)
curl -sI URLHeaders only; silent progress meter
curl -si URLHeaders + body; silent meter
 
curl -si http://127.0.0.1:8765/ | head -1
# HTTP/1.0 200 OK  →  status is field 2
curl -si http://127.0.0.1:8765/ | head -1 | cut -d' ' -f2

Beyond the pareto

pkill (signal by name — easy to over-match), kill -HUP reload patterns, curl -X/-d/-H for full API work, dig, ss -tlnp (Linux). Add when an incident needs them.
