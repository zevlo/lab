Lesson 0001 · Vim grammar

Vim

Operators, motions, and text objects are a sentence. Arrive by name, change a chosen subset, then put the result where it belongs.

Why this matters

DevOps editing is navigate, read a snippet, and change a small piece — often over SSH, never with a mouse. Vim’s interface is a language for that distribution of work. Missing Semester lecture 3 assumes this grammar; this file is the floor, not a plugin tour.

Read first (≈15 min): :help usr_02.txt through usr_04.txt (modes, moving, small changes). Optional: MS Text editing and Vim — same idea, thinner map.

This is the whole vim floor — grammar, how you jump, substitute vs visual, registers and clipboard. Spread sittings. Scratch lives under /tmp/ms-vim/. Create files from bash with cat > file <<'EOF', not by pasting into Insert (autoindent). No arrow keys. Defaults only — no remaps, no plugins.

Knowledge 1 — the sentence, then arrive by name

Normal is home. Insert is for typed replacement only. Lost? Esc (or Ctrl-[), then speak the next sentence:

[count] operator [count] motion / text-object
e.g. d3w · ci" · >ip
KindWhat it is
operatorsd delete (also yanks) · c change · y yank · p/P put · >/< indent · = auto-indent
motionsw/b/e word · 0/^/$ line · gg/G file · f{x}/t{x} on the line · % matching brace
text objectsi inner / a around: w word, p paragraph, " quotes, ( parens, { braces

ciw is “change inner word.” da" takes the quotes; di" leaves them. Counts multiply: d3w = 3dw.

Do not scroll to the edit. Search is a motion: /pat, n/N, * for the word under the cursor. f{x} then ; repeats on the line. Mark a line with ma, return with 'a. Every jump is in the jump list: Ctrl-o back, Ctrl-i forward. Regex in search: escape dots (/db\.internal).

Knowledge 2 — substitute, visual, repeat

Bulk rename is :s. Prefer it for whole-file work; cgn+. when you want to skip matches by hand.

CommandDoes
:s/old/new/gall matches on this line
:%s/old/new/gall matches in the file
:%s/\<old\>/new/gcwhole-word, confirm each (y/n/a/q)
v / V / Ctrl-vchar / line / block select, then an operator
.repeat last change

Word boundaries matter: :%s/prod/production/g turns production into productionuction. Use \<prod\>. Visual is for seeing the target when the motion is awkward: vip, vi", then d/y/>. gv reselects. Block (Ctrl-v) is a column — insert with I / A after the selection.

Knowledge 3 — registers and the clipboard

Every y/d/c writes a register; p reads one. Prefix "{name} then the operator.

RegisterRole
"unnamed default — last delete clobbers it
0last yank only — paste with "0p after a stray dd
a–znamed stash; A appends
+system clipboard — "+y / "+p
_black hole — delete without clobbering "

Local Mac: :echo has('clipboard') should be 1. Remote vim’s "+y is the remote pasteboard. Pull text to this Mac via tmux copy-mode (next lesson), not "+y over SSH.

No clipboard=unnamedplus. Explicit "+ keeps the default unnamed register for in-buffer edits. Do not remap Caps Lock; use Esc.

1 — One sentence per edit

cd /tmp/ms-vim
cat > service.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: payments-api
  labels:
    app: payments
    env: staging
spec:
  type: ClusterIP
  ports:
    - name: http
      port: 8080
      targetPort: 8080
  selector:
    app: payments
---
# downstream: redis://cache.internal:6379/0
# owner: "platform-team"
# retry: 3
endpoints:
  - host: db-blue.internal
    role: primary
  - host: db-green.internal
    role: replica
EOF
vim service.yaml

(a) Search to staging, change the word to production with a text object.
(b) On the owner comment, ci" to sre-oncall.
(c) Both 8080 → 8443 with :%s (or cgn + .).
(d) Mark endpoints: as e, gg, return with 'e.
(e) On the primary host, change blue → amber with f or search, not l held down.
(f) Visual-line yank the two host entries into register a; paste once with "ap (undo after if you want).

show answer

(a) /staging then ciw → production → Esc.
(b) /owner → ci" → sre-oncall.
(c) :%s/8080/8443/g. Word-boundary not needed here; the digits are unique.
(d) me on endpoints:, gg, 'e. Ctrl-o also walks back.
(e) /blue or f. then ciw on blue.
(f) V over the two - host lines (or vip if it fits), "ay, then "ap.

2 — Registers vs clipboard

cat > /tmp/ms-vim/secrets.yaml <<'EOF'
stringData:
  publishable: pk_live_abcd1234
  secret: sk_live_wxyz9876
  webhook: whsec_qwer4567
EOF
vim /tmp/ms-vim/secrets.yaml

Yank the webhook line into w. Delete another line with dd. Paste the webhook with "wp. Then yank the secret value to the system clipboard ("+y) and prove it with pbpaste in another pane. Why would this last step fail in remote vim?

show answer

"wyy (or V"wy) on the webhook line. After dd, unnamed is the delete; "wp still has the webhook. viw"+y on the secret token, then pbpaste. Remote "+ is the remote pasteboard — use tmux copy-mode to bring text home.

Check your understanding

Four questions. Shuffled answers.

Q1The vim sentence is:

  • Operator plus a motion or text-object (counts optional)
  • Insert mode plus arrow keys, then Escape to save
  • A plugin that expands snippets when you tab
  • Visual mode only — Normal cannot delete

Q2ci" vs ca":

  • Inner changes the contents; around takes the quotes too
  • Inner is linewise; around is characterwise
  • Around writes the system clipboard; inner does not
  • They are aliases — vim treats quotes the same

Q3You yanked a line, then dd another. Paste the yank with:

  • "0p — register 0 still holds the last yank
  • p — unnamed is never written by delete
  • "+p — deletes always go to the macOS clipboard
  • u then p — undo is the only way back to a yank

Q4In vim over SSH, "+y copies to:

  • The remote clipboard — use tmux copy-mode to bring text to this Mac
  • Your Mac pasteboard automatically, via SSH magic
  • Register 0 only; + is ignored on remote hosts
  • The unnamed register, same as a plain y
