Lesson 0026 · Missing Semester — Dev Environment

Terminal workflow vs IDE

Name the two shapes of a development environment, map your bash + vim + tmux + Ghostty stack, then fix a small broken script with composed vim edits.

Why this matters

Missing Semester lecture 3 is about the development environment: the set of tools you use to edit, understand, and change code. You already built the terminal half of that story across vim (L0001–0005), tmux (L0006–0013), and the shell/SSH track (L0015–0025). This slice names the map explicitly — IDE vs terminal workflow — so later lecture-3 topics (language servers, AI form factors) have a place to hang, without abandoning defaults-only vim.

Read first (10–15 min): MS Development Environment and Tools — the opening (IDE vs terminal) through “Text editing and Vim” / “Putting it all together.” Skim language servers and AI sections for awareness only; they are later slices. Skip Caps Lock remaps and plugin shopping lists.

Knowledge 1 — two shapes

At the center is text editing, plus extras people want nearby: highlighting, type checks, formatting, autocomplete. Those can live in one application or as separate programs.

ShapeHow it looks
IDEOne GUI app (MS example: VS Code) bundles editor + language features + often AI
TerminalCompose tools: multiplexer + editor + shell + language CLI tools

MS’s terminal example uses tmux, Vim, a shell, and language CLIs (they mention Ruff / Mypy for Python). Tradeoffs they call out: IDEs are often easier to start and ship richer AI autocomplete; terminal workflows are light, and they may be all you have when there is no GUI or you cannot install software (bare SSH box, recovery shell, locked-down host).

MS advice: get basic familiarity with both; master at least one. Your mission masters the terminal shape for DevOps — that is intentional, not a missing VS Code install.

Defaults-only still holds. No vim plugin managers, no remaps (skip Caps Lock→Esc advice for now — use Esc / Ctrl-[). Do not install a second IDE for this lesson. Language servers and AI tools come later as concepts that fit around this map.

Knowledge 3 — vim as the edit core (retrieval)

MS’s point: programming time is mostly navigate, read snippets, and make small edits — not long insert-mode typing. Vim’s interface is a language: operators + motions + text objects. You already drilled that (L0001–0005). Lecture 3’s “Putting it all together” is composition practice, not a new grammar.

Useful reminders from the MS sequence (you know these keys):

G          end of file
o / O      open line below / above → Insert
/{pat}     search; n / N next / prev
w b e      word motions; counts like 2w
:{n}       go to line n
ci"        change inside quotes
Esc        back to Normal
Vim mode elsewhere. MS notes that many apps offer Vim keybindings (editors, even some AI tools). Optional later: enable Vim mode where you want it. Do not change bash readline or remaps tonight.

Drill — map, then fix fizzbuzz

Ghostty + bash + vim. Scratch: /tmp/ms-dev/.

  1. Say out loud (one sentence each):
    1. What is an IDE workflow?
    2. What is a terminal workflow?
    3. When might the terminal shape be your only option?
    show answer

    (a) One GUI app bundling edit + language features (often AI).
    (b) Compose separate tools — e.g. tmux + vim + bash + CLIs.
    (c) No GUI, cannot install software, or you only have SSH / a recovery shell.

  2. Create the broken MS-shaped script: 
    mkdir -p /tmp/ms-dev && cd /tmp/ms-dev
cat > fizz.py <<'EOF'
def fizz_buzz(limit):
    for i in range(limit):
        if i % 3 == 0:
            print("fizz", end="")
        if i % 5 == 0:
            print("fizz", end="")
        if i % 3 and i % 5:
            print(i, end="")
        print()

def main():
    fizz_buzz(20)
EOF
vim fizz.py
    show answer

    File exists under /tmp/ms-dev/fizz.py. Three bugs match MS: main never called; range starts at 0; multiples of 5 print "fizz" instead of "buzz".

  3. Fix in vim with composed Normal-mode edits (MS order is fine; any correct grammar is fine):
    1. Call main under if __name__ == "__main__": at the end of the file.
    2. Change the loop to range(1, limit + 1).
    3. On the % 5 branch, change the string to "buzz" (e.g. ci").
    Save and quit (:wq).
    show answer

    One valid path (from MS): G → o → type if __name__ == "__main__": then indent main() → Esc. /range → move with w/e/i/a to get range(1, limit + 1). :6 (or search) → ci" → buzz → Esc. Then :wq.

  4. Prove it: 
    python3 fizz.py | head -n 15
    Expect lines like 1, 2, fizz, 4, buzz, fizz, … (15 = fizzbuzz).
    show answer

    If you still see a leading blank or 0, range was not fixed. If fives still say fizz, the ci" edit missed the % 5 line.

  5. Cold rebuilds (no peeking):
    1. Name your four core terminal-workflow tools (emulator, shell, multiplexer, editor).
    2. One sentence: why does MS say vim fits how programmers actually spend time?
    3. From memory: Normal-mode sequence to change the contents of the next double-quoted string on the line (ci" family).
    show answer

    (a) Ghostty, bash, tmux, vim.
    (b) Most time is navigate / read / small edit — not long insert streams; composable commands match that.
    (c) On the quote: ci", type, Esc (or f"ci" / search first if needed).
