Lesson 0026 · Missing Semester — Dev Environment

Development environment

Two shapes: one app, or compose tools. Intelligence is a language server or a CLI. AI is a layer. A container is a disposable box with that environment as code.

Why this matters

Lecture 3 is the set of tools you edit, check, and generate code with. You already master the terminal shape (Ghostty, bash, tmux, vim, ssh). This file names the map, the checkers you can run on an SSH box, the three AI form factors, and a container as a portable “remote” that is not a second IDE.

Read first (≈20 min): MS Development Environment and Tools — the whole lecture, including Exercises. Skip Caps Lock remaps, vim plugins, installing VS Code, extension shopping.

This is the whole lecture as the terminal track. Spread sittings. Scratch: /tmp/ms-devenv/. Zed is owned, not curriculum. Vim stays the no-AI floor and the review surface. devcontainer CLI is optional (like jq / mypy); the drill maps JSON to docker run.

Knowledge 1 — two shapes, your stack is compose

ShapeHow it looks
IDEOne GUI app bundles editor + language features + often AI
TerminalCompose: multiplexer + editor + shell + language CLIs

IDEs are easier to start and ship richer autocomplete. Terminal is light, and it may be all you have (no GUI, cannot install, recovery shell). MS: basic familiarity with both; master at least one. This mission masters the terminal shape.

Your map: Ghostty · bash · tmux · vim · ssh + remote tmux · dotfiles. Programming time is navigate / read / small edit — L0001’s grammar, not long Insert. MS “Putting it all together” is the fizzbuzz compose drill below.

Knowledge 2 — language servers, then CLI checkers

A language server understands a language semantically. The editor talks LSP: completion, hover, jump-to-definition, find-references, imports, diagnostics. No vim LSP client under this mission — those features need a plugin or an IDE. The standalone path is the floor:

JobTool
Python syntaxpython3 -m py_compile file.py
Python typesmypy (one-off install, MS-named)
Go format / vetgofmt -w file.go · go vet ./…

Exit status still rules (L0019): 0 = clean. Wrong python3 on PATH → wrong packages. Ruff and virtualenvs wait (Code Quality / Packaging lectures). Checkers catch syntax and types; they do not catch “valid but wrong-shaped.”

Knowledge 3 — AI as a layer; a container as a box

Form factorTouches existing codeYour surface
autocompleteonly beyond the cursorZed
inline chata selected block → proposed editZed; conversational in opencode
agentmulti-step, files, commandsopencode (you are in it); Zed agent

MS’s autocomplete bug: valid Python, import re inside the function. Gate with the checkers — draft, not verdict. Placement/style needs review or a later linter.

Three nouns: image (blueprint) · container (running instance) · dev container (container + devcontainer.json, editor-agnostic spec). Daily verbs: docker build -t tag . · run · ps · exec -it · stop/rm · logs. The run that is the loop:

docker run -it --rm -v "$PWD":/work -w /work -p 8000:8000 --name ms-box IMAGE bash

-it interactive, --rm disposable, -v live mount (edit on the host). JSON keys are those flags, versioned like a dotfile. Image build depth is the Packaging lecture. compose/k8s stay out of scope.

2 — Fix fizzbuzz in vim

cat > fizz.py <<'EOF'
def fizz_buzz(limit):
    for i in range(limit):
        if i % 3 == 0:
            print("fizz", end="")
        if i % 5 == 0:
            print("fizz", end="")
        if i % 3 and i % 5:
            print(i, end="")
        print()

def main():
    fizz_buzz(20)
EOF
vim fizz.py
python3 fizz.py | head -n 15

Bugs: main never called; range starts at 0; fives print "fizz" not "buzz". Compose Normal-mode edits (G, o, /range, ci").

show answer

G o if __name__ == "__main__": main(). /range → range(1, limit + 1). On the % 5 line ci" → buzz. Expect 1, 2, fizz, 4, buzz, …

3 — Checkers, not an IDE extension

MS: configure a language server. Terminal substitute: break syntax, py_compile nonzero, fix in vim, re-run until 0. Then mypy on a typed file (install if needed: python3 -m pip install --user mypy). Optional: gofmt -w / go vet on a tiny main.go.

show answer

Missing ) → compile error, status ≠ 0. After the fix, py_compile … && echo ok. mypy fails on add("a", 1) even when compile passes — types ≠ syntax.

4 — Gate an AI edit

Have an agent or Zed inline-chat “extract markdown links” (or paste MS’s import re-inside-function shape). Run py_compile / mypy. What did the checker catch vs miss? Skip “browse the extension marketplace.”

show answer

Syntax-clean code can still place import wrong. Checkers raise the floor; they do not replace review. opencode = agent in the terminal; vim = no-AI review.

5 — Map devcontainer.json to docker run

If Docker is up: docker run --rm -it -v /tmp/ms-devenv:/work -w /work debian bash, then python3 -m py_compile on a mounted file (install python if needed). Read this JSON and name the equivalent flags:

{"name":"ms-dev","workspaceFolder":"/work",
 "mounts":["source=${localWorkspaceFolder},target=/work,type=bind"],
 "forwardPorts":[8000]}
show answer

Mount → -v host: /work. Workspace → -w /work. Port → -p 8000:8000. Name → --name. An IDE would run those for you; the file is still just docker, versioned.

  • Only available if you install VS Code Remote

Q3Autocomplete vs inline chat vs agent — the boundary is:

  • How much existing code the model can touch
  • Which programming language you use
  • Whether the model has internet
  • Whether vim or Zed is open

Q4A dev container is:

  • A container plus editor-agnostic config (devcontainer.json) for that environment
  • A Kubernetes cluster defined in compose.yaml
  • The same as an image — they are two words for a Dockerfile
  • A vim plugin that runs docker for you
