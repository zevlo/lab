Packaging and Shipping Code

To run your code on another machine, ship a packaged artifact and declare the environment that it needs.

Why this matters

A program that works on your laptop still has to start on a server, in CI, and on a teammate’s machine. Shipping means turning your source into an artifact that someone else can install and run. That someone else is often you, a week later.

Libraries, command-line tools, and web services use different artifacts: a wheel, a binary, or a container image. They share one pattern. Name the artifact and name the environment it assumes: Python version, system libraries, configuration, and network. This lecture uses Python. Rust’s cargo tool covers the same ideas with one CLI. Python splits the work across specifications and several tools.

Knowledge 1: Dependencies and environments

A dependency is a library that your program imports and that the language runtime doesn’t include. When you write import requests, Python looks in site-packages. pip fetches a wheel from PyPI, installs that library and its dependencies, and copies the files there.

If two packages need incompatible versions of numpy, the installer can’t satisfy both. That’s dependency hell. A virtual environment gives each project its own interpreter and its own package set:

python3 -m venv venv
source venv/bin/activate   # prepends venv/bin to PATH
which python3              # should show .../venv/bin/python3
deactivate                 # restores PATH, then unsets this function

source venv/bin/activate prepends venv/bin to PATH. After that, which python3 should print a path under venv/bin. pip and python3 then refer to that environment. The shell picks those binaries because of PATH order.

activate also defines a shell function named deactivate. type deactivate prints the function. which deactivate searches only for files on PATH, so it often prints nothing. When you run deactivate, the function restores your previous PATH and then removes itself.

Install into the project venv. macOS and Linux tools can depend on the system Python. This machine already pins the interpreter version with mise (Python 3.12.14). Create one virtual environment per project so packages stay isolated too. Use that environment’s pip.

Other languages often create a project-local environment for you. cargo does that for Rust. The idea is the same. Missing Semester recommends uv as a faster installer. You can try it later.

Knowledge 2: Artifacts, versions, and lockfiles

Source is the code that you edit. An artifact is the packaged file that someone else installs. Python searches a list of known locations for imports. A .py file in the current directory is importable. To import that file from /tmp, add the directory to the search path or install the package. Packaging copies the code into a location that the runtime already searches.

The Python manifest is the pyproject.toml file (PEP 621). A wheel (.whl) is a zip archive of modules, metadata (name, version, dependencies), and the install layout. A .tar.gz file is a source distribution (sdist) for machines that compile from source.

The tag py3-none-any means any Python 3, any OS, and any CPU. The tag cp312-macosx_arm64 means CPython 3.12 on Apple Silicon. If the tag doesn’t match your platform, pip tries another wheel or builds from the sdist. A source build needs a compiler.

You change source continuously. You release artifacts at discrete versions. Semantic Versioning uses MAJOR.MINOR.PATCH:

BumpPromise
PATCH 1.2.3 to 1.2.4bug fix; compatible
MINOR 1.2.3 to 1.3.0feature; compatible
MAJOR 1.2.3 to 2.0.0breaking change; callers may need edits

In 0.x versions, a minor bump can include breaking changes. In the pyproject.toml file you constrain versions with specifiers: ==2.32.3 (this exact version), >=8.0 (8.0 or newer), >=1.24,<2.0 (at least 1.24 and below 2.0), and ~=2.1.0 (at least 2.1.0 and below 2.2.0). That last form is Python’s compatible-release operator.

SemVer is a convention. A patch release can still change behavior. Calendar Versioning, such as Ubuntu 24.04, encodes a date. It describes age, and it leaves compatibility implicit.

A library is imported by other projects, so wide version ranges reduce conflicts. An application is the final consumer, so pin exact versions. A lockfile records the solver’s exact list: name, version, URL, and often a hash. The next install then matches. pip freeze writes that list as text. Files such as uv.lock add hashes. Nix and Bazel can pin the compiler as well; this lesson names those tools.

New versions fix security issues and can change behavior. Test upgrades in CI, and keep a rollback path to a known-good artifact. Tools such as Dependabot watch for new versions. This lesson names them.

Knowledge 3: Virtual machines, containers, and configuration

Some dependencies live outside the language: OpenSSL, GPU drivers, a specific libc. A language package manager leaves those to the operating system.

What you packKernel
VMwhole guest OSguest’s own
containerapp, libraries, and filesystemshared with host

Containers start faster because they share the host kernel. A VM isolates more strongly because it runs a guest kernel. On macOS and Windows, Docker runs a Linux VM, which you already used in lesson 0026.

An image is a layered template. A container is a running instance of that image. You can start many containers from one image.

A Dockerfile is the recipe. Each FROM, RUN, and COPY instruction becomes a layer. Docker reuses a layer until that instruction or an earlier one changes. Copy the lockfile or manifest first, then the source, so a code edit leaves the dependency layers cached. Pin image tags. Prefer slim base images. Keep secrets out of layers; old layers remain in the image history.

Missing Semester’s improved example copies a uv binary from another image instead of compiling it. That’s the builder pattern. This lesson names it. An amd64 image on this arm64 Mac runs under emulation and is slow.

Pass configuration when the process starts, using environment variables or a file. Use the same artifact in development, staging, and production. For a required secret, read os.environ["API_KEY"] so a missing value raises immediately. Store secrets in the runtime environment. Git commits and image layers keep old copies, so treat a committed secret as leaked.

If two processes need conflicting packages, run them in two containers. Compose declares those services in one YAML file. Compose DNS resolves the service name: redis://cache:6379 when the service is named cache. Volumes keep data after the container stops. On Linux, production often wraps docker compose up -d in a systemd unit. This Mac uses launchd instead. Kubernetes orchestrates many machines. Missing Semester calls it overkill for small projects. This lesson names it.

Services communicate over HTTP. You publish Python packages to TestPyPI (a sandbox) or PyPI, binaries with GitHub Releases, and images to ghcr.io or Docker Hub. Registries verify files with checksums, and sometimes signatures. Use TestPyPI for experiments. Use PyPI for packages that you intend other people to install.

1. Save the environment

Missing Semester: dump the environment, create a venv, dump again, and diff. Why does the shell pick the venv’s binaries? What is deactivate?

cd /tmp/ms-ship
printenv | sort > before.txt
python3 -m venv venv
source venv/bin/activate
printenv | sort > after.txt
diff before.txt after.txt
which python3
type deactivate
which deactivate || true
deactivate
which python3
show answer

The diff shows PATH starting with /tmp/ms-ship/venv/bin (macOS may print /private/tmp/...). VIRTUAL_ENV appears, and often VIRTUAL_ENV_PROMPT does too. That prepend is why python3 and pip resolve inside the venv. type deactivate shows a function that restores the old PATH, unsets VIRTUAL_ENV, and runs unset -f deactivate. which deactivate usually prints nothing because which searches for files. After deactivate, which python3 points at mise or the OS again, and type deactivate fails.

2. Package, install, and lock

Missing Semester: create a package with a pyproject.toml file, install it in a virtual environment, then create a lockfile and inspect it. Use a tiny stdlib module:

cd /tmp/ms-ship
mkdir pkg && cd pkg
cat > greet.py <<'EOF'
import sys

def greet(name: str) -> str:
    return f"Hello, {name}!"

def main() -> None:
    print(greet(sys.argv[1] if len(sys.argv) > 1 else "world"))

if __name__ == "__main__":
    main()
EOF
cat > pyproject.toml <<'EOF'
[project]
name = "ms-greet"
version = "0.1.0"
description = "tiny shipping drill"
requires-python = ">=3.11"

[project.scripts]
greet = "greet:main"

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[tool.setuptools]
py-modules = ["greet"]
EOF
python3 -m venv venv
source venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install .
greet Ada
python3 -m pip wheel . -w dist
ls dist
python3 -m pip freeze > requirements.lock
cat requirements.lock
deactivate
show answer

greet Ada prints Hello, Ada! because the console script is on PATH while the venv is active. The dist/ directory has a wheel, and pip may also emit an sdist. requirements.lock is the output of pip freeze: exact names and versions in this environment, including ms-greet==0.1.0 plus setuptools and pip. That’s a pin list. uv lock would add URLs and sha256 hashes. To reinstall later, run pip install -r requirements.lock inside a fresh venv.

The YAML builds missing-semester:latest from the repo Dockerfile (Ruby on Alpine, bundle install, Jekyll serving on all interfaces). 4. Dockerfile, Compose, and Redis

Missing Semester: write a Dockerfile for a small Python app, then a Compose file that runs it next to Redis. Use the stdlib only. Redis is there so the app can address it by service name:

cd /tmp/ms-ship
mkdir app && cd app
cat > app.py <<'EOF'
import os
from http.server import BaseHTTPRequestHandler, HTTPServer

class H(BaseHTTPRequestHandler):
    def do_GET(self):
        body = f"hello redis={os.environ.get('REDIS_URL', 'missing')}\n".encode()
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, fmt, *args):
        return

HTTPServer(("0.0.0.0", 8080), H).serve_forever()
EOF
cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
EXPOSE 8080
CMD ["python3", "-u", "app.py"]
EOF
cat > docker-compose.yml <<'EOF'
services:
  web:
    build: .
    ports:
      - "8080:8080"
    environment:
      - REDIS_URL=redis://cache:6379
    depends_on:
      - cache
  cache:
    image: redis:7-alpine
EOF
docker compose up --build

In another pane, run curl -s http://127.0.0.1:8080. Why does the app use the hostname cache?

show answer

Curl prints hello redis=redis://cache:6379. Compose DNS resolves the service name cache to the Redis container. Inside web, localhost is the web container itself. depends_on starts Redis first; it doesn’t wait until Redis accepts connections. Host port 8080 maps to container port 8080. Tear down with Ctrl-C, then docker compose down.

5. TestPyPI and ghcr.io

Missing Semester: publish a package to TestPyPI, then push an image to ghcr.io. Skip this exercise unless you have TestPyPI and GitHub Container Registry accounts and a package that you intend to upload. Treat tokens as runtime secrets. Keep them out of git and out of image layers. TestPyPI is a sandbox index; install from it with pip install --index-url https://test.pypi.org/simple/. An image registry stores filesystem artifacts the way PyPI stores wheels. Checksums (and sometimes signatures) let the other machine trust the bytes.

Check your understanding

Four questions. Answers shuffle on each page load.

Q1A virtual environment exists so that:

  • This project’s interpreter and packages stay isolated from the OS Python and other projects
  • pip can write into /usr/lib without sudo and share one global site-packages
  • Docker can share the host kernel with the language runtime on macOS
  • Git can snapshot site-packages instead of tracking your source tree

Q2A wheel is:

  • A zip of code, metadata, and install layout that pip can install
  • The source tree you edit, including tests and the venv directory
  • A lockfile listing exact hashes of every transitive dependency
  • A VM image that bundles a guest kernel with your program

Q3Libraries and applications constrain dependencies differently because:

  • Other projects import a library (wide ranges); an app is a final product (pin and lock)
  • Libraries must pin exact versions; applications must publish version ranges
  • Only applications have transitive dependencies; libraries never do
  • SemVer makes lockfiles unnecessary once the major version is frozen

Q4Runtime configuration should be:

  • Passed in at start time with environment variables, files, or a secret store
  • Compiled into the wheel so production cannot drift from the build
  • Stored as ENV API_KEY=… in the Dockerfile so every replica matches
  • Copied from the developer’s ~/.bashrc so prod equals the laptop
