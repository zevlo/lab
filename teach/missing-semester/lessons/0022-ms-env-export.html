Environment variables & export

Shell-local vars vs the environment children inherit — one-shot VAR=value cmd, export, printenv, and unset.

Why this matters

You already assign shell variables and expand "$name" (L0018), and you know PATH / HOME from navigation (L0015). Missing Semester’s CLE “Environment variables” section draws the line that matters for DevOps: a plain foo=bar stays in this shell; children only see what is in the environment. That is how DEBUG=1 ./run.sh, TZ=… date, and long-lived exports actually work.

Read first (10–15 min): MS Command-line Environment — the “Environment variables” section only (assignment / quotes / printenv / one-shot prefix / export / unset). Skip process substitution, Return codes, and later sections for now.

Knowledge 1 — shell variables (quick refresh)

Assign with name=value (no spaces). Everything is a string. Double quotes expand; single quotes are literal.

host=db01
echo "$host"    # db01
echo '$host'    # $host

stamp=$(date +%Y-%m-%d)
echo "$stamp"
host = db01 is not assignment. Spaces make the shell run a command named host with arguments = and db01. Same footgun as L0018.

Convention: lowercase for shell-local scratch; ALL_CAPS for environment-facing names (HOME, PATH, DEBUG, TZ). Not enforced — just readable.

Knowledge 2 — the environment vs this shell

When bash starts a program, it passes a set of name/value pairs: the environment. Inspect it with printenv (or printenv NAME for one key). A variable that is only set in the shell — not exported — does not appear there and is invisible to children.

secret=only-here
printenv secret        # empty / no line
bash -c 'echo "[$secret]"'   # []  — child never saw it

Two ways to put a value into a child’s environment:

FormScope
VAR=value cmdone-shot — only that command (and its kids)
export VAR=valuethis shell’s environment — later children inherit it
 
TZ=Asia/Tokyo date
echo "${TZ-}"          # still empty in this shell (one-shot did not stick)

export DEBUG=1
bash -c 'echo DEBUG=$DEBUG'   # DEBUG=1
printenv DEBUG                # 1
One-shot does not change your shell. After TZ=Asia/Tokyo date, echo $TZ in the parent is still empty. Use export TZ=… if you want it to stick (then unset TZ when done).

Knowledge 3 — unset and common names

unset NAME removes a variable from the shell (and from the environment if it was exported).

export DEBUG=1
unset DEBUG
printenv DEBUG         # gone

Programs often read env vars instead of requiring a flag — same idea as flags being a convention:

NameTypical role
HOMEyour home directory
PATHwhere the shell finds commands (L0015)
TZtimezone for date and friends
DEBUG / app-specifictoggle verbose / feature flags

Drill — prove inheritance

Ghostty + bash. Scratch optional: /tmp/ms-env/. Clean up exports with unset when done.

  1. Shell-local stays local: 
    mkdir -p /tmp/ms-env && cd /tmp/ms-env
token=local-only
echo "shell=$token"
printenv token || true
bash -c 'echo child=[${token-}]'
    show answer

    Shell prints the value. printenv shows nothing useful for token. Child prints empty brackets — not exported.

  2. One-shot prefix (MS TZ shape): 
    TZ=Asia/Tokyo date
echo "TZ after=[${TZ-}]"
date
    show answer

    First date reflects Tokyo (or an offset vs local). TZ after is empty. Second date is your normal zone again.

  3. export so children see it: 
    export DEBUG=1
printenv DEBUG
bash -c 'echo child_DEBUG=$DEBUG'
unset DEBUG
bash -c 'echo child_DEBUG=${DEBUG-}'
    show answer

    While exported, printenv and the child both show 1. After unset, the child sees empty.

  4. Script that reads the environment (no argv needed): 
    cat > greeter.sh <<'EOF'
#!/bin/bash
echo "hello from ${NAME:-world}"
EOF
chmod +x greeter.sh
NAME=ops ./greeter.sh
./greeter.sh
export NAME=prod
./greeter.sh
unset NAME
    show answer

    One-shot → hello from ops. Plain run → hello from world (default). After export → hello from prod. ${NAME:-world} is “use NAME, or world if unset/empty.”

  5. Cold rebuilds (no peeking):
    1. Run date once in UTC via a one-shot env prefix (do not leave TZ set in your shell).
    2. export a var, prove a bash -c child sees it, then unset it.
    3. One sentence: what is the difference between FOO=1 and export FOO=1 for a child process?
    show answer

    (a) TZ=UTC date (or TZ=Etc/UTC date)
    (b) export FOO=1 → bash -c 'echo $FOO' → unset FOO
    (c) Plain FOO=1 is shell-local (child does not see it); export puts it in the environment children inherit. (FOO=1 cmd is the one-command middle path.)

Check your understanding

Four questions. Shuffled answers.

Q1After secret=x (no export), what does a child see?

  • nothing — not in environment
  • always the value x
  • only if printenv ran
  • only via $1 argv

Q2What does TZ=UTC date change?

  • env for that date only
  • TZ in your shell forever
  • system clock hardware
  • PATH for all shells

Q3What does export DEBUG=1 do?

  • add DEBUG to the environment
  • print DEBUG to stdout
  • delete DEBUG permanently
  • run DEBUG as a command

Q4How do you remove an exported variable?

  • unset NAME
  • export -d NAME
  • rm $NAME
  • kill %NAME
