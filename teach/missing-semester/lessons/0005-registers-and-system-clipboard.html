Lesson 0005 · Phase 2 — vim

Registers & system clipboard

Registers are vim's clipboards (plural). Knowing which slot your text just went into — and how to talk to the macOS clipboard from inside vim — is the unlock for fast local edits and remote SSH workflows.

Why this matters

Devops patterns that registers solve cleanly:

  • Copy a Kubernetes secret from a remote vim into your local browser.
  • Stash a snippet you'll need in five minutes ("ay … "ap) so it survives the edits in between.
  • Delete a chunk of text without overwriting the thing you just yanked.
  • Paste the same YAML stanza in four places without re-yanking.
  • Recover your last yank after a stray delete clobbered it.

Knowledge 1 — registers are vim's clipboards (plural)

Every y, d, c, and x writes the affected text to a register. Every p reads from one. Vim has dozens of them, addressed by a " prefix followed by one character.

:regList all registers and their current contents
:reg a b +Inspect specific registers only

The unnamed register (") is the default: plain y/d/p write and read it. Every other register is opt-in — name it explicitly to use it.

Knowledge 2 — the register families that matter

"Unnamed — default for plain y/d/p
0Last yank only (never written by deletes). Lifesaver when a delete clobbers ".
1Last delete or change of a line or more. Family 1–9 rotates (new delete → 1, old 1 → 2, etc.); 1 covers ~every real case.
a–zNamed, persistent. Stash text you'll come back to.
A–ZAppend to the lowercase slot instead of replacing it.
+System clipboard — the workhorse for this lesson.
_Black hole — writes are discarded. Delete without clobbering ".
% · . · :Read-only: current filename · last inserted text · last :-command.

Knowledge 3 — using a register

The pattern is always "{register} then the operator or motion. The " prefix tells vim "the next character names a register."

"ayyYank current line into register a
"apPaste from register a
"0pPaste your last yank, even after a delete clobbered "
"+yYank selection to system clipboard
"+pPaste from system clipboard
"_ddDelete line into the black hole — " untouched
"AyAppend current line to register a

Registers compose with everything you already know: operators, counts, motions, text objects, visual mode. 3"ayy yanks three lines into a. vip"+y yanks the paragraph to the system clipboard. "_ciw changes a word without saving the old one.

Knowledge 4 — system clipboard on macOS (local vim + ghostty)

When vim is built with clipboard support, the + register bridges directly to the macOS pasteboard via pbcopy/pbpaste. No config, no plugin.

:echo has('clipboard')Returns 1 if your vim can talk to the system clipboard. Verify once.
"+yyCopy current line into the macOS clipboard
"+pPaste from the macOS clipboard into the buffer
vi( then "+yYank the text inside parens to the system clipboard

Verify it works end-to-end: yank with "+yy, open another ghostty pane (or use the mouse on the ghostty title bar to open a new tab), run pbpaste — your line prints. Or Cmd-V in any browser field.

If has('clipboard') returns 0. Your vim was built without pasteboard support (common on stripped-down server builds, rare on Homebrew vim). Fallback for one-off copies: select the text with the mouse, Cmd-C / Cmd-V through ghostty's terminal selection. The + register won't work until you install a clipboard-enabled vim.

Knowledge 5 — the remote-SSH gotcha & the OSC 52 bridge

This is the devops-critical bit. When you SSH to a remote host and run vim there, "+y puts text in the remote's clipboard — which is invisible to your local machine. Useless for "copy a URL from the remote vim into my local browser."

The fix is OSC 52: an ANSI escape sequence that means "set the system clipboard." Modern terminals — ghostty included — translate it to a host clipboard write. tmux 3.7b forwards OSC 52 by default (set-clipboard=external), so a copy-mode yank inside an SSH session flows through the SSH connection, lands in ghostty, and ends up in your local macOS clipboard.

The workflow: inside remote tmux, press Ctrl-b [ to enter copy-mode, move to the text, start a selection (the key depends on your copy-mode style — see drill Task 5), copy it, and the text is now in your local clipboard. Verify with Cmd-V. Full depth (remote pbcopy forwarding, vim-to-tmux hooks) comes in the tmux phase; for now, reach for tmux copy-mode when you need to pull text out of a remote vim.

Drill (~10 min)

Create the file from bash:

cat > /tmp/secrets.yaml <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: stripe-key
type: Opaque
stringData:
  publishable: pk_live_abcd1234
  secret: sk_live_wxyz9876
  webhook: whsec_qwer4567
EOF
vim /tmp/secrets.yaml

Tasks

  1. Yank the webhook line (line 9) into register w, then jump to the bottom of the file and paste it with "wp. A second webhook line appears at the end.
    show answer

    9G"wyy — go to line 9, yank the line into register w. G — jump to the last line. "wp — paste from w.

    After this, registers ", 0, and w all contain the webhook line — because specifying a named register also writes the unnamed register.

  2. Delete the publishable line (line 7) without overwriting the unnamed register. Verify by pasting: p should still produce the webhook line, not the deleted publishable.
    show answer

    7G"_dd — go to line 7, delete it into the black-hole register _. The line is gone, but " still holds the webhook line.

    Press p — it pastes " webhook: whsec_qwer4567", proving " was untouched. This is the canonical "delete something throwaway without losing my clipboard" pattern.

  3. Now demonstrate the difference between " and 0. Delete the secret line with a normal dd (no register prefix). Then: p should paste the secret line (your last delete), but "0p should paste the webhook line (your last yank).
    show answer

    After Task 2, the file is 8 lines. 7G lands on the secret line (was line 8). dd deletes it.

    • p pastes " secret: sk_live_wxyz9876" — because " now holds the deleted line (the normal-delete clobbered it).
    • "0p pastes " webhook: whsec_qwer4567" — because 0 only ever receives yanks, never deletes. Your webhook yank from Task 1 is still there.

    Takeaway: 0 is the recovery register for "I yanked something, then deleted something, and now I want the yank back." Reach for "0p whenever p gives you the wrong thing.

  4. Copy the webhook value (whsec_qwer4567) into your macOS clipboard. Verify by running pbpaste in another ghostty pane (or by Cmd-V in a browser).
    show answer

    Two clean ways:

    Option A — line-wise: 8G"+yy (or whichever line currently holds the webhook). Yanks the whole line into +. pbpaste in another pane prints it; Cmd-V in a browser pastes it.

    Option B — value-only: /whsec<CR> to land on the value, then "+yiW — yank the inner WORD into +. Now pbpaste prints just whsec_qwer4567, no surrounding text. Pick this when you need a clean token to paste into a Slack message or config field.

  5. Bonus — verify the OSC 52 bridge. Requires tmux. Open a tmux session, then run tmux show -g set-clipboard — it should output set-clipboard external (the tmux 3.7b default). Enter copy-mode with Ctrl-b [, move to a line of text, start a selection, copy. Switch to any non-terminal app (Notes, a browser URL bar) and press Cmd-V. The text you copied in tmux appears in your local clipboard.
    show selection keys by copy-mode style

    tmux's copy-mode keys depend on the mode-keys option:

    • vi mode (set via set-window-option -g mode-keys vi — an option, not a remap): v to start char-wise selection, V line-wise, move with hjkl / w / /, then y to copy.
    • emacs mode (tmux default): C-Space to start selection, move with C-n/C-p/C-f/C-b or arrow keys, then M-w (Alt-w) to copy.

    If Cmd-V shows nothing: check set-clipboard isn't off, and that no allow-passthrough off is blocking OSC sequences. ghostty accepts OSC 52 by default.

    The full tmux copy-mode curriculum is Lesson 0006. This task just confirms the bridge works end-to-end on your stack.

Tool-matching recap. Three "clipboards" in play: " (vim's default, volatile), 0 (last yank, immune to deletes), + (system clipboard, crosses into macOS). And one delete-target: _ (throw it away). Pick by intent: "where do I want this text to go?" — the register letter follows.
