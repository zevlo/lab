Lesson 0037 · Missing Semester — Debugging & Profiling

Visualizing performance data

A mean can look fine while a plot shows periodic spikes. Log in a tidy CSV so you can graph it — then split by category before you average.

Why this matters

L0036 gave you one command’s three numbers. That is a point. Performance work is a series: latency over an hour, cost of the 1st insert vs the 10,000th. MS: humans spot patterns in graphs much faster than in tables of numbers. Last week’s tidy-logs note (L0031) was not decoration — a line like 1705012345,42.5 is already a plot; “request was a bit slow just now” is not.

Read first (≈5 min): MS Debugging and Profiling — “Visualizing Performance Data” (stop before “CPU Profilers”).

Knowledge 1 — tidy data is the plot

When you add diagnostic output, shape it so a plotter can swallow it later. Two shapes that work:

ShapeExampleWhy
CSV1705012345,42.5timestamp, value — gnuplot’s default job
JSON (structured logs){"t": 1705012345, "ms": 42.5, "ep": "/api"}extra fields you can slice on later

A prose sentence is a dead end: you will re-parse it by hand, then give up and look at the mean. The mean is the thing that hides the spike.

Knowledge 2 — gnuplot, then a terminal

MS’s one-liner, for a file of timestamp,value:

gnuplot -e "set datafile separator ','; plot 'latency.csv' using 1:2 with lines"

Read the pieces (gnuplot’s own language; help plot inside gnuplot):

BitMeans
set datafile separator ','fields are commas, not whitespace (the default)
using 1:2column 1 as x, column 2 as y
with linesconnect the points — a series, not a scatter

That command’s default output is a GUI window. The drill box has no X display, so you pick a terminal first:

set terminal dumb                          # ASCII in the terminal
set terminal png; set output 'latency.png' # a file you can open on the Mac

gnuplot-nox is the Debian package that does this without pulling X11. Same binary, no window.

The one-liner as written needs a display. On this Mac gnuplot is not installed (not a brew-install lesson). In the box, skip the GUI: dumb for a first look, png to take the picture home via the bind mount. Official docs: set datafile separator defaults to whitespace; CSV always needs the comma.

Knowledge 3 — what a graph names that a mean will not

MS’s three use cases, which are the drill:

PlotWhat you seeWhat a mean hid
latency over timea spike every N samplesGC, a cron, a traffic burst — periodic, not “always slow”
insert cost vs sizespikes at 2, 4, 8, 16, …the array doubled; most inserts were cheap
the same metric, split by categoryonly one facet is sicka “system-wide” problem that was one endpoint

The third is faceting: same axes, one subplot per category. MS names Python’s matplotlib and R’s ggplot2 for this kind of iterative slice. ggplot2 stays named (R is not the track). matplotlib is the Python one — plt.subplots(2, 1, sharex=True) then fig.savefig('facet.png'). In a box with no display, matplotlib picks the Agg backend and writes a file; you do not need a window.

Drill — log tidy, then look

Ghostty + bash + vim. Scratch lives on the Mac at /tmp/ms-viz/ and is the container’s working directory (L0030 -v/-w), so PNGs are waiting when you open them. gnuplot and matplotlib are Linux packages here — apt in the box, nothing on the Mac. An SSH Linux remote works identically (add sudo for installs).

  1. Cold-name the slice: why a graph beats a table; the tidy CSV shape; the three things a plot can name that a mean will not.
    show answer

    Eyes find spikes and steps in a picture; a table (or a mean) averages them away. Tidy: timestamp,value (CSV) or structured JSON — not a sentence. Three names: a periodic slowdown (GC/cron/traffic); a doubling-array copy spike; a problem that is one category, not the whole system.

  2. Boot the box with the scratch dir mounted. On the Mac: 
    mkdir -p /tmp/ms-viz
docker run --rm -it -v /tmp/ms-viz:/work -w /work --name ms-viz debian bash
# inside:
apt-get update && apt-get install -y gnuplot-nox python3 python3-matplotlib
    Confirm gnuplot will not try to open a window: 
    gnuplot -e "show terminal"
    show answer

    gnuplot-nox has no X11 terminal. show terminal should mention something like unknown/dumb/png — not x11 or qt. If a later plot errors about a display, you forgot set terminal dumb or png.

  3. Doubling spikes. Still in the box, in /work: 
    cat > grow.py <<'EOF'
cap = 1
for k in range(1, 65):
    if k == cap:
        cost = k      # this insert copied the live buffer into one twice as big
        cap *= 2
    else:
        cost = 1
    print(f"{k},{cost}")
EOF
python3 grow.py > grow.csv
awk -F, '{s+=$2; n++} END {print "mean", s/n}' grow.csv
gnuplot -e "set terminal dumb; set datafile separator ','; plot 'grow.csv' using 1:2 with lines"
    Compare the mean to the picture. Then take a PNG home: 
    gnuplot -e "set terminal png; set output 'grow.png'; set datafile separator ','; plot 'grow.csv' using 1:2 with lines"
    On the Mac (another pane): open /tmp/ms-viz/grow.png.
    show answer

    Mean is a little under 2 — “inserts are cheap.” The plot spikes at 1, 2, 4, 8, 16, 32: those inserts copied the whole buffer. That is MS’s vector-insert example. The mean told you nothing about when it was expensive.

  4. Periodic latency. MS’s other picture: a slowdown that repeats. 
    cat > latency.py <<'EOF'
for t in range(120):
    ms = 200 if t % 15 == 0 else 20
    print(f"{t},{ms}")
EOF
python3 latency.py > latency.csv
awk -F, '{s+=$2; n++} END {print "mean", s/n}' latency.csv
gnuplot -e "set terminal dumb; set datafile separator ','; plot 'latency.csv' using 1:2 with lines"
gnuplot -e "set terminal png; set output 'latency.png'; set datafile separator ','; plot 'latency.csv' using 1:2 with lines"
    Mean should be 32. One sentence: is the service “32 ms p50-ish fine,” or is something waking every 15 samples?
    show answer

    32 ms is the average of a 20 ms baseline and a 200 ms spike every 15 samples (GC, a cron, a traffic burst). The plot names the period; the mean names a service that looks only a bit slow. This is why L0031 asked for CSV-shaped logs.

  5. Facet by endpoint. Same metric, a third column. matplotlib for the split (MS: iterative slice; plt.subplots + savefig): 
    cat > by_endpoint.py <<'EOF'
for t in range(60):
    print(f"{t},20,/api")
    chk = 200 if t % 15 == 0 else 22
    print(f"{t},{chk},/checkout")
EOF
python3 by_endpoint.py > by_endpoint.csv
awk -F, '{s+=$2; n++} END {print "pooled mean", s/n}' by_endpoint.csv

cat > facet.py <<'EOF'
import csv
from matplotlib import pyplot as plt

by = {"/api": ([], []), "/checkout": ([], [])}
with open("by_endpoint.csv") as f:
    for t, ms, ep in csv.reader(f):
        by[ep][0].append(int(t))
        by[ep][1].append(int(ms))

fig, (ax1, ax2) = plt.subplots(2, 1, sharex=True)
ax1.plot(by["/api"][0], by["/api"][1])
ax1.set_title("/api")
ax2.plot(by["/checkout"][0], by["/checkout"][1])
ax2.set_title("/checkout")
fig.savefig("facet.png")
EOF
python3 facet.py
    On the Mac: open /tmp/ms-viz/facet.png. Which facet is sick? Would the pooled mean have sent you looking at /api?
    show answer

    Pooled mean is mid-20s — slightly off, nowhere. /api is a flat 20 ms. /checkout carries the 200 ms period. Split before you average. That is MS’s facet point (ggplot2 does the same in R — named, not run).

Check your understanding

Four questions. Shuffled answers.

Q1Why write diagnostic output as 1705012345,42.5 instead of a sentence?

  • A timestamp,value CSV is already a plot; a prose sentence is not
  • A sentence has more context, so gnuplot can parse it automatically
  • bash time prints CSV by default if you add any print first
  • JSON is illegal in log files; CSV is the only format Linux accepts

Q2plot 'latency.csv' using 1:2 with lines — what is using 1:2?

  • column 1 as x, column 2 as y
  • skip the first two rows of the file
  • plot only the first two points in the file
  • read the twelfth column of a TSV

Q3Append-cost spikes at 2, 4, 8, 16; the mean of those costs is tiny. What did the plot name?

  • Doubling copies of a growing array — a complexity shape a mean hides
  • The CPU is pegged; time’s real line is each spike
  • gnuplot draws a spike on every even x as a default grid
  • The CSV was not tidy, so every other point is garbage

Q4Faceting latency by endpoint shows /api flat and /checkout spiking. Point?

  • A “system-wide” problem can be one category — split before you average
  • Always average first so the facet has less noise to look at
  • Faceting is ggplot2-only; matplotlib cannot show two series
  • The spikes are a gnuplot bug when the CSV has a third column

Ask the teacher. Did the doubling spikes beat the mean? Did faceting make the “not actually system-wide” point? Prefer gnuplot’s dumb terminal or the PNG?
