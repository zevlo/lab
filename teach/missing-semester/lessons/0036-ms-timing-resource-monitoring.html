Lesson 0036 · Missing Semester — Profiling

Profiling

Correct is not fast. Name the scarce resource, then ask which function. A mean is not a plot; a wide flame-graph frame is not a timeline.

Why this matters

Lecture 4’s second half: the program works and is still too slow — or the box is full. time gives three numbers and no names. A profiler names functions. Tidy logs let you see a spike a mean will hide.

Read first (≈15 min): MS Debugging and Profiling — Profiling through CPU Profilers, and the Profiling exercises. Skip Benchmarking (hyperfine’s example is fd vs find). Memory profilers (massif) are notes-only — not in the exercise set.

This is the profiling half. Spread sittings. Scratch: /tmp/ms-prof/. time works on the Mac (bash keyword). htop / free / taskset / ss / perf / callgrind: Linux box. Docker-on-Mac: hardware cycles is <not supported> — use -e cpu-clock. perf needs --privileged (perf_event); Valgrind does not.

Knowledge 1 — measure, then watch the box

type time → shell keyword. help time.

NumberMeans
realwall clock, including waits
userCPU in user code
sysCPU in the kernel

Shapes: sleep 1 → real ≈ 1, user/sys ≈ 0 (wait). Tight loop → real ≈ user+sys (CPU). curl → real ≫ user+sys (network). user+sys > real on several cores is still CPU-bound, just parallel. /usr/bin/time is a different program — stay with the keyword.

QuestionTool
which process is hot?htop (P/M sort, t tree, H threads, h help, q quit). top ships by default.
memory left for new work?free -h — read available, not free
who has this file?lsof FILE / lsof -p PID
who listens on this port?ss -tlnp (Linux); Mac lsof -nP -iTCP -sTCP:LISTEN

taskset --cpu-list 0 stress -c 2: two workers, one core — N workers ≠ N CPUs. Affinity is why.

Knowledge 2 — a series, not a mean

One time is a point. A tidy log is a series: CSV timestamp,value (L0031’s “convert prints to logs,” plotted). gnuplot: set datafile separator ',' then plot 'f' using 1:2 with lines. Headless box: set terminal dumb or png — the default terminal is a GUI. A mean can hide doubling spikes or one bad endpoint; facet before you average. matplotlib for facets if you are already in Python; ggplot2 is R (named).

Knowledge 3 — sampling vs tracing, then a flame graph

Sampling interrupts and records stacks — low overhead, preferred in production. Tracing (callgrind) counts every call — exact, slow. perf is the Linux sampler: perf stat (counters; hardware events often fail in this VM) then perf record -e cpu-clock -g and perf report. Compile with -g and -fno-omit-frame-pointer so default fp unwind works at -O2.

Flame graph: x is the sample population, not time; y is stack depth; width ∝ samples. MS pipeline: perf script | stackcollapse-perf.pl | flamegraph.pl. callgrind: valgrind --tool=callgrind then callgrind_annotate — self vs inclusive. Speedscope / Perfetto / kcachegrind named. Language-specific (cProfile, py-spy) named.

Exercises

MS profiling set. Try before show answer.

1 — three time shapes (Mac)

time sleep 1
time python3 -c 'n=0
for i in range(10**7): n += i'
time curl -s https://missing.csail.mit.edu/ >/dev/null

For curl: where did the rest of real time go?

show answer

Sleep: wait. Loop: CPU. Curl: waiting on the network (real ≫ user+sys).

2 — perf stat then slow.c

In the box: perf stat on a short command — expect <not supported> for cycles. Then MS’s slow.c (or a smaller loop so it finishes), compile gcc -g -O2 -fno-omit-frame-pointer slow.c -o slow -lm, perf record -e cpu-clock -g ./slow, perf report. Optional flame graph if you clone Brendan Gregg’s scripts. Then callgrind on a tiny version — Valgrind is slow.

show answer

Software cpu-clock still samples. Report / flame graph should name sin/cos or slow_computation. Hardware PMU is the VM gap, not a broken perf install. /usr/bin/perf may be a wrapper — use the versioned binary if it complains.

3 — hyperfine

MS: benchmark fd vs find. Skip — fancy-CLI constraint; the example is the reason.

show answer

Named only. Compare two of your scripts with time if you want a poor person’s benchmark.

4 — htop + taskset

In the box: stress -c 2 in one pane, htop in another. Then taskset --cpu-list 0 stress -c 2. Why don’t you see two cores at 100%?

show answer

Both workers are pinned to CPU 0. N workers ≠ N CPUs unless the scheduler (or you) places them there.

5 — occupied port

python3 -m http.server 4444
# other pane:
ss -tlnp | grep 4444     # Linux box
kill <pid>

On the Mac the same question is lsof -nP -iTCP -sTCP:LISTEN.

show answer

ss names the process; kill frees the port. Second http.server 4444 fails until then.

Check your understanding

Four questions. Shuffled answers.

Q1A timed curl shows real 0.27s, user 0.08s, sys 0.03s. The rest of real is:

  • Waiting — network (or disk, or sleep), not CPU
  • A bug in time; real must equal user+sys
  • Kernel time that sys failed to count
  • Proof you need ASan

Q2taskset --cpu-list 0 stress -c 2. Two cores at 100%?

  • No — both workers share CPU 0
  • Yes — -c 2 always means two cores
  • Only if htop is sorted with P
  • Yes on Mac, no on Linux

Q3On a flame graph, a wide frame on the right means:

  • That stack was on-CPU in a large fraction of samples — x is not a timeline
  • That function ran later in the program
  • That function allocated more heap
  • The process was waiting on the network

Q4In this Docker-on-Mac box, perf stat prints <not supported> for cycles. What still works?

  • Software events — perf record -e cpu-clock -g
  • Nothing; perf cannot run in Docker
  • Only callgrind, because it uses PMU too
  • Hardware events if you drop --privileged
