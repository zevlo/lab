Introduction to the Shell

Terminal vs shell, where you are, how programs are found — the foundation of Missing Semester lecture 1.

Knowledge 1 — terminal vs shell

From Missing Semester: a terminal is the visual interface (Ghostty). A shell (bash) reads your commands, runs programs, and shows output. Nearly every platform has a shell; we stay on bash.

date                 # run a program
echo hello           # program + arguments
echo $SHELL          # confirm you are in bash/zsh-class Unix shell

Knowledge 2 — cwd, cd, paths

The prompt shows where you are. ~ is home. pwd (or echo $PWD) prints the working directory. cd changes it — and is a builtin, not a separate binary.

FormMeans
/binAbsolute path (from root)
binRelative (from cwd)
. / ..This dir / parent
cd -Previous directory
Why cd is a builtin. A child process cannot change its parent’s working directory. If cd were an external program, it would change cwd only for itself and exit — your shell would stay put. (Missing Semester exercise.)

Knowledge 3 — PATH, which, man

The shell finds echo / date by searching directories in $PATH (:-separated). which name shows which file runs. man name is the manual — your primary docs habit.

echo $PATH
which echo
man ls          # q to quit; space/ arrows to scroll
ls -l /         # then ask: what do the first columns mean?

Drill

Do every step in Ghostty + bash. Say the answer out loud before you press Enter when you can.

  1. Confirm shell and home: 
    echo $SHELL
pwd
cd /
pwd
cd ~
pwd
    show answer

    You should see something like /bin/bash, then /, then your home path. cd with no args also goes home.

  2. Absolute vs relative (from Missing Semester): 
    cd /
cd bin
pwd
cd ..
pwd
cd /bin
pwd
    show answer

    cd bin from / lands in /bin. .. returns to /. Absolute /bin works from anywhere.

  3. Dot path nonsense that still works — predict pwd before running: 
    cd /
cd bin/../bin/../bin/././../bin/..
pwd
    show answer

    You end at /. . and .. are real path components — walk them carefully.

  4. Repeat navigation three times (muscle): from home → /tmp → .. → home using only cd and pwd after each hop. Then cd - twice and watch it toggle.
    show answer

    cd /tmp, pwd, cd .., pwd, cd ~, pwd. cd - swaps with the previous directory.

  5. PATH: 
    echo $PATH
which date
which ls
/bin/echo "full path works"
    show answer

    which prints a path under one of the PATH directories. Full-path execution skips the search.

  6. man habit (Missing Semester exercise): 
    man ls
    Find what -l does. Run ls -l /. Note the first ~10 characters of a line — you do not need to memorize every bit yet; just open man ls and locate the long-format description.
    show answer

    -l is long format. The leading block is file type + permissions (e.g. drwxr-xr-x). Details deepen later; the win today is using man.

  7. Tiny programs three times each: date, echo hello world, ls ~, cat a small file you create with echo 'hi' > /tmp/ms-hi.txt.
    show answer

    echo 'hi' > /tmp/ms-hi.txt then cat /tmp/ms-hi.txt. Redirects deepen next; here just feel create → print.

Check your understanding

Four questions. Shuffled answers.

Q1Ghostty is the…?

  • terminal program
  • shell interpreter
  • kernel process
  • PATH variable

Q2What does .. mean in a path?

  • parent directory
  • home directory
  • root directory
  • empty directory

Q3How does the shell find echo?

  • search $PATH dirs
  • search only /tmp
  • search the kernel
  • search man pages

Q4Why must cd be a builtin?

  • child can't set cwd
  • PATH forbids binaries
  • man pages require it
  • root owns all paths
