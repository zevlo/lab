Lesson 0016 · Missing Semester — shell

Pipes & core filters

Compose small programs with | — cat/head/tail/grep/sort/uniq from Missing Semester lecture 1.

Why this matters

Missing Semester’s power move is composition: each tool does one job; pipes chain them. This lesson covers the simple tools from Introduction to the Shell, then one ranking pipeline you can rebuild cold.

Read first (10–15 min): MS notes — “What is available in the shell?” through the simple tools (cat/sort/uniq/head/tail/grep), then “The shell language” paragraphs on pipes, >/>>, and tee. Stop before find/sed/awk and the scripting section.

Knowledge 1 — filters read files or stdin

From Missing Semester: most of these programs take a file argument, or read standard input when none is given. That is the contract that makes | work — stdout of one program becomes stdin of the next.

ToolJob
catPrint contents
head / tailFirst / last lines
grep PATKeep matching lines
sortOrder lines
uniq / -cCollapse / count adjacent dupes

Knowledge 2 — pipe vs redirect

| feeds another program. > / >> feeds a file. tee does both: copy to a file while the stream keeps flowing (MS + Shotts).

cmd1 | cmd2           # program → program
cmd > out.txt         # overwrite file
cmd >> out.txt        # append file
cmd | tee out.txt     # see it and save it

Knowledge 3 — uniq needs sort

Adjacent only. uniq collapses runs of identical neighbors. Unsorted input → wrong counts. Muscle: sort | uniq -c | sort -nr | head.

Drill — solo, then compose, then cold

Ghostty + bash. One token per line so you do not need cut/awk yet. Say the expected output before Enter when you can.

  1. Build the sample (heredoc — closing EOF alone on its line): 
    cat > /tmp/ms-users.txt <<'EOF'
root
admin
ubuntu
root
postgres
admin
root
test
ubuntu
root
admin
mysql
ubuntu
root
EOF
    Confirm with wc -l /tmp/ms-users.txt (expect 14).
    show answer

    Fourteen lines. If not, re-run the heredoc — a mistyped closing EOF is the usual culprit.

  2. Solo — run each twice: 
    cat /tmp/ms-users.txt
head -n 3 /tmp/ms-users.txt
tail -n 3 /tmp/ms-users.txt
grep ubuntu /tmp/ms-users.txt
    show answer

    head → root, admin, ubuntu. tail → mysql, ubuntu, root. grep ubuntu → three lines.

  3. Prove the uniq footgun, then the fix: 
    uniq -c /tmp/ms-users.txt
sort /tmp/ms-users.txt | uniq -c
    show answer

    Without sort, counts are nonsense (only adjacent dupes). With sort | uniq -c, each name has one count line — root should be 5.

  4. Rank top names (MS composition shape): 
    sort /tmp/ms-users.txt \
  | uniq -c \
  | sort -nr \
  | head -n 5
    show answer

    Expect root 5, then ubuntu 3 and admin 3 (tie order may vary by locale), then test/postgres/mysql at 1 — head -n 5 shows the first five ranked lines.

  5. Save while viewing — overwrite, then tee: 
    sort /tmp/ms-users.txt | uniq -c | sort -nr > /tmp/ranked.txt
cat /tmp/ranked.txt
sort /tmp/ms-users.txt | uniq -c | sort -nr | tee /tmp/ranked-tee.txt | head -n 3
cat /tmp/ranked-tee.txt
    show answer

    > saves the full ranked table silently. tee writes the full stream to the file while head only shows three lines on screen — open the file to see everything.

  6. Pipe vs redirect — predict before running: 
    grep root /tmp/ms-users.txt | wc -l
grep root /tmp/ms-users.txt > /tmp/roots.txt
wc -l /tmp/roots.txt
    show answer

    Both count 5. First: pipe into wc. Second: redirect into a file, then count the file. Same data, different destination type.

  7. Cold rebuild (no peeking at this page): clear the scrollback mentally, then type from memory the command that prints the top 5 usernames by frequency from /tmp/ms-users.txt. Check against step 4.
    show answer

    sort /tmp/ms-users.txt | uniq -c | sort -nr | head -n 5. If you missed sort before uniq, re-run step 3 until the footgun feels obvious.

  8. Optional spacing: close the terminal tab, open a new one, cd /tmp, and rebuild the ranking pipeline once more without the lesson open.
    show answer

    Same recipe. Crossing a session boundary (new tab, fresh cwd) is a good check that it stuck.

Check your understanding

Four questions. Shuffled answers.

Q1What does | connect?

  • stdout → next stdin
  • stdout → a file
  • stderr → man pages
  • PATH → which

Q2Why sort before uniq -c?

  • uniq needs adjacent
  • sort deletes files
  • uniq ignores stdin
  • head requires sort

Q3Pipe vs > — which is true?

  • pipe→program; >→file
  • both write only files
  • both feed only programs
  • tee replaces both always

Q4What does tee out.txt do in a pipe?

  • save and keep flowing
  • sort then stop
  • delete the input file
  • merge stderr only
