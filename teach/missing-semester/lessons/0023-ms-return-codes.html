Lesson 0023 · Missing Semester — CLE

Return codes

Every command leaves a status — 0 means success — and && / || / if all decide from that number.

Why this matters

You already branch with if [ -f … ] and abort scripts with set -e (L0018), and you met $? / && / || in the lecture-1 workbook (L0020). Missing Semester’s CLE “Return codes” section names the shared rule: programs report success or failure with an exit status, and the shell’s conditionals are just short-circuit tests on that status. That is how deploy one-liners, “retry until fail,” and CI steps decide what to do next.

Read first (10–15 min): MS Command-line Environment — the “Return codes” section only ($?, && / ||, true/false, if/while). Skip Signals (done), Remote Machines, and later sections for now.

Knowledge 1 — exit status and $?

Besides stdout/stderr and filesystem side effects, every process returns a small integer: the return code (exit status). Convention:

CodeMeans
0success — everything went well
nonzerofailure / some issue

Read the last command’s status with $?. Scripts default to exiting 0; force a failure with exit NUM.

true
echo $?          # 0

false
echo $?          # 1

ls /no/such/path
echo $?          # nonzero (often 1)
$? is overwritten every time. After false; echo $?, a second bare echo $? prints 0 — that is echo’s success, not false’s failure. Capture it if you need it later: rc=$?.

Knowledge 2 — && and ||

Shell && / || are not boolean math on strings. They short-circuit on return codes: success means status 0.

FormRuns the right side when…
cmd1 && cmd2cmd1 succeeded (0)
cmd1 || cmd2cmd1 failed (nonzero)
 
# echo only if grep finds a match (-q = quiet, status only)
grep -q "owner=ops" notes.txt && echo "Pattern found"

# echo only if grep finds no match
grep -q "owner=ops" notes.txt || echo "Pattern not found"

true && echo "This will always print"
false || echo "This will always print"
Inverted from many languages. In C / Python, 0 is false. In the shell, 0 is success and counts as “true” for if / &&. Nonzero is failure / “false.”

Knowledge 3 — same rule as if / while

You already use this: if cmd; then …; fi runs the then-branch when cmd returns 0. [ -f notes.txt ] is just a command (test) whose status is 0 or 1. while cmd; do …; done keeps going while cmd returns 0.

if grep -q "owner=ops" notes.txt; then
  echo "Found"
fi

if [ -f notes.txt ]; then
  echo "file exists"
fi

set -e (L0018) is the automatic version: the script exits as soon as a command returns nonzero (with a few exceptions you can learn later).

Drill — prove status, then chain

Ghostty + bash. Scratch: /tmp/ms-rc/.

  1. Scratch + sample file: 
    mkdir -p /tmp/ms-rc && cd /tmp/ms-rc
cat > notes.txt <<'EOF'
status=draft
owner=ops
EOF
pwd
    show answer

    cwd is /tmp/ms-rc. notes.txt has two lines.

  2. Read $? after success and failure: 
    true; echo "true=$?"
false; echo "false=$?"
ls /no/such/path; echo "ls=$?"
    show answer

    true=0, false=1, ls= some nonzero (and an error on stderr). The ; echo form is intentional so echo still runs after a failing ls.

  3. Short-circuit with grep -q: 
    grep -q "owner=ops" notes.txt && echo "Pattern found"
grep -q "owner=ops" notes.txt || echo "Pattern not found"
grep -q "missing" notes.txt && echo "Pattern found"
grep -q "missing" notes.txt || echo "Pattern not found"
    show answer

    First line prints Pattern found. Second prints nothing useful for the || (grep succeeded). Third prints nothing for &&. Fourth prints Pattern not found.

  4. Same idea with if (status, not a special keyword): 
    if grep -q "owner=ops" notes.txt; then echo Found; else echo Missing; fi
if [ -f notes.txt ]; then echo file-ok; fi
    show answer

    Found then file-ok. Both branches are driven by exit status 0.

  5. Script that exits nonzero: 
    cat > fail.sh <<'EOF'
#!/bin/bash
echo "about to fail"
exit 2
EOF
chmod +x fail.sh
./fail.sh; echo "script=$?"
    show answer

    Prints about to fail then script=2. The script’s exit status is whatever exit set.

  6. Cold rebuilds (no peeking):
    1. Show $? after true and after false.
    2. One-liner: print hit only if grep -q owner=ops notes.txt succeeds.
    3. One sentence: why does the shell treat 0 as success / “true”?
    show answer

    (a) true; echo $? → 0; false; echo $? → 1
    (b) grep -q owner=ops notes.txt && echo hit (quotes optional here; fine either way)
    (c) Convention: zero means the command completed without error, so conditionals treat 0 as success.

Check your understanding

Four questions. Shuffled answers.

Q1What does exit status 0 mean?

  • success — command went well
  • failure — always an error
  • stdout was empty
  • process was killed

Q2When does cmd1 && cmd2 run cmd2?

  • only if cmd1 status is 0
  • only if cmd1 status is 1
  • always, ignore cmd1
  • only if stdout matched

Q3What does $? hold?

  • last command’s exit status
  • current working directory
  • count of positional args
  • PID of the shell

Q4What does false || echo hi print?

  • hi — false failed
  • nothing — false succeeded
  • false — the word itself
  • 0 — the exit status
