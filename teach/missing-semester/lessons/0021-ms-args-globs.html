Arguments & globs

What a program actually receives on its argv — and how the shell expands *, ?, and {} before the program ever runs.

Why this matters

You already pass $1 into scripts (L0018) and hit globs in the lecture-1 workbook (L0020). Missing Semester’s CLE “Arguments” section names the model: every CLI gets a list of plain strings; flags are a convention; and globs are expanded by the shell, not by rm or ls. That is why rm *.py beats a for/grep loop — and why quoting a glob can silently break your intent.

Read first (10–15 min): MS Command-line Environment — the “Arguments” section only (through brace / glob examples). Skip Streams, Environment variables, Return codes, and later sections for now.

Knowledge 1 — argv is a list of strings

When you type ls -l folder/, the shell runs /bin/ls with arguments roughly ['-l', 'folder/']. Inside a bash script:

FormMeaning
$0script / program name
$1 … $9positional args (you used $1 in check.sh)
$@all positional args as a list
$#count of positional args
 
#!/bin/bash
# save as /tmp/ms-args/show.sh  then: chmod +x show.sh
echo "name=$0 count=$#"
echo "first=$1"
echo "all: $@"
/tmp/ms-args/show.sh alpha beta
# name=.../show.sh count=2
# first=alpha
# all: alpha beta
Quote "$@" when forwarding args. Bare $@ can break on spaces. Prefer "$@" (MS flaky-test exercise uses this). Same habit as quoting "$1".

Knowledge 2 — flags are a convention

Programs decide how to parse their strings. By convention, options start with - or --:

  • Short: -a, often one letter; groupable: ls -la ≡ ls -l -a
  • Long: --all (same idea as -a for ls)
  • Order of flags usually does not matter: ls -la ≡ ls -al

Many tools also take several operands of the same kind: mkdir src docs is one call, two directories — not two separate mkdirs. That pairs powerfully with globs.

Knowledge 3 — the shell expands globs

Globs are patterns the shell turns into matching pathnames before it invokes the program. rm never sees the literal *.py when matches exist — it sees the expanded names.

PatternMatches
*any string (including empty), non-recursive in the current dir by default
?exactly one character
{a,b,c}brace expansion → multiple words (bash; not a filesystem search)
 
mkdir -p /tmp/ms-args && cd /tmp/ms-args
touch folder/{a,b,c}.py
# → folder/a.py folder/b.py folder/c.py

echo *.py          # may print nothing if no .py in cwd — try:
echo folder/*.py   # folder/a.py folder/b.py folder/c.py

ls folder/?.py     # one-char basename before .py → a.py b.py c.py

Brace expansion is pure text rewrite (works even if files do not exist yet). Filename globs (*, ?) only expand to paths that exist — otherwise bash usually leaves the pattern literal (default nullglob off).

Quotes freeze the glob. echo "*.py" prints the characters *.py. echo *.py expands. Use quotes when you mean a literal star; leave them off when you want matches.
# Combined (MS shape)
touch x.py y.sh
echo *.{py,sh}     # x.py y.sh  (brace first, then glob — details in man bash)

Drill — see argv, then expand

Ghostty + bash. Scratch: /tmp/ms-args/. Clean up when done.

  1. Make the scratch dir and a tiny argv printer: 
    mkdir -p /tmp/ms-args && cd /tmp/ms-args
cat > show.sh <<'EOF'
#!/bin/bash
echo "count=$#"
printf 'arg: %s\n' "$@"
EOF
chmod +x show.sh
./show.sh one "two words" three
    show answer

    Expect count=3 and three arg: lines — including two words as one argument because of the quotes.

  2. Create three files with one brace expansion, then list with a glob: 
    mkdir -p folder
touch folder/{alpha,beta,gamma}.txt
ls folder/*.txt
./show.sh folder/*.txt
    show answer

    touch receives three paths. ./show.sh folder/*.txt should report count=3 — the shell expanded the glob before show.sh started.

  3. Prove quoting blocks expansion: 
    ./show.sh folder/*.txt
./show.sh "folder/*.txt"
    show answer

    First call: three args (expanded). Second: count=1 and a single arg literally folder/*.txt.

  4. One-char glob + multi-operand habit: 
    touch a.py b.py cc.py
ls ?.py
mkdir -p out
cp ?.py out/
ls out/
    show answer

    ?.py matches a.py and b.py only (cc.py has two characters before .py). cp gets multiple sources in one invocation.

  5. Cold rebuilds (no peeking):
    1. In a fresh empty subdir, create setup.sh, build.sh, deploy.sh with one touch and braces.
    2. Run your show.sh (or printf) so it receives only the .sh files via a glob — confirm the count.
    3. One sentence: who expands *.sh — the shell or rm/ls?
    show answer

    (a) touch {setup,build,deploy}.sh
    (b) ./show.sh *.sh → count=3
    (c) The shell expands globs before the program runs.

Check your understanding

Four questions. Shuffled answers.

Q1In a script, what is $#?

  • count of positional args
  • name of the script ($0)
  • last command exit status
  • current job number %N

Q2Who expands *.py in rm *.py?

  • the shell, before rm runs
  • rm itself, always
  • the kernel after exec
  • find, via a hidden hook

Q3What does touch f/{a,b}.txt do?

  • creates f/a.txt and f/b.txt
  • creates one file named f/{a,b}.txt
  • searches the disk for a,b
  • only works inside find -name

Q4What does echo "*.log" print?

  • the literal characters *.log
  • every matching .log file
  • an empty line always
  • an error from bash
