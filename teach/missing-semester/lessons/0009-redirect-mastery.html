Lesson 0009 · Phase shell — redirect

Capture what failed

Stdout vs stderr, > vs >>, why 2>&1 order matters, and tee when you need to watch and save.

Why this matters

Incident work means saving command output — including the error text that usually scrolls past. Lesson 0007 put redirects on the map; this lesson makes them muscle. Finishes the five-family shell pareto before you branch into network tools or tmux copy-mode.

Knowledge 1 — two outputs, one screen

From Shotts (I/O Redirection / TLCL ch. 6) and man bash REDIRECTION: programs write stdout (fd 1, results) and stderr (fd 2, diagnostics). Both default to the terminal, so they look identical until you redirect.

ls /tmp /no-such-path
# listing  → stdout
# error    → stderr

Knowledge 2 — overwrite, append, stderr alone

FormDoes
cmd > fStdout overwrites f
cmd >> fStdout appends to f
cmd 2> fStderr overwrites f

> alone leaves stderr on the screen. That is why “I redirected but still see errors” is so common.

Knowledge 3 — merge with 2>&1 (order matters)

2>&1 means: point stderr at wherever stdout is pointing right now. So retarget stdout first, then merge.

cmd >out.txt 2>&1      # both in out.txt
cmd 2>&1 >out.txt      # stderr still on terminal — footgun
Left to right. Destination (>file), then duplicate (2>&1). Reverse the tokens and you “merged” onto the terminal before stdout moved to the file.
POSIX-lean. Bash also has &>file. Prefer >file 2>&1 so the same reflex works on bare remote shells.

Knowledge 4 — tee: see and save

tee is the T-junction: copy the pipe to a file without killing the screen. Merge first if you want errors in the capture.

cmd 2>&1 | tee /tmp/capture.txt
cmd 2>&1 | tee -a /tmp/capture.txt   # append

Drill — lose an error, then catch it

All in bash. Use /tmp so nothing important gets clobbered.

  1. See both streams on screen: 
    ls /tmp /no-such-path
    show answer

    You get a directory listing (stdout) and a “No such file” line (stderr). Same terminal, two fds.

  2. Capture stdout only — watch stderr escape: 
    ls /tmp /no-such-path > /tmp/out-only.txt
cat /tmp/out-only.txt
    show answer

    The error still printed on screen. The file has only the listing. This is the classic “redirect didn’t catch the failure” moment.

  3. Capture both (correct order): 
    ls /tmp /no-such-path > /tmp/both.txt 2>&1
cat /tmp/both.txt
    show answer

    Screen is quiet. File has listing and the error. That is the form to memorize for incident logs.

  4. Prove the footgun — wrong order: 
    ls /tmp /no-such-path 2>&1 > /tmp/wrong-order.txt
cat /tmp/wrong-order.txt
    show answer

    Error on screen again; file is listing-only. You merged stderr onto the terminal, then moved stdout to the file. Order is the lesson.

  5. Append, then tee (watch + save): 
    echo '--- next run ---' >> /tmp/both.txt
ls /tmp /no-such-path >> /tmp/both.txt 2>&1
ls /tmp /no-such-path 2>&1 | tee /tmp/tee-capture.txt
cat /tmp/tee-capture.txt
    show answer

    >> … 2>&1 appends both streams. tee prints the same text you saved — useful when you refuse to run a command twice just to keep a log.

Pareto cut. Not today: &>, |&, fancy fd swaps, process substitution. Cheat sheet: shell redirection.

Check your understanding

Four short questions. Answers are shuffled on each page load.

Q1Which fd is stderr?

  • file descriptor 2
  • file descriptor 0
  • file descriptor 1
  • file descriptor 3

Q2Capture both streams to a file?

  • cmd >f 2>&1
  • cmd 2>&1 >f
  • cmd >f 1>&2
  • cmd <f 2>&1

Q3What does >> do to the file?

  • append stdout bytes
  • erase stdout bytes
  • merge stderr bytes
  • pipe stdout bytes

Q4Why use tee mid-capture?

  • see output and save
  • hide output and save
  • sort output and save
  • kill output and save
