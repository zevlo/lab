Lesson 0019 · Missing Semester — CLI

Command-line conventions

Programs talk through argv, three streams, an environment, a small integer, and signals. The shell expands globs and jobs before the program ever starts.

Why this matters

Lecture 2’s first half is the contract every CLI follows — not extra tools. Once you see the contract, ls -la, DEBUG=1 cmd, grep -q &&, and Ctrl-Z are the same idea. The ops loop (find a process, probe it, stop it) lives here because it is that contract used on a live service.

Knowledge 1 — argv, then the shell expands

ls -l folder/ runs /bin/ls with ['-l', 'folder/']. In a script: $0 name, $1…$9 positionals, $@ / "$@" all of them, $# count. Flags are a convention: - short (groupable -la), -- long. -- stops flag parsing — everything after is a positional (touch -- -myfile).

The shell expands * / ? / {a,b} before exec. rm never sees the literal *.py when matches exist. Quotes freeze expansion. ** / globstar is later (zsh-ish).

Knowledge 2 — streams, environment, status

Every process has stdin/stdout/stderr. A pipeline starts all stages at once — streams, not “run then run.” > overwrite, >> append, 2> stderr, >f 2>&1 merge (POSIX). < stdin from a file. Do not use bash &> as the taught form.

Shell-local vs environment: printenv is what children see. VAR=value cmd is one-shot. export VAR=value sticks for later children. unset VAR removes it. Double quotes expand; single quotes do not. TZ=Asia/Tokyo date does not set $TZ in your shell.

Exit status: 0 = success, nonzero = failure. $? is overwritten by the next command — capture with rc=$?. && / || short-circuit on that integer (inverted from C: 0 is “true”). Same rule as if / while. true / false are programs.

Knowledge 3 — signals, jobs, then find/probe/stop

Key / cmdDoes
Ctrl-C / Ctrl-\ / Ctrl-ZSIGINT interrupt / SIGQUIT / SIGTSTP suspend
jobs fg bg & %Nthis shell’s jobs; kill %1 sends TERM
kill PID / kill -9 / kill -0TERM / KILL / “still alive?” (no signal)

pgrep -f PATPIDs matching full argv (portable). Mac list: -lf; Linux list often -af
curl -si URLheaders + body; status is field 2 of the first line (cut -d' ' -f2)

jobs is per-shell. Another pane’s sleep will not show. Kill by PID you confirmed, not a vague pkill on a shared box. wait only waits on this shell’s children; kill -0 + sleep is how you wait on a stranger PID (pidwait).

Exercises

MS CLE set for this half, plus the ops loop. Try before show answer.

1 — -- and a leading dash

touch -- -myfile then remove it without --. Why does -- exist?

show answer

Without --, rm -myfile looks like flags. rm -- -myfile (or rm ./-myfile). -- means “stop parsing options.”

2 — ls flags from the man page

All files including hidden, human sizes, newest first, colorized.

show answer

ls -lah --color=auto (GNU) or on this Mac ls -lahG / ls -lah with CLICOLOR=1. Recency: -t. Read man ls.

3 — printenv vs export

MS: diff <(printenv | sort) <(export | sort). Why differ? (Process substitution <(…) is a named-pipe trick — use it here, then move on.)

show answer

printenv is the environment. export (with no args) lists exported names, often as declare -x / assignment syntax — different format, and shell-only variables never appear in printenv.

4 — marco / polo

Functions: marco saves cwd; polo cds back. source marco.sh.

show answer
marco() { export MARCO_PWD="$PWD"; }
polo() { cd "$MARCO_PWD" || return; }

Must be a function (or builtin) in this shell — a script would cd only in a child.

5 — run until fail

MS’s random-42 script: loop until it fails; capture stdout and stderr; print how many runs.

show answer
n=0
until false; do
  n=$((n+1))
  ./ms-random.sh >out.txt 2>err.txt && continue
  echo "failed on run $n"; cat out.txt err.txt; break
done

Or while ./ms-random.sh >out 2>err; do n=$((n+1)); done then report. Merge streams if you want one file: >both 2>&1.

6 — jobs then pgrep

sleep 10000, Ctrl-Z, bg. Kill it with pgrep/pkill (or kill the PID) without typing the number from memory. Then: sleep 60 & and a function pidwait that polls kill -0.

show answer

pgrep -lf sleep then pkill -f 'sleep 10000' (specific pattern). jobs only sees this shell.

pidwait() { while kill -0 "$1" 2>/dev/null; do sleep 1; done; }
sleep 5 &
pidwait $!

wait cannot see another session’s PID; kill -0 can.

7 — ops loop

python3 -m http.server 8765 --bind 127.0.0.1 >/tmp/ms-cli/http.log 2>&1 &
curl -si http://127.0.0.1:8765/ | head -1
curl -si http://127.0.0.1:8765/ | head -1 | cut -d' ' -f2
pgrep -lf http.server
kill $(pgrep -f 'http.server 8765')
kill -0 $(pgrep -f 'http.server 8765') 2>/dev/null || echo gone

Status field is 2. Confirm TERM stopped it. cut default delimiter is tab — spaces need -d' '.

show answer

First line HTTP/1.0 200 OK; field 2 is 200. Portable find is pgrep -f; Mac display -lf. Default kill is TERM. kill -0 nonzero means the PID is gone.

Cold rebuilds

  1. Who expands *.py?
  2. Merge both streams, POSIX.
  3. One-shot env vs export.
  4. Why 0 means success.
  5. SIGHUP vs tmux; kill -0.
show answer

(a) The shell, before exec.
(b) cmd >f 2>&1.
(c) One-shot is only that command; export is inherited by later children.
(d) Convention — if / && treat 0 as true.
(e) Hangup kills a raw SSH child; tmux keeps the session. kill -0 tests aliveness with no signal.

Check your understanding

Four questions. Shuffled answers.

Q1When you type rm *.py and matches exist, rm receives:

  • The expanded pathnames — the shell globbed first
  • The literal string *.py to interpret itself
  • Nothing; globbing is a kernel feature of execve
  • A single argument after rm converts the glob

Q2In the shell, exit status 0 means:

  • Success — if / && treat it as true (opposite of C)
  • Failure — same as Python’s False
  • The program printed nothing
  • The process was killed by SIGHUP

Q3TZ=Asia/Tokyo date then echo $TZ in the same shell:

  • TZ is still unset here — the assignment was one-shot for date
  • TZ is now Asia/Tokyo until unset
  • date fails unless TZ was exported first
  • printenv TZ is empty but echo $TZ shows Tokyo

Q4A job started in another pane:

  • Will not show in this shell’s jobs — use pgrep / kill -0
  • Always appears in jobs because the kernel shares a job table
  • Can only be stopped with Ctrl-C in this pane
  • Is immune to TERM until you export JOBS=1
