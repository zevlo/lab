Debugging

Code does what you told it to, not what you expected. Pick an observation point: client, DNS, sockets, debugger, syscalls, packets, sanitizer — then paste the artifact, and verify.

Why this matters

Lecture 4’s debugging half is one ladder. Checkers (L0026) can pass while the program is still wrong — a logic bug, or a bug outside the process. Golden rule: inspect the actual value / call / packet. Profiling is L0036.

Knowledge 1 — print, log, debugger

Printf when you know roughly where and re-running is cheap. Logging is printing with care (severity, routing, structure) — convert a successful print into a log before you delete it. Third-party: -v, /var/log/, journalctl -u (Linux). A debugger wins when you do not know what to print, or restart is expensive. Hands-on: pdb. gdb is the same verbs for C — named.

python3 -m pdb script.py
breakpoint()          # inline, 3.7+

Core: b break · c continue · n next · s step · p print · l list · w where · q quit. Loop: reproduce → isolate → inspect → fix → gate with checkers. Cardinal rule: look at the actual value.

Knowledge 3 — memory bugs, then paste the artifact

Overflow / use-after-free / leak: the symptom is far from the act. pdb does not see the heap; strace sees mmap not the write; checkers pass. ASan: recompile gcc -fsanitize=address -g — report is three stacks (access ← freed by ← allocated by); abort. Valgrind Memcheck: no recompile; --leak-check=full; verdicts definitely/indirectly/possibly/still reachable. Decision: can recompile → ASan (CI-fast); cannot → Valgrind; races → TSan (named); heisenbug → rr (named). Intra-object overflow can blind both — that is the corruption.c teaser.

AI-for-debug is distinct from L0026 form factors: you paste a compiler wall, strace, or ASan report, not a paraphrase. Shine: cryptic errors, FFI boundaries, symptom↔cause, crash stacks. Limitations: hallucinate, mask the bug (e.g. “delete the free”). Always re-run the tool. -g / frame pointers are why a native stack is readable.

Exercises

MS debugging set. Try before show answer.

1 — merge-sort in pdb

MS’s merge has a bug (right[i] on the else branch). Implement in Python, breakpoint() in merge, step until the wrong element is selected. Test: [3,1,4,1,5,9,2,6] → sorted.

show answer

Else branch should append right[j] and increment j, not right[i]. p left, right, i, j at the bad comparison. Fix, gate with py_compile.

2 — rr / corruption.c

MS: record-replay the intra-object overflow. Skip the run — no PMU in this VM. Read the program: scores[3] walks onto the next Student.id. Named: rr record / rr replay / reverse-continue. Warpspeed on macOS.

show answer

The loop bound is 4 on a 3-element array. ASan/Valgrind often miss intra-object overflow. rr would watchpoint students[1].id and reverse to the write.

3 — ASan on uaf.c

MS’s program verbatim: malloc, print, free, write through the pointer. Plain build may “work” and exit 0. Then gcc -fsanitize=address -g. What bug? Fix (use after last use, then free). Optional: comment the free, compare LeakSanitizer vs Valgrind on the plain binary.

show answer

heap-use-after-free: write at the line after free. Exit 0 on the plain binary is not proof (UB). Connect the three stacks: allocate, free, then write.

4 — strace ls -l

In the Linux box: strace ls -l, then -e trace=file. What is the first syscall? What files did it open? Try a more complex program (python -c, or a pipeline with -f).

show answer

execve first. File trace shows openat on the directory and loader libs. -f is required when the program spawns (shell pipelines).

5 — paste an artifact

Paste the ASan report (or a C++ template wall, or the strace ENOENT) into an LLM. Apply a fix only after you re-run the tool to status=0 / a clean report. Reject “delete the free.”

show answer

Paste the raw output. A fluent “fix” that removes free masks a leak. Verify with ASan/strace/compile — the LLM is a draft.

6 — dig and who is listening

Local: dig example.com (status line + ANSWER), +short, @1.1.1.1, AAAA / MX. Then: who listens on a port? Linux ss -tlnp; Mac lsof -nP -iTCP -sTCP:LISTEN.

show answer

NOERROR vs NXDOMAIN. Empty +short with NXDOMAIN is an answer. ss is not on this Mac.

Check your understanding

Four questions. Shuffled answers.

Q1Checkers pass, the program is still wrong. That is:

  • A logic bug (or a bug outside the process) — inspect actual values / calls / packets
  • Proof the checkers are broken; skip them
  • Always a memory error; start with ASan first
  • An LLM problem; do not use pdb

Q2strace shows:

  • System calls at the program↔kernel boundary — not Python variable values
  • The same stack pdb would print, with types
  • Packets on the wire, including HTTPS bodies
  • Only file contents, never execve

Q3You cannot recompile a third-party binary. Suspected leak:

  • Valgrind Memcheck — no recompile; ASan needs -fsanitize
  • ASan anyway — it attaches like strace -p
  • tcpdump — leaks always show as RSTs
  • mypy — types catch heap errors

Q4When asking an LLM about a crash, paste:

  • The raw compiler / strace / ASan output — then verify with the same tool
  • A paraphrase of what you think happened
  • Only the source, never the sanitizer report
  • The binary, base64, so it can disassemble

Ask the teacher. Did the ladder replace “which tool”? ASan three-stack readable? rr skip acceptable?
