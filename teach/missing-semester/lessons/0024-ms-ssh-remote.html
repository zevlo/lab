Lesson 0024 · Missing Semester — CLE

SSH / remote machines

Secure Shell for login, one-shot remote commands, keys, scp/rsync, and short Host names in ~/.ssh/config.

Why this matters

Half your work is already over SSH. Missing Semester’s CLE “Remote Machines” section names the operator floor: open a remote shell, run a command without an interactive session, prove who you are with keys (not shared passwords), move files with scp/rsync, and stop typing user@long.host.name -p 2222 every time by putting defaults in ~/.ssh/config. You already survive disconnects with tmux (L0006) and know why a naked SSH drop sends SIGHUP (L0019) — this slice is the SSH client side.

Read first (10–15 min): MS Command-line Environment — the “Remote Machines” section only (connect, remote commands, keys, scp/rsync, ~/.ssh/config). Skip Mosh. Skip the Terminal Multiplexers re-teach (you have L0006–0013). Skip Customizing the Shell for now.

Knowledge 1 — connect and remote commands

Interactive login:

ssh alice@server.example.com

Often overlooked: ssh can run a command and exit. Stdin/stdout cross the tunnel, so you can pipe into local tools — but quoting decides where the pipeline runs:

# ls on remote; wc on your Mac
ssh alice@server ls | wc -l

# both ls and wc on the remote
ssh alice@server 'ls | wc -l'
Local shell sees unquoted |. Without quotes, your Mac parses the pipe. Quote the remote command string when the whole pipeline (or any shell metacharacters) should run on the server. Same idea as bash -c '…' (L0022): the string is for a other shell.

Knowledge 2 — keys instead of passwords

The server must authorize you: password, or better, public-key crypto. You keep a private key; the server stores the matching public key in ~/.ssh/authorized_keys. The private key is effectively a password — never paste or commit it.

FileRole
~/.ssh/id_ed25519Private — secret
~/.ssh/id_ed25519.pubPublic — install on servers
~/.ssh/authorized_keysOn server — allowed pubkeys
 
# generate once (skip if you already have ed25519)
ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519

# print the public key for this private key (validates passphrase too)
ssh-keygen -y -f ~/.ssh/id_ed25519

# install pubkey on a host (if not already key-based)
ssh-copy-id -i ~/.ssh/id_ed25519 alice@server
Do not cat the private key into chat, git, or screenshots. *.pub and ssh-keygen -y output are the shareable side.

Knowledge 3 — files and ~/.ssh/config

scp copies over SSH. rsync is usually better for repeated syncs: it skips identical files and can resume with --partial. Both understand Host aliases from your config.

scp notes.txt alice@server:~/inbox/
scp alice@server:~/inbox/notes.txt ./

rsync -av notes.txt alice@server:~/inbox/
rsync -av --partial big.bin alice@server:~/

Client defaults live in ~/.ssh/config (also used by scp and rsync):

Host vm
    User alice
    HostName 172.16.174.141
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host *.example.com
    User alice

After that, ssh vm is enough. Keep ~/.ssh/config and private keys mode 600.

Long remote work → tmux first. Interactive triage that must survive a laptop sleep or VPN flap belongs in a remote tmux session (detach / reattach). Plain ssh alone is not a session manager — you already practiced that floor.

Drill A — keys & config (local)

Ghostty + bash. Scratch: /tmp/ms-ssh/. Do not print or copy private key material.

  1. Inventory (names only): 
    mkdir -p /tmp/ms-ssh && cd /tmp/ms-ssh
ls -la ~/.ssh
# expect something like: config, id_ed25519, id_ed25519.pub, known_hosts
    show answer

    You should see a private key (no .pub) and matching .pub. Mode on the private file should be restrictive (600 / -rw-------). If you have no ed25519 pair yet, generate with the Knowledge 2 ssh-keygen line, then re-list.

  2. Validate the private key (prints the public form): 
    ssh-keygen -y -f ~/.ssh/id_ed25519 | head -c 40; echo "…"
    show answer

    Starts like ssh-ed25519 AAAA…. If it asks for a passphrase, that is expected. Never redirect the private file itself into a paste buffer.

  3. Draft a Host stanza (scratch only — do not overwrite real config unless you mean to): 
    cat > /tmp/ms-ssh/config.example <<'EOF'
Host practice
    User YOURUSER
    HostName YOUR.HOST.EXAMPLE
    IdentityFile ~/.ssh/id_ed25519
EOF
cat /tmp/ms-ssh/config.example
    show answer

    Four lines: short name practice, then User / HostName / IdentityFile. In real life you would merge a Host block into ~/.ssh/config (or use ssh -F /tmp/ms-ssh/config.example practice after filling real values).

  4. One sentence (say it out loud): what is the difference between id_ed25519 and id_ed25519.pub?
    show answer

    Private key stays on your machine and proves identity; public key is what servers keep in authorized_keys.

Drill B — remote (SSH to a host you use)

Pick a Host alias or user@host you already reach (same pattern as L0010). Replace HOST below. If you have no remote tonight, finish Drill A + quiz, then run Drill B next session.

  1. One-shot remote facts: 
    ssh HOST 'hostname; whoami; pwd'
    show answer

    Three lines: remote hostname, your remote username, remote cwd (usually home for a non-login one-shot — exact home path is fine).

  2. Quoting: local vs remote pipe: 
    ssh HOST ls | wc -l
ssh HOST 'ls | wc -l'
    show answer

    Both print a number. First: remote ls, local wc. Second: both on the remote. Counts can match; the point is where each side runs.

  3. Push a tiny file with scp, then pull a copy back with rsync: 
    echo "ssh-drill $(date +%F)" > /tmp/ms-ssh/hello.txt
scp /tmp/ms-ssh/hello.txt HOST:~/ms-ssh-hello.txt
rsync -av HOST:~/ms-ssh-hello.txt /tmp/ms-ssh/hello-back.txt
cat /tmp/ms-ssh/hello-back.txt
    show answer

    Remote home gets ms-ssh-hello.txt. Local hello-back.txt matches the echo line. Clean up remote with ssh HOST 'rm -f ~/ms-ssh-hello.txt' when done.

  4. Cold rebuilds (no peeking):
    1. Command: run hostname on HOST without an interactive shell.
    2. One-liner shape: count remote home files with wc running on the remote.
    3. One sentence: why put Host / User / HostName in ~/.ssh/config?
    show answer

    (a) ssh HOST hostname or ssh HOST 'hostname'
    (b) ssh HOST 'ls | wc -l' (quoted)
    (c) Short name + defaults (user, real hostname, key, port) for ssh/scp/rsync so you stop retyping them.

Later. Server hardening (PasswordAuthentication, PermitRootLogin); port forwarding (-L/-R/-N/-f); deeper ssh-agent; aliases & dotfiles. Skip MS “consider installing” tools (mosh, fzf, ripgrep, oh-my-*).

Check your understanding

Four questions. Shuffled answers.

Q1What does ssh user@host open?

  • remote shell as that user
  • local root shell only
  • FTP file browser GUI
  • DNS lookup for host

Q2In ssh host ls | wc -l, where does wc run?

  • locally — unquoted pipe
  • only on the remote
  • nowhere — syntax error
  • inside authorized_keys

Q3What must you never share?

  • the private key file
  • the .pub public key
  • HostName in config
  • known_hosts entries

Q4What does a Host block in ~/.ssh/config buy you?

  • short name + ssh defaults
  • root on every server
  • automatic mosh install
  • disables all passwords
