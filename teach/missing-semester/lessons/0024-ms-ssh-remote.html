Lesson 0024 · Missing Semester — remote & home

Remote machines and dotfiles

SSH is a remote shell with quoting rules. Keys replace passwords. Dotfiles are sourced config — aliases die with the process unless a file brings them back.

Why this matters

The other half of lecture 2 is the machine you live on: a remote box you reach with SSH, and the hidden files that make the next shell yours. Long work on a remote belongs in tmux (L0006). This file is connect, keys, copy, config, then persist aliases without editing production configs unless you choose to.

Read first (≈15 min): MS Command-line Environment — Remote Machines and Customizing the Shell (aliases / PATH / bashrc). Skip Mosh, sshd hardening, port-forward challenges, oh-my-*, fancy CLIs, Terminal Emulator shopping (Ghostty stays).

This is CLE’s “where you live” half. Spread sittings. Scratch: /tmp/ms-home/. Never dump private key material into chat, git, or screenshots. Owned ~/.bashrc / ~/.ssh/config — optional apply, like Git’s global alias.

Knowledge 1 — SSH is a shell elsewhere

ssh alice@server.example.com          # interactive
ssh alice@server ls | wc -l           # ls remote, wc local
ssh alice@server 'ls | wc -l'         # both remote

Unquoted | is parsed by this shell. Quote when the pipeline (or any metacharacter) belongs on the server — same idea as bash -c '…'.

FileRole
~/.ssh/id_ed25519private — secret
~/.ssh/id_ed25519.pubpublic — install on servers
~/.ssh/authorized_keyson the server — allowed pubkeys
 
ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519   # skip if you have one
ssh-keygen -y -f ~/.ssh/id_ed25519                  # print pubkey (passphrase check)
ssh-copy-id -i ~/.ssh/id_ed25519 alice@server

scp copies; rsync -av --partial is better for repeats. Both honor ~/.ssh/config:

Host vm
    User alice
    HostName 172.16.174.141
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Then ssh vm. Mode 600 on config and private keys. Interactive triage that must survive a flap: remote tmux first.

Knowledge 2 — a dotfile is a hidden config

Names starting with . are hidden from bare ls (ls -a). Convention: ~/.bashrc, ~/.vimrc, ~/.tmux.conf, ~/.ssh/config, ~/.gitconfig. Interactive bash customizations usually live in ~/.bashrc; login shells often source it from ~/.bash_profile.

Knowledge 3 — aliases and PATH, then persist

export PATH="$PATH:/path/to/append"
alias ll='ls -lh'
alias ll                 # print definition
\ls                      # ignore alias once
unalias ll

No spaces around =. Aliases compose; they cannot insert arguments in the middle of a template (that is a function — later). Typed at the prompt, they die with the shell. Put durable lines in a file and source it. MS’s career pattern: a versioned folder + ln -s install script. You already have real dotfiles — inventory tonight; migrate/publish is optional.

Setup

mkdir -p /tmp/ms-home && cd /tmp/ms-home
ls -la ~/.ssh | awk '{print $NF}'    # names only — not key contents

Exercises

MS remote + aliases/dotfiles, adapted. Try before show answer.

1 — keys, names only

List ~/.ssh. Do you already have id_ed25519 and a config? If generating, use the ssh-keygen line above. Print the public key with ssh-keygen -y or cat …pub. Never cat the private file.

show answer

Expect config, id_ed25519, id_ed25519.pub, known_hosts. ssh-keygen -y reprints the public half and checks the passphrase.

2 — config as a Host alias

In the scratch dir, write a practice ssh config fragment (do not overwrite real config unless you mean to):

cat > /tmp/ms-home/config.example <<'EOF'
Host vm
    User YOURUSER
    HostName YOURHOST
    IdentityFile ~/.ssh/id_ed25519
EOF

What does each keyword do? Optional: the same block in real ~/.ssh/config if you have a host.

show answer

Host is the alias you type. User / HostName / Port / IdentityFile fill in what you would otherwise pass as flags. ssh vm then works.

3 — quoting a remote pipeline

On a host you use (or skip if none tonight): ssh HOST hostname; then ssh HOST ls | wc -l vs ssh HOST 'ls | wc -l'. One sentence: who ran wc?

show answer

Unquoted: wc is local. Quoted: both on the remote. Counts will differ if the remote listing is not what local wc saw.

4 — scp / rsync

Copy a tiny file to the remote (or between two local paths with rsync -av to see the flags). What does -a / -v / --partial buy you?

show answer

-a archive (perms, times, recurse). -v verbose. --partial keeps incomplete files so a retry can continue. scp is fine for one file; rsync for trees and repeats.

5 — alias dc, then persist in a practice file

alias dc='cd'
alias dc
\dc          # should fail — dc is not a real command
cat > /tmp/ms-home/bashrc.practice <<'EOF'
alias ll='ls -lh'
alias dc='cd'
export PATH="$PATH:/tmp/ms-home/bin"
EOF
source /tmp/ms-home/bashrc.practice
type ll
mkdir -p /tmp/ms-home/bin

MS also wants your top commands from history — consider aliases; do not have to add them to real bashrc tonight.

history | awk '{$1="";print substr($0,2)}' | sort | uniq -c | sort -n | tail -n 10
show answer

alias dc prints dc='cd'. After source, ll works in this shell. Real persist = a line in ~/.bashrc (your call). History ranking is L0015 exercise 17’s cousin.

6 — inventory, do not migrate

ls -a ~ | grep '^\.' | head. Name the ones this mission already uses (bashrc, vim, tmux, ghostty, ssh, gitconfig). MS’s “dotfiles repo + install script + publish” is the pattern — skip the full migrate unless you want it later.

You already have those configs. The floor is: hidden name, sourced on shell start, version them if you clone a new machine. Not a GitHub homework tonight.

Check your understanding

Four questions. Shuffled answers.

Q1ssh host ls | wc -l runs wc:

  • On this machine — the local shell saw the unquoted pipe
  • On the remote — ssh always takes the rest of the line
  • Twice, once each side, and diffs the counts
  • Nowhere; ssh refuses pipelines

Q2The file you may share is:

  • id_ed25519.pub — the public key, also printed by ssh-keygen -y
  • id_ed25519 — the private key, so the server can impersonate you
  • known_hosts — it contains your private key in disguise
  • authorized_keys on your laptop — it is the private half

Q3An alias typed at the prompt:

  • Dies with that shell — put it in a sourced file to persist
  • Is written to disk automatically by bash
  • Applies to every user on the machine
  • Survives reboot via /etc/aliases

Q4Long interactive work over SSH should:

  • Run inside remote tmux so a drop is a reattach, not a SIGHUP
  • Use nohup on every command instead of a multiplexer
  • Rely on Ghostty’s local scrollback for the remote pane
  • Disable keys and use passwords so sshd can resume
