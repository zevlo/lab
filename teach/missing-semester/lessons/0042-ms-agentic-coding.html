Agentic Coding

A coding agent is a conversational model with tools. You steer it, confirm what it runs, and gate what it writes.

Why this matters

Lesson 0029 named three form factors: autocomplete, inline chat, and agent. The agent is the one that edits across files and runs commands. That autonomy is the win, and it is also the risk. You already use that form factor in Cursor (this chat). Zed still covers autocomplete and inline chat. vim stays the place you review the diff.

Missing Semester’s picture: you are the manager of an intern. The intern does the nitty-gritty. You give a spec, you interrupt a wrong turn, and you check the work. The intern samples text. You still own the mental model of the machine.

Knowledge 1: The agent loop

An LLM models the probability of a completion given a prompt, then samples from that distribution. It has a fixed context window: the maximum length of input plus output. Chat apps send the whole conversation, with turn markers, as the next prompt.

A coding agent adds tools: read and write files, search the web, run shell commands. The harness is the program around the model. When the model emits a tool request, the harness runs that tool (after you confirm) and pastes the result back into the prompt. Inference runs again. The interesting part of an agent is that loop. The core of it fits in a couple of hundred lines of code.

Those tools can change your disk and run programs. By default, the harness asks you to confirm each call. If the agent picks python -m mypy and you have a mypy binary on PATH, reply in text: “run mypy directly.” Multi-turn chat is how you steer. Interrupt when the track is wrong.

Most setups send a lot of your data to the cloud. Sometimes only inference is remote. Sometimes the provider also sees the repository and the chat. Open models you run locally exist. Bleeding-edge local inference is still a hardware problem for most machines. Treat the default as: the vendor can read this workspace.

The high-leverage trick is a feedback loop. Give the agent a command it can run, and let it read the output. “Fix mypy” works when the agent can invoke mypy, see the errors, edit, and run it again until the status is 0 (lesson 0023). If it cannot run the check, paste the artifact (lesson 0035) and stay in the loop yourself.

Spec writing is an art. Enough detail that the intern heads the right way. Enough room that you are still delegating. Models change; keep a feel for what they can do this month.

The lecture demo is the Markdown-link extractor from lesson 0029, plus a download helper. The prompt they use:

Turn this into a proper command-line program, with argparse
for argument parsing. Add type annotations, and make sure
the program passes type checking.

Then: run the script, and ask for a change (only absolute URLs). That is one sitting of implement → run → iterate.

Knowledge 3: Context, skills, and review

The context window is scarce. Extra tokens slow the model down even before you overflow it. Start a new conversation for an unrelated task. Some harnesses let you rewind a bad turn, which clears it more cleanly than arguing with the next message. Compaction summarizes the prefix when the history gets long. You lose detail; that is the trade.

/llms.txt is a dense doc meant for models at inference time. When a library is newer than the model’s training cutoff, point the agent at that file. It carries more per token than an HTML page. Example: cursor.com/llms.txt.

Three ways to give standing advice:

ThingWhen it loadsUse it for
AGENTS.mdevery session, in fullshort project rules: how to test, “run py_compile after Python edits”
Skillwhen the agent opens itoptional depth that would bloat AGENTS.md
Subagentits own contexta long tool dump (web research, a checker run) that the parent chat should not swallow

Claude Code looks for CLAUDE.md. Cursor reads AGENTS.md and skills (SKILL.md). A subagent in Cursor is a separate agent run with its own context. Keep AGENTS.md short. Put rare procedures in a skill. Put noisy work in a subagent.

MCP (Model Context Protocol) plugs extra tools into the harness: a Notion server, a browser, an issue tracker. Parallel agents can work on the same task (sample twice, keep the better diff) or on disjoint tasks. Isolate their trees with git worktree (named in lesson 0040; hands-on stays later).

The model is next-token prediction. Review the diff for correctness and security. If verifying would take longer than writing the critical path, write that path yourself. If the agent is circling or talking you into a bad fix, stop and clear context. The vim grammar and the shell still matter on a box where the agent is down.

Auto-run / yolo. Some agents have a mode that skips confirmation (Claude Code: --dangerously-skip-permissions). Use that only inside an isolated VM or container with no host secrets and no mount of $HOME. Default on this machine: confirm each call.

1. Four form factors, one task

Missing Semester: do the same small feature four times: by hand, with autocomplete, with inline chat, and with an agent. Seed file:

cd /tmp/ms-agent
cat > extract.py <<'EOF'
from urllib.request import urlopen

def download_contents(url: str) -> str:
    with urlopen(url) as response:
        return response.read().decode("utf-8")

def extract(content: str) -> list[str]:
    import re
    pattern = r"\[.*?\]\((.*?)\)"
    return re.findall(pattern, content)

print(extract(download_contents(
    "https://raw.githubusercontent.com/missing-semester/"
    "missing-semester/refs/heads/master/_2026/development-environment.md"
)))
EOF
python3 -m py_compile extract.py; echo "status=$?"

The feature: turn extract.py into a CLI with argparse (URL argument, optional --limit N), move import re to module level, and keep type annotations. Restore the seed from the heredoc before each attempt so the four runs start equal.

  1. Hand: vim only.
  2. Autocomplete: Zed or Cursor Tab. You still type the structure.
  3. Inline chat: select the file or a block, prompt in the editor.
  4. Agent: paste Missing Semester’s prompt (Knowledge 2), then ask it to add --limit and to run the script.

After each attempt: python3 -m py_compile extract.py, then run it. One sentence per attempt: what was fast, and what you still had to catch.

show answer

Hand is slow and precise. Autocomplete fills beyond the cursor; rearranging import re still takes a delete and retype. Inline chat proposes a diff you accept. The agent reads, edits, and can run the checker. Expect a working argparse CLI; --limit slices the list. py_compile status 0 means the file parses. Confirm the flag by running the program. Read the help text and try a URL you control if GitHub is slow. The point is the comparison.

A few dozen lines around http.server is enough. Status 0 means the files parse. Curl proves it listens. vim is where you look for a bind to 0.0.0.0 you did not ask for, a secret, or extra files. Tear down with Ctrl-C. Treat the result as a draft you accepted.

4. AGENTS.md, a skill, and a subagent

Missing Semester: create and test an AGENTS.md, a skill, and a subagent for your agent. In Cursor those are AGENTS.md, a SKILL.md, and a subagent (a separate agent run). Write them under scratch so this course repo stays clean. AGENTS.md loads automatically only if that folder is the workspace. Here, paste it into the prompt or open /tmp/ms-agent as a workspace.

cd /tmp/ms-agent
mkdir -p .cursor/skills/ms-py-check
cat > AGENTS.md <<'EOF'
After any Python edit, run:
  python3 -m py_compile FILE
Treat a nonzero exit as a failed edit: fix and re-run.
Use the project venv if one exists. Install packages only there.
EOF
cat > .cursor/skills/ms-py-check/SKILL.md <<'EOF'
---
name: ms-py-check
description: Type-check and syntax-check Python files with py_compile and mypy when available. Use when Python files changed or the user asks to gate AI edits.
---

# Python check

Run `python3 -m py_compile` on each changed `.py` file.
If `python3 -m mypy` imports, run it too.
Print `status=$?`. Nonzero means keep editing.
EOF
cat > subagent-check.txt <<'EOF'
You are a Python checking subagent.
Look at `.py` files in this directory.
Run python3 -m py_compile on them.
If mypy is importable, run python3 -m mypy too.
Return only the commands, their output, and status=N.
EOF

Test: ask this agent (or a new chat pointed at /tmp/ms-agent) to follow AGENTS.md, then “open the ms-py-check skill,” then “use a subagent and the prompt in subagent-check.txt.” One sentence: when you would pick each of the three.

show answer

AGENTS.md: short rules you want in every session. Skill: extra procedure, loaded when relevant, so the always-on file stays small. Subagent: a checker or research dump whose raw output would crowd the parent chat. If Cursor does not auto-load the scratch skill, pasting the skill body once still tests the idea. Claude Code / Codex are the same three knobs with different filenames.

5. Convert bullets with sed

Missing Semester: same goal as the Code Quality lecture’s Markdown-bullet exercise, done by an agent. Convert - list markers to *. Dates, flags, and ranges keep their hyphens. First, let the agent try. Then require a lecture-1 tool.

cd /tmp/ms-agent
cat > notes.md <<'EOF'
# Shipping notes
Date: 2026-01-21
- Pack the artifact
- Name the environment
See also: pre-commit and CI (later).
Run: python3 extract.py --limit 3
Cost: 5-10 minutes
EOF

Prompt A: “In /tmp/ms-agent/notes.md, change Markdown dash bullets to asterisks.” Notice whether it edited the file directly, and whether 2026-01-21 / --limit / 5-10 survived. Restore the file from the heredoc. Prompt B: “Use sed on Markdown bullet lines only. Leave editor tools unused.”

show answer

A direct edit is fast and easy to overshoot (rewriting the whole file, touching hyphens that are not bullets). sed makes the rule visible and repeatable:

sed -E 's/^([[:space:]]*)- /\1* /' notes.md
# then, if the preview is right:
sed -i '' -E 's/^([[:space:]]*)- /\1* /' notes.md   # macOS BSD sed

Bullets become asterisks. The date, --limit, pre-commit, and 5-10 stay. Downside of a silent file rewrite: you cannot grep the transcript for the rule, and a wrong pattern is harder to notice. Lesson 0017: macOS needs sed -i ''; Linux remotes use sed -i.

Check your understanding

Four questions. Answers shuffle on each page load.

Q1A coding agent is:

  • A conversational LLM plus tools that read/write files, search the web, and run a shell
  • A language server that completes symbols from a local index of your repo
  • An autocomplete model that only inserts text beyond the cursor position
  • A container image that ships your app together with its Python version

Q2Agent harnesses confirm tool calls by default because:

  • File and shell tools can change your machine; you review before they run
  • The context window overflows unless you click once on every turn
  • MCP servers require a human in the loop on every HTTP request
  • Compaction only works after you approve the summary of the chat

Q3AGENTS.md versus a skill:

  • AGENTS.md loads in full every session; a skill loads when the agent opens it
  • Skills always load; AGENTS.md loads only if you mention its filename
  • Both are lockfiles that pin the model version for CI and production
  • AGENTS.md replaces git hooks; skills replace Dockerfiles in Compose

Q4The highest-leverage setup for “fix the mypy errors” is:

  • Let the agent run mypy, read the output, edit, and re-run until status 0
  • Paste a paraphrase of the errors and ask the model to guess the patch
  • Disable the type checker so the agent can finish the edit faster
  • Ask autocomplete to invent annotations without opening the file
