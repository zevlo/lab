Aliases & dotfiles

Make the shell feel like home: hidden config files, export PATH=… in startup, and short alias names that stick across sessions.

Why this matters

You already live in bash, vim, tmux, and ~/.ssh/config (L0024). Missing Semester’s CLE “Customizing the Shell” section ties those together: programs read plain-text dotfiles on startup, and the shell itself can grow aliases — short names that expand before a command runs. That is how ll, a safer default flag, or an extra directory on PATH become permanent without installing a new framework.

Read first (10–15 min): MS Command-line Environment — “Customizing the Shell” through aliases (alias / \ / unalias, PATH append, bashrc). Skip package-manager install ads for ripgrep/fd/tldr, oh-my-* frameworks, and the AI / Terminal Emulator sections (you already chose Ghostty).

Knowledge 1 — dotfiles

A dotfile is a config whose name starts with ., so bare ls hides it (ls -a shows it). Convention, not magic — same idea as ~/.ssh/config.

ToolTypical path
bash~/.bashrc, ~/.bash_profile
vim~/.vimrc
tmux~/.tmux.conf
ssh~/.ssh/config
git~/.gitconfig

For bash, interactive customizations usually live in ~/.bashrc. Login shells often read ~/.bash_profile, which commonly sources ~/.bashrc (your Mac setup already does that shape). Full login vs interactive vs non-interactive rules are in man bash INVOCATION — learn the matrix when a remote host “ignores” an alias; for now, prefer putting aliases and PATH tweaks in ~/.bashrc.

ls vs ls -a. Dotfiles are not missing — they are hidden by the listing convention. ls -a ~ | head is the quick check.

Knowledge 2 — PATH and aliases

Installers often ask you to append a directory so children can find new programs (same export idea as L0022):

export PATH="$PATH:/path/to/append"

When you only need a shorter name or fixed flags, use an alias. The shell expands it before running the command. No spaces around =:

alias ll='ls -lh'
alias gs='git status'
alias la='ls -A'
alias lla='la -l'     # aliases can compose

alias ll              # print: ll='ls -lh'
\ls                   # run real ls once, ignore alias
unalias ll            # remove the alias
alias ll = 'ls -lh' fails. alias is a builtin that takes one argument of the form name=value. Spaces around = break it — same family as host = db (L0018 / L0022).

Aliases cannot insert arguments in the middle of a longer command template. For that, use a shell function (later).

Knowledge 3 — make it survive a new shell

An alias typed at the prompt dies when the shell exits. Put durable lines in ~/.bashrc (or a file it sources), then open a new shell or:

source ~/.bashrc

MS advice for a long career of configs: keep dotfiles in a version-controlled folder and symlink them into place with a small install script — so a new machine is one clone + one run. You do not need to migrate everything tonight; knowing the pattern is the floor.

Defaults-only still holds. Prefer short aliases for commands you already use (ll, gs). Skip oh-my-*, starship, and MS “consider installing” replacements (rg, fd, fzf) while the mission says so. Overwriting core tools (alias mv='mv -i') is optional and personal — know that it changes muscle memory on every host.

Drill — prove aliases, then persist in a file

Ghostty + bash. Scratch: /tmp/ms-dot/. Drill uses a practice file you source — do not require editing real ~/.bashrc until you choose to.

  1. Scratch + see hidden names at home: 
    mkdir -p /tmp/ms-dot && cd /tmp/ms-dot
ls -a ~ | grep '^\.' | head -n 20
    show answer

    You should recognize entries like .bashrc, .bash_profile, .ssh, maybe .vimrc / .tmux.conf. Exact list varies.

  2. Session-only alias, inspect, bypass, remove: 
    alias ll='ls -lh'
alias ll
ll /tmp/ms-dot
\ls /tmp/ms-dot
unalias ll
alias ll || true
    show answer

    alias ll prints the definition. ll lists with sizes; \ls is plain. After unalias, alias ll finds nothing (or errors) — || true keeps a set -e shell calm.

  3. Persist via a sourced file (practice stand-in for ~/.bashrc): 
    cat > /tmp/ms-dot/bashrc.practice <<'EOF'
# practice fragment — not your real bashrc
alias ll='ls -lh'
alias gs='git status'
export PATH="$PATH:/tmp/ms-dot/bin"
EOF
mkdir -p /tmp/ms-dot/bin
source /tmp/ms-dot/bashrc.practice
alias ll
alias gs
echo "$PATH" | tr ':' '\n' | grep '/tmp/ms-dot/bin'
    show answer

    Both aliases print. One PATH line ends with /tmp/ms-dot/bin. A brand-new shell will not have these until it sources the same lines from a real startup file.

  4. Compose + optional real-file peek: 
    alias la='ls -A'
alias lla='la -l'
lla /tmp/ms-dot
# optional: grep -n alias ~/.bashrc | head
    show answer

    lla expands through la into a long almost-all listing. The optional grep shows whether you already keep aliases at home.

  5. Cold rebuilds (no peeking):
    1. Define ll as ls -lh, then print its definition with alias.
    2. Write two alias lines into a file and source that file.
    3. One sentence: what is a dotfile?
    show answer

    (a) alias ll='ls -lh' then alias ll
    (b) e.g. cat > /tmp/ms-dot/x <<'EOF' … aliases … EOF then source /tmp/ms-dot/x
    (c) A plain-text config file whose name starts with . (hidden from bare ls), read by a program on startup.

Check your understanding

Four questions. Shuffled answers.

Q1Why are they called dotfiles?

  • names start with a dot
  • they only store DNS data
  • bash requires binary format
  • they replace the kernel

Q2Where do durable bash aliases usually live?

  • ~/.bashrc (then source)
  • /etc/hosts only
  • inside id_ed25519
  • the vim undo file

Q3What does \ls do if ls is aliased?

  • run real ls once
  • delete the alias forever
  • open man ls in vim
  • append ls to PATH

Q4Why does alias ll = 'ls -lh' fail?

  • spaces around the =
  • ll is a reserved PID
  • aliases need sudo
  • ls cannot take flags
