Lesson 0018 · Missing Semester — shell

Light bash scripting

Variables, if/for, shebang, and set -euo pipefail — the rest of MS lecture 1’s shell language.

Why this matters

One-liners get you far; a tiny .sh file gets you further — check a path, loop hosts, fail loudly when something is wrong. Missing Semester treats bash as a programming language: variables, conditionals, loops, then a script with a shebang and strict set flags.

Read first (10–15 min): MS Introduction to the Shell — “The shell language (bash)” from conditionals through the shebang / set -euo pipefail paragraphs. Skim the long flaky-test example for structure; you will not rebuild stress/cargo today.

Knowledge 1 — variables

Assign with name=value (no spaces around =). Expand with $name. Quote expansions that might be empty or contain spaces.

host=db01
echo "$host"
msg="hello world"
echo "$msg"
Spaces break assignment. host = db01 runs a command named host with arguments = and db01. Always host=db01.

Knowledge 2 — if and test

Exit status drives control flow: success (0) → then-branch. Common checks use test, usually written [ … ].

if [ -f /tmp/notes.txt ]; then
  echo "exists"
else
  echo "missing"
fi

name=ops
if [ "$name" = "ops" ]; then
  echo "match"
fi
CheckMeaning
[ -f path ]path is a regular file
[ -d path ]path is a directory
[ "$a" = "$b" ]strings equal (quote both)
Spaces inside [ ]. [ -f file ] needs a space after [ and before ]. Bash also has [[ ]] (safer built-in); stick to [ ] for this lesson — it matches the MS exercises.

Knowledge 3 — for and $()

for walks a word list. Command substitution $(…) inserts a command’s stdout into that list (prefer $() over backticks).

for h in web db cache; do
  echo "host=$h"
done

for i in $(seq 1 3); do
  echo "n=$i"
done

while cmd; do …; done repeats while cmd succeeds (exit 0). Same idea as if, but looping.

Knowledge 4 — script file, shebang, strict set

Put durable logic in a file. First line is the shebang: the kernel runs that interpreter on the file. Second line turns on common safety:

#!/bin/bash
set -euo pipefail
FlagDoes
-eexit if a command fails
-uexit on undefined variable
-o pipefaila failed pipe stage fails the script

Make it executable, then run by path. $1 is the first argument.

chmod +x check.sh
./check.sh /tmp/notes.txt
./ and execute bit. bash check.sh works without +x. ./check.sh needs the execute bit (chmod +x) so the kernel honors the shebang.

Drill — prompt first, then a real script

Ghostty + bash. Work under /tmp/ms-script.

  1. Scratch dir + sample file: 
    rm -rf /tmp/ms-script
mkdir -p /tmp/ms-script
cat > /tmp/ms-script/notes.txt <<'EOF'
status=draft
owner=ops
EOF
cd /tmp/ms-script
pwd
    show answer

    cwd is /tmp/ms-script. ls shows notes.txt.

  2. Variables at the prompt: 
    role=ops
echo "$role"
bad = oops
    show answer

    First two lines print ops. Third should error (command not found / unexpected) — that is the spaces-around-= footgun.

  3. if / [ -f ] at the prompt: 
    if [ -f notes.txt ]; then echo yes; else echo no; fi
if [ -f missing.txt ]; then echo yes; else echo no; fi
    show answer

    yes then no.

  4. for + $(): 
    for x in a b c; do echo "x=$x"; done
for i in $(seq 1 3); do echo "i=$i"; done
    show answer

    Three x=… lines, then i=1 … i=3.

  5. Dated backup via command substitution (MS-shaped): 
    cp notes.txt "notes_$(date +%Y-%m-%d).txt"
ls
    show answer

    You should see notes.txt and something like notes_2026-08-03.txt (today’s date).

  6. Write check.sh (MS exercise shape — shebang, strict set, $1, [ -f ]): 
    cat > check.sh <<'EOF'
#!/bin/bash
set -euo pipefail

if [ -f "$1" ]; then
  echo "file exists: $1"
else
  echo "file missing: $1"
fi
EOF
chmod +x check.sh
./check.sh notes.txt
./check.sh no-such.txt
ls -l check.sh
    show answer

    First run: file exists: notes.txt. Second: file missing: no-such.txt. ls -l should show an x in the permission bits (e.g. -rwxr-xr-x).

  7. Feel -u (undefined variable): 
    bash -c 'set -u; echo "$unset_var"'
    show answer

    Bash errors unbound variable / unbound parameter — that is -u doing its job. Without -u, you often get a silent empty string.

  8. Cold rebuilds (no peeking) — from /tmp/ms-script:
    1. One-liner: if notes.txt exists, print ok, else missing.
    2. Loop web db cache and print each.
    3. From memory: first two lines of every new script; how do you run ./check.sh?
    show answer

    (a) if [ -f notes.txt ]; then echo ok; else echo missing; fi
    (b) for h in web db cache; do echo "$h"; done
    (c) #!/bin/bash then set -euo pipefail; need chmod +x check.sh (once) then ./check.sh ….

Check your understanding

Four questions. Shuffled answers.

Q1Why does host = db fail?

  • spaces → runs cmd host
  • bash forbids host names
  • need export always
  • must use double quotes

Q2What does set -u do?

  • fail on unset vars
  • unlock the terminal
  • unbuffer all pipes
  • undo last assignment

Q3What is $1 in a script?

  • first script argument
  • first awk field only
  • exit status of last
  • path to bash itself

Q4Why chmod +x before ./s.sh?

  • kernel needs exec bit
  • shebang becomes optional
  • turns on set -euo
  • adds PATH entry

Ask the teacher. After the drill: did the spaces-around-= footgun bite? Did ./check.sh fail before chmod? Did -u click?
