Substitute & the dot formula

Two workflows for changing many things at once: the :s family for bulk, cgn + . for surgical. Both are devops bread and butter.

Why this matters

Renaming a label across a Kubernetes manifest. Updating an image tag in every Deployment. Changing a log-level string everywhere it appears. These come up every shift. Two tools cover ~95% of the cases:

  • The :s family — for when you want everything changed (optionally with per-match confirmation).
  • The cgn + . workflow — for surgical, case-by-case find-and-replace that's faster to apply and easier to undo.

Knowledge 1 — the :s family

:s/old/new/First match on current line only
:s/old/new/gAll matches on current line
:%s/old/new/gAll matches in whole file
:%s/old/new/gcAll matches, with per-match confirmation

The % before s means "every line in the file". The trailing g means "all matches per line, not just the first". The trailing c means "confirm each".

The pattern is regex — same metachar gotcha as Lesson 0002: . matches any char, * is a quantifier, etc. To match literally, escape: :%s/db\.internal/db-blue.internal/g.

Knowledge 2 — word boundaries: the precision tool

Without anchors, :%s/api/edge/g would change api, api-server, apiV2, and edge-api all at once. Often that's wrong.

Use \< and \> to anchor to word boundaries:

\<api\>Matches api as a whole word only
\<apiWord starting with api
api\>Word ending with api
Real-world gotcha. If your file already contains production and you run :%s/prod/production/g, vim will replace the prod substring inside production too — leaving productionuction. Always use :%s/\<prod\>/production/g when the pattern is a substring risk.

Knowledge 3 — the confirmation prompt

With gc, vim pauses at each match and asks. The keys you'll use:

yYes — replace this one, continue
nNo — skip this one, continue
aAll — replace all remaining without asking
qQuit — stop here
lLast — replace this one, then stop

Knowledge 4 — the dot formula: . + cgn

The dot (.) in normal mode repeats the last change — anything that modified the buffer. gn is a motion that targets the next search match. Combined:

  1. /old<Enter> — search for the thing
  2. cgn — change the go-to-next-search-match (recall Lesson 0001: operator + motion)
  3. type the replacement, Esc
  4. . — repeat at the next match
  5. n — skip the next match if you don't want to change it

This is Drew Neil's dot formula — "one keystroke to move, one to execute, repeat with .." It's faster than gc for medium-length lists, and each u undoes one change rather than the whole batch.

Dot repeat is general

. isn't tied to cgn. It repeats the last change as a unit, including any motion that was part of it:

  • x, then j. — delete a char down a column
  • dw, then j.j. — delete first word across three lines
  • >iw, then j. — indent a word, repeat down

Drill (~8 min)

Create the file from bash (autoindent-safe, per Lesson 0002):

cat > /tmp/manifest.yaml <<'EOF'

Tasks

  1. Rename every env: prod value to env: production. First try :%s/prod/production/g and observe what happens to namespace: production. Then u to undo, and redo it correctly.
    show what happens and the fix

    :%s/prod/production/g will turn namespace: production into namespace: productionuction — because prod is a substring of production.

    Undo with u. Then use word boundaries: :%s/\<prod\>/production/g. This anchors prod as a whole word, leaving production alone.

  2. Update both image tags from :v2.4.1 to :v2.4.2. The lesson said "use cgn" — but first ask: is this really a cgn-shaped problem? (Hint: it isn't. There are better tools.)
    show the four options (yes, cgn is overkill here)

    Option A — :%s (the right tool here): :%s/v2.4.1/v2.4.2/g<Enter>. One command, both matches, done. The unescaped . in the search pattern still matches the literal dot — it's more permissive than needed, but in this file there are no false positives.

    Option B — very-no-magic \V (for cgn fans): /\Vv2.4.1<Enter> then cgn v2.4.2 Esc .. \V disables regex special chars, so dots are literal — no escaping needed. Reach for this when a pattern is regex-heavy (URLs, IPs, file paths).

    Option C — single-char r + . (for this exact case): the only difference is the last digit. /v2.4.1<Enter> (no escape needed), $ to land on the trailing 1, r2 to replace the char, then n. to repeat at the next match. About 12 keystrokes.

    Option D — the canonical cgn workflow (what the lesson originally asked): /v2\.4\.1<Enter> cgn v2.4.2 Esc .. About 20 keystrokes; tedious because the dots need escaping.

    General principle: :%s for bulk (all matches), cgn for surgical (some in, some out), r+. for single-char diffs. Match the tool to the task.

  3. Change LOG_LEVEL value info to debug — but only sometimes. Use :%s/info/debug/gc and practice the prompt keys (y, n, a, q).
    show what to try

    At each match, try y for yes, n for no, then u to undo and try again with a (all). Then u and try q to abort. Get the prompt's reflexes into your fingers.

  4. Add the suffix -blue to prod-db.internal. Use search to get there (from Lesson 0002) and then a single change.
    show answer

    /prod-db.internal<Enter> — wait, we just renamed prod in Task 1! So now it's production-db.internal. Adjust your search accordingly: /production-db.internal<Enter>. Then f., i, -blue, Esc. (Or ci" if you prefer.)

    This task demonstrates a real-world lesson: substitutions change downstream searches. Always re-verify after a bulk rename.

  5. Bonus — general dot repeat: cursor on the first tier: backend line. Delete the word backend with dw. Move down with j. Press . to repeat the deletion on the next line if it also says backend. u to undo.
    show what to expect

    Only the first Deployment has tier: backend in two places (top-level labels and template labels). The second Deployment has tier: worker at top-level but no tier under template. So dw + j + . + n navigation lets you sweep through. u walks back.

Task 4 captures a real devops lesson: a substitution changes the text downstream searches operate on. The classic version is "I renamed the host, now my SSH alias doesn't resolve." Always re-verify after bulk renames.
