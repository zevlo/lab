Drill — foundations

  1. What does the -l flag to ls do? Run ls -l / and examine the output. What do the first 10 characters of each line mean? (Hint: man ls)
    show answer

    -l is long listing: type, permissions, links, owner, group, size, mtime, name. The first character is file type (- regular, d directory, l symlink, …). The next nine are rwx for user, group, other (a - means that bit is off). Together that is 10 characters before the link count.

  2. In find ~/Downloads -type f -name "*.zip" -mtime +30, the *.zip is a “glob”. What is a glob? Create a test directory with some files and experiment with ls *.txt, ls file?.txt, and ls {a,b,c}.txt. See Pattern Matching in the Bash manual. 
    mkdir -p /tmp/ms-ex/glob && cd /tmp/ms-ex/glob
touch a.txt b.txt c.txt file1.txt file2.txt file10.txt notes.md
ls *.txt
ls file?.txt
ls {a,b,c}.txt
    show answer

    A glob is a shell pattern the shell expands into matching pathnames before running the command (* any string, ? one character, {a,b} brace expansion). Quote "*.zip" for find -name so the shell does not expand it early — find matches the pattern itself. file?.txt matches file1.txt / file2.txt but not file10.txt.

  3. What’s the difference between 'single quotes', "double quotes", and $'ANSI quotes'? Write a command that echoes a string containing a literal $, a !, and a newline. See Quoting in the Bash manual.
    show answer

    Single quotes: literal everything (no $ expansion). Double quotes: expand $var, $(…), backticks, \ escapes. ANSI $'…': C-style escapes like \n, \t. One approach:

    echo $'literal $ and !\nand a newline'

    Or: printf '%s\n' 'literal $ and !' (single-quoted $/!; printf supplies the newline).

  4. The shell has three standard streams: stdin (0), stdout (1), and stderr (2). Run ls /nonexistent /tmp and redirect stdout to one file and stderr to another. How would you redirect both to the same file? See Redirections.
    show answer

    ls /nonexistent /tmp >/tmp/ms-ex/out.txt 2>/tmp/ms-ex/err.txt

    Both to one file (POSIX merge order): ls /nonexistent /tmp >/tmp/ms-ex/both.txt 2>&1 — not 2>&1 >file.

  5. $? holds the exit status of the last command (0 = success). && runs the next command only if the previous succeeded; || runs it only if the previous failed. Write a one-liner that creates /tmp/mydir only if it doesn’t already exist. See Exit Status.
    show answer

    mkdir /tmp/mydir 2>/dev/null || true is weak. Cleaner: [ -d /tmp/mydir ] || mkdir /tmp/mydir or mkdir -p /tmp/mydir (-p is a no-op if it exists). Another: test ! -d /tmp/mydir && mkdir /tmp/mydir.

  6. Why does cd have to be built into the shell itself rather than a standalone program? (Hint: think about what a child process can and cannot affect in its parent.)
    show answer

    A standalone cd would run in a child process. Changing cwd in the child cannot change the parent shell’s cwd — when the child exits, you would still be where you started. Builtins run inside the shell process, so they can change its state.

Drill — scripts

  1. Write a script that takes a filename as an argument ($1) and checks whether the file exists using test -f or [ -f … ]. Print different messages depending on whether the file exists. See Bash Conditional Expressions. 
    cd /tmp/ms-ex
touch notes.txt
    show answer
    cat > check.sh <<'EOF'
#!/bin/bash
set -euo pipefail
if [ -f "$1" ]; then
  echo "exists: $1"
else
  echo "missing: $1"
fi
EOF

    Test with bash check.sh notes.txt and bash check.sh no-such.txt.

  2. Save the script from the previous exercise (e.g. check.sh). Try ./check.sh somefile. What happens? Now run chmod +x check.sh and try again. Why is this step necessary? (Hint: look at ls -l check.sh before and after.)
    show answer

    Without execute permission, ./check.sh fails with “Permission denied” (kernel will not run it via the shebang). bash check.sh still works because you are feeding the file to bash. chmod +x sets the x bit; ls -l shows -rwxr-xr-x (or similar) afterward.

  3. What happens if you add -x to the set flags in a script? Try it with a simple script and observe the output. See The Set Builtin.
    show answer

    set -x (or set -euxo pipefail) prints each command and its expanded arguments to stderr before running it — a trace for debugging. Example: put set -x under the shebang in check.sh and run ./check.sh notes.txt; you will see lines like + [ -f notes.txt ].

  4. Write a command that copies a file to a backup with today’s date in the filename (e.g. notes.txt → notes_2026-01-12.txt). Hint: $(date +%Y-%m-%d). See Command Substitution.
    show answer

    cp notes.txt "notes_$(date +%Y-%m-%d).txt"

  5. Modify the flaky-test script from the lecture to accept the test command as an argument instead of hardcoding cargo test my_test. Hint: $1 or $@. See Special Parameters. (You do not need stress or Rust installed — use a tiny stand-in command.)
    show answer

    Replace the hardcoded test with "$@" (or $1 if a single word). Sketch:

    #!/bin/bash
set -euo pipefail
LOGFILE="test_runs_$(date +%s).log"
RUN=1
while "$@" > "$LOGFILE" 2>&1; do
  echo "Run $RUN passed"
  ((RUN++)) || true
done
echo "Failed on run $RUN"
tail -n 20 "$LOGFILE"

    Try: ./flaky.sh true (loops forever — Ctrl-C), or a script that fails on the third run. $@ preserves separate arguments; $* does not.

Drill — pipelines & tools

  1. Use pipes to find the 5 most common file extensions in your home directory. Hint: combine find, grep / sed / awk, sort, uniq -c, and head.
    show answer

    One approach (may take a while; add -maxdepth 3 to bound it):

    find ~ -type f 2>/dev/null \
  | sed 's/.*\.//' \
  | sort | uniq -c | sort -nr | head -5

    Or extract with awk -F. '{print $NF}'. Files with no dot become the whole basename — filter with grep '\.' first if you want only dotted names.

  2. xargs converts lines from stdin into command arguments. Use find and xargs together (not find -exec) to find all .sh files in a directory and count the lines in each with wc -l. Bonus: handle filenames with spaces (-print0 / -0). See man xargs. 
    mkdir -p /tmp/ms-ex/scripts
printf 'echo hi\n' > /tmp/ms-ex/scripts/a.sh
printf 'echo bye\n# comment\n' > "/tmp/ms-ex/scripts/my script.sh"
    show answer

    Basic: find /tmp/ms-ex/scripts -name '*.sh' | xargs wc -l

    Spaces-safe: find /tmp/ms-ex/scripts -name '*.sh' -print0 | xargs -0 wc -l

  3. Use curl to fetch the HTML of the course website (https://missing.csail.mit.edu/) and pipe it to grep to count how many lectures are listed. Hint: look for a pattern that appears once per lecture; use curl -s to silence progress.
    show answer

    Inspect once: curl -s https://missing.csail.mit.edu/ | less. A common pattern is lecture links under the schedule. Count lines matching that pattern, e.g.:

    curl -s https://missing.csail.mit.edu/ | grep -c 'href="/2026/'

    (Exact pattern may shift year-to-year — choose something that appears once per lecture row, then grep -c.)

  4. jq is a powerful tool for processing JSON. Fetch https://microsoftedge.github.io/Demos/json-dummy-data/64KB.json with curl and use jq to extract just the names of people whose version is greater than 6. Hint: pipe to jq . first; then jq '.[] | select(...) | .name'.
    Exception. This workbook includes the MS jq exercise even though fancy CLIs are normally out of scope. Install if needed: brew install jq.
    show answer

    curl -s https://microsoftedge.github.io/Demos/json-dummy-data/64KB.json | jq '.[] | select(.version > 6) | .name'

    Confirm field names with | jq '.[0]' first if the shape surprises you.

  5. Write an awk command that prints only lines where the second column is greater than 100, and swaps the first and third columns. Test with: 
    printf 'a 50 x\nb 150 y\nc 200 z\n'
    show answer

    printf 'a 50 x\nb 150 y\nc 200 z\n' | awk '$2 > 100 {print $3, $2, $1}'

    Expect y 150 b and z 200 c. (If you literally “swap first and third” keeping column 2 in place: {print $3, $2, $1} is that swap.)

  6. Dissect the SSH log pipeline from the lecture: what does each step do? Then build something similar to find your most-used shell commands from ~/.bash_history. 
    ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
    show answer

    Dissection: remote journalctl for previous-boot sshd → grep disconnect lines → sed -E capture username → sort | uniq -c counts → sort -nk1,1 | tail -n10 (ascending by count, then last 10 = most frequent) → awk '{print $2}' usernames only → paste -sd, comma-join.

    History analogue (bash; first word = command):

    awk '{print $1}' ~/.bash_history \
  | sort | uniq -c | sort -nr | head -20

    Skip comments/blank lines if needed: grep -v '^#' ~/.bash_history | …

Check your understanding

Six questions spanning the exercise set. Answers shuffled on each load.

Q1First 10 chars of ls -l are mainly…

  • type + rwx bits
  • owner and group
  • size and mtime
  • inode and links

Q2Why quote '*.zip' for find -name?

  • stop early shell glob
  • make find case-fold
  • enable brace expansion
  • force recursive match

Q3Both streams into one file (POSIX)?

  • cmd >f 2>&1
  • cmd 2>&1 >f
  • cmd <f 2>&1
  • cmd >f 1>&2

Q4Why is cd a shell builtin?

  • child can’t change parent cwd
  • PATH has no cd binary
  • cd needs root privileges
  • man pages forbid externals

Q5Spaces-safe find → xargs?

  • -print0 | xargs -0
  • -print | xargs -n1
  • -ls | xargs -I{}
  • -exec | xargs -0

Q6What does set -x add?

  • trace before each command
  • exit on first failure
  • error on unset vars
  • fail on pipe errors
