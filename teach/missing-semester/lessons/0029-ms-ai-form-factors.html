AI form factors

The three shapes AI takes in a dev workflow — autocomplete, inline chat, and agents — and where each one already lives in your stack (Zed, opencode, vim).

Why this matters

L0028 closed code intelligence (language servers + CLI checkers). MS’s next slice in lecture 3 is AI-powered development: how LLMs entered software engineering after GitHub Copilot popularized them in 2021. You already run three surfaces that span all three MS form factors — so this lesson names them, so you reach for the right one deliberately instead of by habit, and ties them back to the L0028 checkers as the way you gate AI output.

Read first (≈10 min): MS Development Environment and Tools — the “AI-powered development” section (Autocomplete → Inline chat → Coding agents). Skim Extensions for context; skip installing anything tonight.

Knowledge 1 — three form factors (MS taxonomy)

MS names three form factors. The boundary that matters is how much existing code the model can touch:

Form factorWhat it doesKey limit
autocompletesuggests at the cursor as you type; steered by commentsonly completes beyond the cursor — cannot rearrange existing code
inline chatselect a line/block, prompt in plain language, model proposes an edityou review & accept the proposed diff
agentdelegates a multi-step task; model edits across files and can run commandsmost autonomous — needs the most verification (MS gives it its own lecture)

MS’s autocomplete example exposes the core risk directly: asked to “extract all Markdown links,” the model returns valid code but places import re inside the function body instead of at the module level. Plausible, runnable, and wrong-shaped. That is the shape of almost every AI mistake you will see.

Knowledge 2 — map to your stack

Your three surfaces cover all three form factors. The notable one: opencode is a terminal-native coding agent — the most autonomous MS form factor, running in the same bash / tmux / ssh stack this mission is building. The agent form factor is not locked inside an IDE for you.

Mission framing. Vim stays the no-AI editing floor — for remote / SSH / surgical speed, and as the place you review AI output. Zed is an IDE you already own (like kitty / starship — present, not curriculum to expand). This lesson names form factors; it does not switch your daily editor. Exact Zed panel / mode names live in Zed’s docs.

Knowledge 3 — gate AI output (L0028 callback)

MS’s autocomplete bug is valid Python — py_compile would not catch it. The discipline: treat AI output as a draft, not a verdict, and run the L0028 checkers on it before you trust it.

python3 -m py_compile ai_output.py   # syntax?
mypy ai_output.py                    # types? (installed L0028)
gofmt -w ai_output.go && go vet ./... # format + static?

Same exit-status rule as L0023: 0 = clean, nonzero = reject or fix. Some AI mistakes (syntax, type mismatches) the checkers catch; others (the import placement, naming, design) only review or a dedicated linter catches — that linter depth is the later Code Quality lecture. The honest model: checkers raise the floor; they do not ceiling the work.

Drill — name, map, gate

Ghostty + bash + vim. Scratch: /tmp/ms-ai/.

  1. Name MS’s three form factors cold (no peeking), and one-sentence each what they do.
    show answer

    autocomplete (suggests at cursor, beyond-cursor only), inline chat (selected block → prompt → proposed edit), agent (multi-step, edits across files, can run commands).

  2. Map them to your surfaces. Which form factor does opencode give you in the terminal? Which surface has no AI at all?
    show answer

    opencode = agent (and conversational inline-chat-style proposes). Zed has all three. vim has none — it is the no-AI floor and the review surface.

  3. Reproduce MS’s autocomplete example and probe what a checker catches vs misses: 
    mkdir -p /tmp/ms-ai && cd /tmp/ms-ai
cat > extract.py <<'EOF'
def extract(content: str) -> list[str]:
    # extract all Markdown links from the content
    import re
    pattern = r'\[.*?\]\((.*?)\)'
    return re.findall(pattern, content)
EOF
python3 -m py_compile extract.py; echo "status=$?"
    Expect status=0 — the AI’s code is syntactically valid. One sentence: what did the checker catch, and what did it miss?
    show answer

    Caught: nothing — syntax is valid (status 0). Missed: import re belongs at module level, not inside the function. That is a placement / style issue caught by review or a linter (Ruff / Code Quality lecture), not by py_compile.

  4. Agent form factor, live. Using an agent surface — opencode (you are inside it now) or Zed’s agent mode — ask it to refactor extract.py: move import re to the module level and add a one-line docstring. Then gate the result before accepting: 
    python3 -m py_compile extract.py && mypy extract.py; echo "status=$?"
    Confirm both clean (status=0). If the agent touched anything else, that is normal — review the diff in vim.
    show answer

    import re now at top of file; docstring added under def. py_compile + mypy both 0. The point: the agent did the edit; the checkers (L0028) certified it.

  5. One sentence out loud: why does vim stay in the stack even with AI available everywhere?
    show answer

    Remote / SSH / no-GUI hosts where an IDE or agent may not run; surgical edits at grammar speed; and a neutral place to review AI output. AI is a layer on top, not a replacement for the manual floor.

  6. Cold rebuilds (no peeking):
    1. MS’s three AI form factors.
    2. Which form factor can change existing code, not just complete beyond the cursor?
    3. Why run py_compile / mypy on AI-suggested code?
    show answer

    (a) autocomplete, inline chat, agent.
    (b) inline chat and agent — autocomplete only completes beyond the cursor.
    (c) AI can produce plausible-but-wrong code; checkers catch syntax/type errors (nonzero status), and review catches the rest.

Later. MS gives agents their own Agentic Coding lecture — prompt patterns, tool-use, scope control, safety. The Code Quality lecture adds linters (e.g. Ruff) that catch placement / style issues py_compile misses. Prompt engineering depth and model / provider choice wait there.
