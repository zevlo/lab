Lesson 0002 · Phase 2 — vim

Audit your speed, then learn to jump

The grammar from Lesson 0001 plus five navigation tools — search, f, %, marks, and Ctrl-o — cover ~80% of real-world movement. That's all you need.

The audit — measure your current speed honestly

Before any new content, time yourself on a small edit using your old habits. After the lesson, you'll redo it with the new tools and compare.

Create the file from bash (not by pasting into vim — autoindent will mangle it):

cat > /tmp/audit.json <<'EOF'
{
  "service": "api-gateway",
  "version": "2.4.1",
  "endpoints": [
    {"path": "/users",  "method": "GET",  "handler": "listUsers"},
    {"path": "/orders", "method": "POST", "handler": "createOrder"}
  ],
  "database": {
    "host": "db.internal",
    "port": 5432,
    "pool": {"min": 5, "max": 50, "idleTimeoutMs": 30000}
  }
}
EOF
vim /tmp/audit.json

Task: change api-gateway to edge-gateway, and change db.internal to db-blue.internal. Two edits. Use whatever you'd normally use — arrow keys, scrolling, manual selection. Note your start and end time. Don't use anything from this lesson yet — it's a baseline. Write the time down.

Knowledge 1 — search: /pattern + n / N

The single highest-leverage motion in vim. Get somewhere by name, not by counting lines or scrolling.

/{pattern}<Enter>Search forward; cursor lands on first match
?{pattern}<Enter>Search backward
nNext match (same direction)
NNext match (reverse direction)
*Search forward for the word under cursor
Regex gotcha. ., *, [, ^, $, \ are regex metacharacters. /db.internal will usually match the literal db.internal (because . matches any char, including the dot), but the safe form is /db\.internal with the dot escaped. If you ever get E486: Pattern not found on something you can see in the buffer, the cause is either (a) metacharacter surprise, or (b) the buffer doesn't actually contain what you think — check for paste mangling.

Search composes as a motion in the grammar from Lesson 0001: operator + motion.

  • d/endpoints<Enter> — delete forward to the next endpoints
  • c?port<Enter> — change backward to the previous port

Knowledge 2 — char on a line: f + ;

For landing on a specific column on the current line — usually faster than w/b when you can see the target character.

f{x}Forward to next {x}; cursor lands ON it
;Repeat last f (find the next one)

Operators compose: df, deletes forward through the next comma. cf" changes forward to the next quote.

Knowledge 3 — brace matching: %

From a brace (( [ { ) ] }), % jumps to its match. From a non-brace char, it jumps to the next brace on the line first.

On the audit file, place your cursor on the { at the start of "pool"'s value. Press % — you land on its matching }. Press % again — back.

As a motion: d% deletes from cursor to matching brace (inclusive). v% selects from cursor to matching brace. This is the devops payoff for tracing nested JSON.

Knowledge 4 — marks: bookmark a line

Sets a named anchor you can return to. Lowercase marks are per-buffer; uppercase are global.

m{a}Set mark {a} at cursor
'{a}Jump to first non-blank on mark {a}'s line

Devops idiom: you're editing a long config, set ma on the line you're working on, detour with /search to check a related value, 'a snaps you straight back. No "where was I?" cognitive cost.

Knowledge 5 — the universal back button: Ctrl-o

Every jump (mark, search, G, etc.) is recorded in the jump list. Ctrl-o walks back through your trail. Use this when you forgot to set a mark but need to get back.

  • Ctrl-o — jump back
  • Ctrl-i — jump forward (after you've gone back)

Drill — same audit, new tools (~6 min)

Reset the file from bash so the contents are byte-perfect again:

cat > /tmp/audit.json <<'EOF'
{
  "service": "api-gateway",
  "version": "2.4.1",
  "endpoints": [
    {"path": "/users",  "method": "GET",  "handler": "listUsers"},
    {"path": "/orders", "method": "POST", "handler": "createOrder"}
  ],
  "database": {
    "host": "db.internal",
    "port": 5432,
    "pool": {"min": 5, "max": 50, "idleTimeoutMs": 30000}
  }
}
EOF
vim /tmp/audit.json

Tasks — each uses only motions from this or Lesson 0001

  1. Jump to api-gateway with search, then change it to edge-gateway.
    show answer

    /api-gateway<Enter> — cursor lands on a. ci" — change inside the quotes. Type edge-gateway, Esc.

    Notice how ci" from Lesson 0001 still does the heavy lifting. Search got you there.

  2. Change db.internal to db-blue.internal using search to get there, then f. to land on the dot.
    show answer

    /db\.internal<Enter> — note the escaped dot for precision. f. — forward to the next dot. i, type -blue, Esc.

    Alternative: ci"db-blue.internal<Esc> from inside the quotes. Faster for a short value, but f. is the technique being drilled.

  3. Brace match: cursor on the { of pool's value, press %. Verify you land on the matching }.
    show what to expect

    One keystroke moves you across multiple lines of nested JSON. % again returns you. This is the structural-navigation payoff.

  4. Mark roundtrip: cursor on the "host" line, ma. Search /createOrder<Enter>. Press 'a — verify you return to the host line.
    show what to expect

    Cursor lands on first non-blank of the marked line. The mark survives any number of subsequent jumps.

  5. Forget the mark this time: from createOrder, search /port<Enter>, then press Ctrl-o twice. Verify you walk back through your trail.
    show what to expect

    Ctrl-o once: back to createOrder. Twice: back to host. The jump list is your safety net when you didn't plan ahead with a mark.

  6. Bonus callback to Lesson 0001: da{ from inside the pool block — delete the whole object. u to undo.
    show answer

    Cursor anywhere inside the pool object's braces. da{ removes content and the delimiters. u brings it back.

Compare your times

Look at your baseline time versus how long the second pass took. Most comfortable dabblers cut their time by 40–60% on this drill. More importantly, the second pass should have felt smoother — less hunt-and-peck, less scrolling.

If it didn't feel smoother, that's the most useful signal you could give the teacher. Where exactly did you reach for the old habit? Note it and bring it to the next session.

Check your understanding

Four short questions. Click an option; feedback is immediate.

Q1After /foo<Enter>, which key finds the next match?

  • n
  • N
  • *
  • #

Q2Which key repeats the last f char search?

  • ;
  • ,
  • .
  • :

Q3Which key jumps to the matching brace from the cursor?

  • %
  • &
  • *
  • #

Q4Which key walks back through the jump list?

  • Ctrl-o
  • Ctrl-i
  • Ctrl-d
  • Ctrl-n

Ask the teacher. Did the audit show a measurable speedup? Did % feel like a superpower or did you forget it was there? Did you find yourself reaching for the mouse/arrow keys despite knowing the new tools — and if so, where?

Bring concrete observations to the next session. The teacher uses them to decide whether to push forward or pause and reinforce.
