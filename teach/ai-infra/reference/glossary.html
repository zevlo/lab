Glossary

AI Inference / Infrastructure Engineering — the shared vocabulary. Grows with each lesson.

VRAM memory
Video RAM — the GPU's own high-bandwidth memory (GDDR6 on the RTX A2000). Everything the GPU computes on must live here: model weights, the KV cache, and activation buffers. The central budget of inference engineering. Distinct from system RAM, which is attached to the CPU.
CUDA core compute
A general-purpose arithmetic lane on an NVIDIA GPU. The A2000 has 3,328. They do the bulk FP32/INT math. Grouped into Streaming Multiprocessors (SMs).
Tensor core compute
Specialized unit that does small matrix-multiply-accumulate operations very fast, especially in low precision (FP16/INT8). The A2000 has 104. Matrix multiplies dominate transformer inference, so Tensor cores do most of the heavy lifting.
Memory bandwidth memory
How fast data moves between VRAM and the compute cores, in GB/s (A2000: 288 GB/s). For LLM token generation (decode), this — not raw compute — is usually the bottleneck, because each token requires reading the whole model from VRAM. See Lesson 1.
Precision / dtype numerics
How many bytes represent each number (weight/activation). FP32 = 4 bytes, FP16/BF16 = 2 bytes, INT8 = 1 byte, INT4 ≈ 0.5 byte. Lower precision → less VRAM and faster math, at some accuracy cost.
Quantization numerics
Converting a model's weights (and sometimes activations) to lower precision to shrink VRAM use and speed up inference. E.g. a 3.8B model is ~7.6 GB in FP16 but ~1.9 GB in INT4. Common families: GGUF K-quants (llama.cpp/Ollama), GPTQ, AWQ, and FP8.
GGUF / K-quant numerics
The file format used by llama.cpp and Ollama for quantized models. "K-quant" levels like Q4_K_M mix precisions — most weights at ~4 bits, but embeddings and select layers kept higher — for better accuracy. Consequence: real files run ~20–40% larger than the naive params × 0.5 byte estimate. See Lesson 1.
Model weights model
The learned parameters. Memory ≈ num_params × bytes_per_param. A "7B" model has 7 billion parameters. This is the fixed, must-always-be-resident part of the VRAM budget.
KV cache inference
Stored key/value vectors for every token already processed, so the model doesn't recompute them each step. Grows with sequence length × batch size, and competes with weights for VRAM. The thing PagedAttention/vLLM exist to manage. (Dedicated lesson coming.)
Activations inference
Temporary intermediate tensors created during a forward pass. Plus framework overhead (CUDA context, PyTorch, NCCL). Part of the VRAM budget you must leave headroom for.
Throughput performance
Total useful work per unit time — e.g. tokens/second across all requests, or requests/second. The metric you maximize for serving cost-efficiency. Contrast with latency.
Latency performance
Time for a single request — often split into time-to-first-token (TTFT) and inter-token latency. The metric a single user feels. Often traded off against throughput via batching.
nvidia-smi tooling
NVIDIA System Management Interface — the command-line tool to inspect GPU model, VRAM usage (MiB), utilization %, temperature, power, and which processes hold the GPU. Your first diagnostic. Modal glossary.
Prefill vs decode inference
Two phases of LLM inference. Prefill: process the whole prompt at once (compute-bound). Decode: generate output tokens one at a time (memory-bandwidth-bound). They have very different performance characteristics.
