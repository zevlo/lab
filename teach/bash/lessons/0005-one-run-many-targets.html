One Run, Many Targets

≈ 15 minutes · one win: one run of diskcheck.sh checks every path you give it — and survives the bad ones · ← lesson 0004 · glossary

Why this matters

Your diskcheck.sh checks one path per run. Real days are not like that: five mounts to check, three services to restart, ten log directories to clean. Copy-pasting the body five times is how scripts rot — fix one copy, forget the other four. Today the script learns to loop: write the body once, point it at a list. And you finally meet "$@", promised since lesson 0003.

The one idea

for runs the body once per word in a list. Bash splits the words after in, sets the loop variable to one word at a time, and runs everything between do and done for it [1]. do and done play the roles then and fi played in your if:

for svc in nginx docker ssh; do
  echo "checking $svc"
done
PartJob
for name in words; do Split words into a list. Start with the first word in name.
the body Any commands. They run once per word.
done Ends the body. Move to the next word — or continue past the loop when the list runs out.

Quoting rules do not change: "$svc" in the body stays one word. The lesson-0002 rules travel with you.

Where the words come from

Three sources cover almost every real loop you will write:

ListWhat bash loops over
for svc in nginx docker ssh Literals you type. Fine for a fixed, short list.
for target in "$@" Every argument the user gave — each one whole, spaces safe. The quotes are the whole trick: they stop word splitting.
for file in *.log Every filename matching the glob — each one whole. Bash expands the pattern before the loop starts, so filenames with spaces survive.

A bare for target with no in list means the same as in "$@" — the bash manual says so in those words [2]. Write the explicit form anyway; it reads better.

Upgrade diskcheck.sh

  1. Replace the single-target body with a loop. The argument guard stays. The existence guard from lesson 0004 moves inside the loop — but its exit 1 becomes continue: one bad path should warn and be skipped, not kill the whole run: 
    #!/usr/bin/env bash
# diskcheck.sh — check free space on every path you give
if [ $# -eq 0 ]; then
  echo "usage: $0 /path/to/check [more paths ...]" >&2
  exit 1
fi
for target in "$@"; do
  if [[ ! -e "$target" ]]; then
    echo "error: no such path: $target" >&2
    continue
  fi
  echo "=== disk check: $target ==="
  df -h "$target"
done
    continue drops the current item and jumps to the next one — the per-item version of a guard's exit 1. Its sibling break leaves the loop entirely but keeps the script running.
  2. Predict, then run. Before each command, say what you will see and in what order: 
    ./diskcheck.sh / /tmp /nope
=== disk check: / === …
=== disk check: /tmp === …
error: no such path: /nope
./diskcheck.sh /nope /tmp
error: no such path: /nope
=== disk check: /tmp === …
    The loop keeps going after an error — that is continue doing its job.
  3. Break it on purpose. Remove the quotes around $@ in the for line, then: 
    mkdir "/tmp/odd dir"
./diskcheck.sh "/tmp/odd dir"
error: no such path: /tmp/odd
error: no such path: dir
    Unquoted $@ got word-split: one argument became two. Put the quotes back. Your mission demands scripts that survive spaces — this is exactly what that means.

Honesty note. The upgraded script still exits 0 even when a path was skipped — the last df decided the exit status. For now, the error message tells the human. Making CI fail properly is a later lesson.

Files: loop over globs, never over ls

You will meet this loop in old scripts. It is a famous bug:

for file in $(ls *.log)   # wrong
for file in *.log          # right

$(ls *.log) pastes ls's output into the list as one text blob, and bash word-splits it. A file called server one.log arrives as two broken words. The glob form never splits: bash itself matched the real filenames, and hands them to the loop one whole word each [3]. ShellCheck flags the ls version as SC2045 — one more reason to keep it in your workflow.

One edge to know: when nothing matches, bash hands the loop the literal text *.log. If that matters, reuse your guard habit:

for file in *.log; do
  [[ -e "$file" ]] || continue   # no matches — skip
  :                            # your commands here
done

Practice on your own work

  1. Upgrade peek.sh the same way. Loop over "$@", keep the -f guard per file, and continue past missing ones. Prove it: ./peek.sh /etc/hosts /nope — the good file is tailed, the missing one warned about. (tail even labels each file itself.)
  2. Feel the glob safety. Then: 
    mkdir -p ~/loopdemo && cd ~/loopdemo
touch "app one.log" "app two.log" readme.txt
for f in *.log; do ls -l "$f"; done
for f in *.log; do ls -l $f; done
    The first loop lists two files. Say why the second one errors before you run it. Then delete the directory and go wash your hands of unquoted variables.
  3. Run ShellCheck on diskcheck.sh and peek.sh. Expect zero warnings — and notice it would have caught the $(ls …) habit as SC2045.
