Look Before You Leap

≈ 14 minutes · one win: a missing path gets a clear error and exit status 1 before anything runs · ← lesson 0003 · glossary · test operators

Why this matters

Last lesson your script learned to count its arguments. But a count is not the whole job. Run ./diskcheck.sh /nope — it passes the count check, then df discovers the problem and prints a confusing error. Real ops tools flip this around: they check the world themselves, before anything runs. Deploy scripts verify the artifact exists. Cleanup scripts verify the path before rm touches it. Today your script learns to look before it leaps.

The one idea

if runs one command and reads its exit status. Success — status 0 — runs the then block. Failure runs the else block, or skips ahead [1]. And bash ships a command whose whole job is checking things: the test command. You already used it once — [ $# -eq 0 ] from your guard.

The full shape, with every optional part:

if [[ -d /var/log ]]; then
  echo "log directory is in place"
elif [[ -d /var/log.0 ]]; then
  echo "only rotated logs found"
else
  echo "no log directory" >&2
fi
PartJob
if … ; then Run the test. Status 0? Run this block.
elif … ; then Optional. Another test, tried only when the first failed.
else Optional. Runs when every test failed.
fi Ends the decision. if spelled backwards.

The test toolbox

Between [[ … ]] you ask one true-or-false question. The ones you will use most:

TestTrue when…
[[ -e "$path" ]]the path exists — file, directory, anything
[[ -f "$path" ]]it is a regular file
[[ -d "$path" ]]it is a directory
[[ -r "$path" ]]you can read it
[[ -z "$text" ]]the string is empty (zero length)
[[ -n "$text" ]]the string is not empty
[[ "$a" = "$b" ]]the strings are identical
[[ "$n" -lt 10 ]]the number is less than 10

Put ! in front to flip any answer: [[ ! -e "$target" ]] is true when the path is missing. The complete operator list lives in the test-operators reference, straight from the bash manual [2].

Which brackets? In bash scripts, prefer [[ … ]]. Inside the double brackets, variables cannot be word-split — the bug class from lesson 0002 cannot reach your test. Keep [ … ] for scripts that must run in other POSIX shells. Both appear in old scripts, so read both; write [[ … ]] [3].

Make the script look first

  1. Add a second guard to diskcheck.sh — below the argument guard, above the body. It uses the flip: not exists → complain and stop: 
    #!/usr/bin/env bash
# diskcheck.sh — check free space on a path you give
if [ $# -eq 0 ]; then
  echo "usage: $0 /path/to/check" >&2
  exit 1
fi
target="$1"
if [[ ! -e "$target" ]]; then
  echo "error: no such path: $target" >&2
  exit 1
fi
echo "=== disk check: $target ==="
df -h "$target"
  2. Prove both branches. Run a real path and a fake one: 
    ./diskcheck.sh /
=== disk check: / === …
./diskcheck.sh /nope
error: no such path: /nope
echo $?
1
    Compare that with the old behaviour: df: : No such file or directory. Same failure, but now the message names the cause, and the exit status still tells CI honestly: 1.
  3. Feel the tests — predict first. Before running, say out loud which of these four lines will print. Then run them: 
    [[ -d /etc ]] && echo "one: directory"
[[ -f /etc ]] && echo "two: regular file"
[[ -z "" ]] && echo "three: empty"
[[ ! -d /etc ]] && echo "four: missing"
    Each silent line is a test that answered false. Wrong predictions are the useful ones — say why it fooled you.

Practice on your own work

  1. Guard peek.sh too. Last lesson's peek.sh tails a file — so it should demand a file. Add: [[ ! -f "$1" ]] → usage message to stderr, exit 1. Prove it with ./peek.sh /etc/hosts and ./peek.sh /nope.
  2. Check a path you really use. Write canwrite.sh: take one argument, then use [[ -d … ]] and [[ -w … ]] to report whether that directory exists and is writable — two guards, or one if/else. Try it on a work directory you actually depend on.
  3. Run ShellCheck on both. Paste the two scripts into shellcheck.net — expect zero warnings. This is the habit from your mission: scripts pass ShellCheck clean before you trust them.
