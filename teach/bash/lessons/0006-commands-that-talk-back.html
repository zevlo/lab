Bash for DevOps · Lesson 0006

Commands That Talk Back

≈ 15 minutes · one win: snapshot.sh writes a dated tarball of any directory — and refuses to lie when tar fails · ← lesson 0005 · glossary

Why this matters

Your scripts can guard, decide, and loop. But they still only talk to eyes: output scrolls past, and decisions come only from [[ ]] questions about files and strings. Real automation asks commands two questions instead. What did you say? — put a command's output into a variable. Did it work? — let any command, not just tests, drive an if. Today you learn both, and your loops from lesson 0005 start to earn their keep.

Capture: what did it say?

Command substitution runs a command and pastes its output where the command sat. Bash runs the command inside $( … ), captures its standard output, and replaces the whole $( … ) with that text. Any trailing newline is trimmed [1]: 

today="$(date +%F)"
echo "backup for $today"
backup for 2026-09-21

Four rules carry you a long way:

RuleWhy
Quote it: "$(cmd)" Same rule as variables. Unquoted output gets word-split; quoted output stays one value [2].
Only stdout is captured Errors still go to stderr and reach your screen. Capture never swallows error messages.
Backticks are read-only `cmd` is the old form. Recognise it in old scripts; never write it — nesting it is a mess [1].
It runs in a subshell A copy of the shell. Changes inside — like cd — do not survive outside. You will meet this again later.

One mercy: in a plain assignment, name=$(cmd) without quotes is safe — assignments never word-split. Quote anyway. One habit, no exceptions, no sleeping.

Ask: did it work?

if has never needed [[ ]]. [[ ]] is itself just a command that reports by exit status. The condition — the command between if and ; then — can be any command: bash runs it and reads its exit status. Zero runs the then block; anything else runs else [3]. Your guards from lesson 0004 were this all along.

The star example is grep -q. The -q flag means quiet: print nothing, answer only by exit status — 0 found, 1 not found. A yes/no command, made for if:

if grep -q root /etc/passwd; then
  echo "root account present"
else
  echo "no root account?!"
fi

Noisy command, same trick: send stdout to /dev/null — the shredder — and keep the status. You already know >&2 from lesson 0003; >/dev/null is its quiet cousin:

if curl -sf -o /dev/null https://example.com; then
  echo "site answers"
else
  echo "site down or unreachable"
fi

-s silences curl's progress meter; -f makes HTTP errors (like 404) count as failure.

Two questions, two tools. Do not mix them up:

QuestionToolShape
What did it print?capture out="$(cmd)"
Did it work?status if cmd; then … fi

Build snapshot.sh

  1. Write it. Every guard is a guard you already own, word for word. Only the last five lines are new: 
    #!/usr/bin/env bash
# snapshot.sh — save a dated tarball of one directory
if [ $# -ne 1 ]; then
  echo "usage: $0 /path/to/snapshot" >&2
  exit 1
fi
target="$1"
if [[ ! -d "$target" ]]; then
  echo "error: not a directory: $target" >&2
  exit 1
fi
name="snapshot-$(date +%F).tar.gz"
if tar -czf "$name" "$target"; then
  echo "wrote $name"
else
  echo "error: tar failed" >&2
  exit 1
fi
    Line by line: $(date +%F) builds today's date into the filename. tar itself is the condition — if the archive writes, we say so; if not, stderr gets the truth and the script exits 1.
  2. Predict, then run. Say each output aloud first: 
    chmod +x snapshot.sh
./snapshot.sh
usage: ./snapshot.sh /path/to/snapshot
./snapshot.sh /tmp
wrote snapshot-2026-09-21.tar.gz
./snapshot.sh /nope
error: not a directory: /nope
    Same-day reruns overwrite yesterday-less archive: %F is date-only. When you need one per run, switch to $(date +%F-%H%M).
  3. Break it on purpose. Change the name line to name="snapshot-$(date).tar.gz" — full date output contains spaces. Keep the quotes: the script still works, spaces and all. Now strip the quotes from "$name" in the tar line and run again: 
    ./snapshot.sh /tmp
tar: snapshot-Mon: Cannot open: No such file or directory
error: tar failed
    Unquoted, one filename became six words, and tar choked on the first. Notice what saved you: the if caught the failure and the script told the truth. Restore the quotes and the %F form.

Pitfalls: two wrong wrappers

You will see both in the wild. Neither asks the question you meant:

if $(grep -q root /etc/passwd); then   # wrong
if [ -n "$(grep root /etc/passwd)" ]; then # wrong
if grep -q root /etc/passwd; then          # right

The first runs the substitution, pastes grep's empty output between if and ; then, and asks bash to run that empty text as the condition command. The second asks "did it print anything?" — a command can print plenty and still have failed. If you only need yes/no, run the command bare as the condition [3]. Capture is for when you need the text.

Honesty note. A command that fails inside $( … ) does not fail your script — name="$(date +%F)" goes wrong silently, and the script marches on. That is now two open gaps, with lesson 0005's loop that skips bad paths but still exits 0. A later lesson teaches scripts to fail loudly on their own.

Practice on your own work

  1. Upgrade healthcheck.sh. It still just prints commands. Capture first, then report: now="$(date '+%F %T')", host="$(hostname)", and print one summary line. Then add one real decision: 
    if pgrep -x sshd >/dev/null; then
  echo "sshd: running"
else
  echo "sshd: not found"
fi
    Predict the output before each run. Then try a process name that is not running, and watch the else branch earn its keep.
  2. Feel the splitting, lesson 0005 style. On the command line: 
    for part in $(date); do echo "[$part]"; done
for part in "$(date)"; do echo "[$part]"; done
    Say both counts out loud before running: five bracketed words, then one. That is capture plus quoting in a single breath.
  3. Run ShellCheck on snapshot.sh and the upgraded healthcheck.sh. Expect zero warnings.
