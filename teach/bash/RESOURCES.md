# Bash for DevOps Resources

## Knowledge

- [GNU Bash Reference Manual](https://www.gnu.org/software/bash/manual/) — verified 2026-09-10
  The authoritative definition of bash, from its maintainers (Free Software Foundation). Use for: exact behaviour of any syntax; settling disagreements about what bash does.
- [ShellCheck](https://www.shellcheck.net) — verified 2026-09-10
  Static analysis that finds bugs in shell scripts. The [wiki](https://github.com/koalaman/shellcheck/wiki) explains every warning code. Use for: checking every script you write; decoding warnings like SC2086.
- [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html) — verified 2026-09-10
  How a large engineering org writes bash in production. Use for: conventions — shebang, quoting, naming, when shell is the right tool at all.
- [Greg's Wiki: BashGuide](https://mywiki.wooledge.org/BashGuide) (+ [BashPitfalls](https://mywiki.wooledge.org/BashPitfalls), [BashFAQ](https://mywiki.wooledge.org/BashFAQ)) — verified 2026-09-10
  Community-maintained and trusted by shell experts; the BashPitfalls page lists common beginner mistakes in order of how often they bite. Use for: pitfalls, deep FAQ answers, the recommended learning path.

## Wisdom (Communities)

- [Unix & Linux Stack Exchange](https://unix.stackexchange.com/)
  High-signal Q&A with strict quality norms. Use for: search first; ask second. Most beginner questions are already answered in depth.
- [r/bash](https://www.reddit.com/r/bash/)
  Active practitioner subreddit. Use for: script review and "why doesn't this work" posts.
- [#bash on Libera.Chat IRC](https://libera.chat/)
  The expert channel referenced by Greg's Wiki. Use for: real-time help on gnarly problems.
