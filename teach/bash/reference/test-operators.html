Test Operators

Every question [[ … ]] can ask, on one page. Pairs with Lesson 0004 · Terms in the glossary · Authoritative source: GNU manual, Bash Conditional Expressions

The if shape

if [[ condition ]]; then
  # success branch (exit status 0)
elif [[ condition ]]; then
  # optional: tried when the first test failed
else
  # optional: runs when every test failed
fi

File tests

TestTrue when…
-e paththe path exists (file, directory, link, anything)
-f pathit is a regular file
-d pathit is a directory
-h pathit is a symbolic link
-r pathyou can read it
-w pathyou can write it
-x pathyou can execute it
-s pathit exists and is not empty (size > 0)
f1 -nt f2file 1 is newer than file 2
f1 -ot f2file 1 is older than file 2

String tests

TestTrue when…
-z strthe string is empty (zero length)
-n strthe string is not empty
a = bthe strings are identical
a != bthe strings differ
a == pata matches glob pattern pat ([[ ]] only)
a =~ rea matches regex re ([[ ]] only)

Number tests

TestTrue when…
n1 -eq n2equal
n1 -ne n2not equal
n1 -lt n2less than
n1 -le n2less than or equal
n1 -gt n2greater than
n1 -ge n2greater than or equal

Combine and flip

FormMeaning
! condNOT — flips the answer
cond1 && cond2AND — both must hold ([[ ]] only)
cond1 || cond2OR — either may hold ([[ ]] only)
[[ ]] vs [ ]. In bash scripts, write [[ … ]]: no word splitting inside, and &&/||/pattern matching work. Keep [ … ] only for scripts that must run in other POSIX shells — you will still read [ … ] in older scripts.

The two guards, ready to copy

# did the user give the argument?
if [[ $# -eq 0 ]]; then
  echo "usage: $0 /path" >&2
  exit 1
fi

# does the thing exist before we act on it?
if [[ ! -e "$1" ]]; then
  echo "error: no such path: $1" >&2
  exit 1
fi
