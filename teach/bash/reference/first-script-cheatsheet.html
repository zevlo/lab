Your First Script

The whole loop on one page. Full explanation in Lesson 0001 · Terms in the glossary

The four-step loop

  1. Create a text file ending in .sh.
  2. First line: the shebang. Then your commands, one per line.
  3. Grant execute permission: chmod +x myscript.sh
  4. Run it: ./myscript.sh

Minimal template

#!/usr/bin/env bash
# myscript.sh — one line: what this does
# your commands here, one per line, top to bottom

Example: quick health check

#!/usr/bin/env bash
# healthcheck.sh — quick server vitals
echo "=== health check ==="
date
df -h /
echo "=== done ==="

Run it two ways

CommandWhat happensNeeds chmod +x?
./healthcheck.shSystem runs it as a program, using the shebang to pick bashYes
bash healthcheck.shYou hand the file to bash directlyNo
Why ./? The shell finds bare command names (like ls) only in the folders listed in PATH. Your script's folder is not in that list, so you must show the way with ./.

Before you call it done

  1. Run it — expect exit status 0: ./healthcheck.sh && echo PASS
  2. Check it at shellcheck.net (or brew install shellcheck, then shellcheck healthcheck.sh) — expect zero warnings.
