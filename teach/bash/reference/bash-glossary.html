Foundations

shell noun
The program that reads what you type and runs commands. It is a layer around the operating system — hence the name.
terminal noun
The window where you talk to the shell. The terminal shows text; the shell thinks.
bash noun
The most common shell on Linux — Bourne Again shell. It is the default on most Linux servers and the shell this course targets. macOS ships an older bash (3.2) plus zsh as default; for scripts, bash is what you write.
POSIX standard
A formal standard that shells and tools agree to follow. A "POSIX script" avoids bash-only features so it runs in any POSIX shell. You will meet this word in older scripts and CI systems.

Scripts

script noun
A text file of shell commands, run from top to bottom. A saved, reusable version of what you type by hand.
shebang noun · #!
The first line of a script, starting with #!. It names the interpreter that runs the file. Example: #!/usr/bin/env bash
interpreter noun
The program that reads your script and carries out its commands, one by one. For your scripts, the interpreter is bash.
executable · execute permission property
A file the system is allowed to run as a program. New files do not have this permission; you grant it with chmod +x.
exit status noun · $?
The number every command leaves behind when it finishes: 0 means success, anything else means failure. Scripts and CI systems make decisions from it.

Variables and quoting

variable noun
A named box that stores text, so one script can serve many jobs. Store once, reuse everywhere. target="/var/log"
assignment noun
The act of storing a value: name=value. No spaces around the =, and no $ on the left side. target="/var/log" ✓ target = "/var/log" ✗
expansion · parameter expansion noun
Reading a variable back: $name or ${name}. Bash pastes the stored text into the command at that spot. echo "checking $target"
quoting noun
Double quotes "…": variables expand, and the value stays one word. Single quotes '…': everything is literal, nothing expands. Rule of thumb — quote every expansion. "$file" → one word · $file → many words · '$file' → text "$file"
word splitting noun
Bash's habit of cutting unquoted text into words at spaces. The number one source of beginner script bugs — ShellCheck flags it as SC2086.
braces syntax · ${name}
The explicit form of expansion. Needed when gluing text to a name: ${file}bak is variable file plus bak. Braces do not quote — you still need the double quotes.

Arguments and errors

argument · positional parameter noun
A word the user types after the script name. Inside the script: $1 is the first, $2 the second, and so on. ./diskcheck.sh /var/log → $1 = /var/log
$# special parameter
The number of arguments the script received. The standard way to check "did the user give me what I need?"
$0 special parameter
The name the script was run as. Used in usage messages, so the message matches whatever the file is called.
"$@" special parameter
All the arguments, each kept whole as its own word. In a loop, for arg in "$@" runs the body once per argument. The quotes are the whole trick — they stop word splitting. ./chk.sh a "b c" → two items: a, b c
exit command
Ends the script immediately, leaving an exit status behind: exit 0 success, exit 1 (or any non-zero) failure. Callers — humans, CI pipelines, other scripts — read that number.
stdout · stderr noun
The two output channels every command has. Normal output goes to stdout; errors go to stderr — written >&2 in bash. CI logs and pipelines separate them, so error messages belong on stderr.

Decisions and tests

if · then · elif · else · fi keywords
The decision shape. if runs one command and reads its exit status: success runs the then block; failure runs elif tests or the else block; fi ends it.
test command · [ … ] command
A real command whose job is checking one thing — file exists, string empty, number big enough — and reporting by exit status. Needs spaces around the brackets, and a closing ].
[[ … ]] bash keyword
Bash's upgraded test. Variables inside cannot be word-split, and &&, ||, pattern matching work. Prefer it in bash scripts; keep [ … ] for POSIX scripts. [[ -d /var/log ]] && echo yes
file tests operators · -e -f -d -r -w
True-or-false questions about a path: -e exists, -f regular file, -d directory, -r/-w readable/writable. Full list in the test-operators sheet.
string tests operators · -z -n = !=
Questions about text: -z is empty, -n is not empty, =/!= compare two strings.
number tests operators · -eq -ne -lt -le -gt -ge
Compare whole numbers: equal, not equal, less than, less-or-equal, greater than, greater-or-equal. [[ "$count" -lt 10 ]]
negation operator · !
Flips a test's answer. [[ ! -e "$x" ]] is true when the path is missing — the shape of every "look before you leap" guard.
guard pattern
A check at the top of a script that refuses to continue when something is wrong: message to stderr, then exit 1, before the body runs. The habit that makes a script safe to run unattended.

Loops

loop noun
A structure that repeats commands, so one body of code can work on many things.
for · in · do · done keywords
The list loop. Bash splits the words after in and runs the body between do and done once per word, with the loop variable set to that word. for target in "$@"; do df -h "$target"; done
continue builtin
Inside a loop: drop the current item and jump to the next one. The per-item version of a guard's exit 1.
break builtin
Inside a loop: leave the loop now. The script continues after done.
glob · filename pattern noun · *.log
A pattern that bash replaces with the matching filenames — each one whole, spaces safe. Write it unquoted so it can expand: for file in *.log. Never loop over $(ls …) output instead.
while · until keywords
The checking loop. Repeats the body for as long as a command succeeds (while) or fails (until) — used when the list is not known in advance.

Commands that talk back

command substitution syntax · $( … )
Run the command inside the parentheses, capture its standard output as text, and paste that text where the $( … ) sat. Trailing newlines are trimmed. Quote it like a variable: "$(cmd)". Backticks `cmd` are the old form — read them, never write them. today="$(date +%F)"
condition noun
In an if statement: the command between if and ; then. Bash reads its exit status to pick a branch. Any command can be a condition — not only tests. if grep -q root /etc/passwd; then …
subshell noun
A copy of the shell that bash starts to run a command substitution. What happens inside — like a cd — does not survive outside it.

Running things

PATH noun
The list of folders the shell searches when you type a bare command name like ls. Your own folder is not on it — that is why you must type ./script.sh.
chmod command
Change mode — the command that changes file permissions. chmod +x file makes a file executable.
ShellCheck tool
A checker that finds common bash bugs before they bite. Free at shellcheck.net. Treat it as your spell-checker for scripts.
