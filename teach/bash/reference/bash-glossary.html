Bash Glossary

The words this course uses. New terms are added every lesson — the lessons always mean exactly what this page says. Lesson 0001 · Lesson 0002 · Lesson 0003 · First-script cheatsheet

Foundations

shell noun
The program that reads what you type and runs commands. It is a layer around the operating system — hence the name.
terminal noun
The window where you talk to the shell. The terminal shows text; the shell thinks.
bash noun
The most common shell on Linux — Bourne Again shell. It is the default on most Linux servers and the shell this course targets. macOS ships an older bash (3.2) plus zsh as default; for scripts, bash is what you write.
POSIX standard
A formal standard that shells and tools agree to follow. A "POSIX script" avoids bash-only features so it runs in any POSIX shell. You will meet this word in older scripts and CI systems.

Scripts

script noun
A text file of shell commands, run from top to bottom. A saved, reusable version of what you type by hand.
shebang noun · #!
The first line of a script, starting with #!. It names the interpreter that runs the file. Example: #!/usr/bin/env bash
interpreter noun
The program that reads your script and carries out its commands, one by one. For your scripts, the interpreter is bash.
executable · execute permission property
A file the system is allowed to run as a program. New files do not have this permission; you grant it with chmod +x.
exit status noun · $?
The number every command leaves behind when it finishes: 0 means success, anything else means failure. Scripts and CI systems make decisions from it.

Variables and quoting

variable noun
A named box that stores text, so one script can serve many jobs. Store once, reuse everywhere. target="/var/log"
assignment noun
The act of storing a value: name=value. No spaces around the =, and no $ on the left side. target="/var/log" ✓ target = "/var/log" ✗
expansion · parameter expansion noun
Reading a variable back: $name or ${name}. Bash pastes the stored text into the command at that spot. echo "checking $target"
quoting noun
Double quotes "…": variables expand, and the value stays one word. Single quotes '…': everything is literal, nothing expands. Rule of thumb — quote every expansion. "$file" → one word · $file → many words · '$file' → text "$file"
word splitting noun
Bash's habit of cutting unquoted text into words at spaces. The number one source of beginner script bugs — ShellCheck flags it as SC2086.
braces syntax · ${name}
The explicit form of expansion. Needed when gluing text to a name: ${file}bak is variable file plus bak. Braces do not quote — you still need the double quotes.

Arguments and errors

argument · positional parameter noun
A word the user types after the script name. Inside the script: $1 is the first, $2 the second, and so on. ./diskcheck.sh /var/log → $1 = /var/log
$# special parameter
The number of arguments the script received. The standard way to check "did the user give me what I need?"
$0 special parameter
The name the script was run as. Used in usage messages, so the message matches whatever the file is called.
"$@" special parameter
All the arguments, each kept whole as its own word. Proper use arrives with loops (lesson 0005) — for now, know the name.
exit command
Ends the script immediately, leaving an exit status behind: exit 0 success, exit 1 (or any non-zero) failure. Callers — humans, CI pipelines, other scripts — read that number.
stdout · stderr noun
The two output channels every command has. Normal output goes to stdout; errors go to stderr — written >&2 in bash. CI logs and pipelines separate them, so error messages belong on stderr.

Running things

PATH noun
The list of folders the shell searches when you type a bare command name like ls. Your own folder is not on it — that is why you must type ./script.sh.
chmod command
Change mode — the command that changes file permissions. chmod +x file makes a file executable.
ShellCheck tool
A checker that finds common bash bugs before they bite. Free at shellcheck.net. Treat it as your spell-checker for scripts.
