# Mission: Bash for DevOps

## Why
You are a DevOps engineer working across CI/CD pipelines, Linux servers, and containers. Today you run commands by hand and treat existing scripts as magic. When this mission is done, you write your own reliable automation, and you can read, debug, and fix the shell code already in your pipelines.

## Success looks like
- You turn a repeated manual task into a saved script you trust to run unattended.
- You read an unfamiliar script in a pipeline and can say exactly what it does.
- A broken script tells you its problem; you find and fix the bug in minutes, not hours.
- Your scripts pass ShellCheck clean and survive filenames with spaces.

## Constraints
- About 30 minutes a day, in short lessons.
- You learn on a macOS terminal; production targets Linux. Note the differences when they matter.
- Fundamentals first. No frameworks, no exotic tricks.

## Out of scope
- Other languages (Python, Go), even where they might fit better.
- zsh/fish specifics. Bash is the target shell.
- Configuration tools (Ansible, Terraform), except as lesson context.
