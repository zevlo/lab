What will you be able to do?

You will read one Git commit and say three things.

What changed. Where that commit sits in the history. Why a password in that history means you rotate the secret.

Why does this job need it?

Git is a basic qualification for DevSec Engineering, Level 2, at Lockheed Martin Space.

Every later tool on the interview path starts from a change in Git. A pipeline will test that change. Argo CD will treat the Git history as what the cluster should be running.

What is a commit?

A repository is the project folder plus the full history Git keeps for it.

A commit is one saved snapshot of the files in that repository. The snapshot carries a message, the author, and a pointer to the previous snapshot.

A diff is the line-by-line comparison Git prints between two snapshots.

A branch is a name that points at one commit. The name can move. main is a branch name.

How do you read a diff?

Read the sample from top to bottom. The password in it is fake.

  1. The first line is the short name of this commit: 4f2a9c1.
  2. The message is the reason the author gave: stop writing the database password in the config file.
  3. A line that starts with - was in the previous snapshot. This snapshot left it out.
  4. A line that starts with + is in this snapshot. The previous snapshot left it out.
commit 4f2a9c1
Author: Example <dev@example.com>

    Stop writing the database password in the config file

diff --git a/app/config.yaml b/app/config.yaml
--- a/app/config.yaml
+++ b/app/config.yaml
@@ -3,1 +3,1 @@
-password: "example-not-real"
+password: "${DB_PASSWORD}"

The old line stored a password in the file. The new line stores the name DB_PASSWORD. That name stands for a value kept outside the file.

Where does this commit sit?

Each commit points at the commit before it. That chain is the history.

When someone adds another commit on main, the name main moves to that new commit. The older commits stay in the chain.

What if the diff shows a password?

The line that starts with - still shows the password. Anyone who can read this commit can read that line.

The parent commit, b7d9f1, stored the file with the password in it. A later commit that drops the line leaves those older snapshots in the repository.

GitHub’s guide to removing sensitive data from a repository says the first step, when that data is a secret, is to revoke or rotate it. After you rotate it, the old value no longer grants access. Other copies of the repository can still hold the old commits.

The sentence to say in the interview: “I would rotate that secret. The old commits still contain it.”

Can you read a change?

Choose one answer for each question. The choices are the same length. The page marks your choice at once.

1. In the sample, what did the commit do with the password line?

2. A line in a diff starts with a plus sign. What does that mark?

3. A later commit drops the password line. What is still true?

4. Which sentence describes a branch name such as main?

What should you read next?

Read two chapters of Pro Git, the Git project’s own book. Start with Recording Changes to the Repository. Then read Branches in a Nutshell. Those chapters are the source for the snapshot, the diff, and the branch name.
