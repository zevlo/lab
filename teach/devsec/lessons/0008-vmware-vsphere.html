vSphere, mapped from Proxmox

Three names, one stack. vSphere is VMware's virtualization platform, the suite. ESXi is the hypervisor, installed bare-metal on each physical host. vCenter Server, shipped as the vCenter Server Appliance (VCSA), is the centralized management utility: it manages virtual machines, multiple ESXi hosts, and all dependent components from one location. Proxmox folds these roles into each node; vSphere separates them on purpose.

vMotion deserves one paragraph, because the mechanism is an interview favorite. The running VM's memory streams to the new host while the VM keeps running; changed blocks re-send in smaller and smaller passes; a final brief freeze switches over. Storage vMotion works the same trick on disks, mirroring them to the destination datastore in sync until the cutover. Both require vCenter.

Bridge from your floor. You have live-migrated VMs between Proxmox nodes. vMotion is that, with the memory-transfer story as the whiteboard answer. Say the mechanism; it lands.

The cluster features

Two cluster features carry the interview, and they answer different questions. HA answers a failure that already happened: when a host dies, HA restarts its VMs on surviving hosts. DRS answers a failure in progress: it watches load and schedules vMotion moves to rebalance before anything starves. Reaction and prevention, one syllable apart in every interview room.

A datastore is the storage layer every host in the cluster can reach, usually VMFS on a SAN or NFS from a filer. Shared storage is what makes vMotion between hosts fast: the disk stays put while the memory moves.

A template is a VM frozen into a golden image. Clones start from it. Nobody builds a VM by hand twice.

Bridge. DRS has no built-in Proxmox twin, and that difference is worth saying out loud in an interview: Proxmox gives you HA and live migration; DRS-style automated balancing is vSphere territory.

vSphere under STIGs

DISA's STIG library covers the whole stack in layers: a STIG for the ESXi host, one for vCenter, one for the virtual machines. Three layers, three baselines, one scan loop. The finding decision matches Lessons 0003 and 0007: fix, or carry a POA&M entry.

Hardening centers on vCenter, because vCenter admin is root over every VM at once. The vocabulary: role-based access, a management network kept separate from VM traffic, and lockdown mode, which closes direct host management so vCenter becomes the single door. One door, one audit trail.

Bridge. The logic is Lesson 0007's domain story at rack scale: declared settings, central delivery, scanned evidence. GPO to Windows is what vCenter policy is to ESXi.

Templates are artifacts

Lesson 0004 built the rule: build once, promote everywhere. A hardened template is that rule applied to VMs. Build the golden image once, harden it against the VM STIG, then clone it into every environment. Export travels too: OVF/OVA is the packaging format for a VM and its configuration, and the checksum travels with it, verified before first boot on the far side. SI-7, the same control from Lesson 0004.

Bridge. You already deploy containers by digest and never rebuild per environment. A template digest-checksum at promotion is the identical instinct with a different artifact.

Interview traps. vSphere is the suite; ESXi is the hypervisor; vCenter is the management plane. HA reacts to failure; DRS balances before it. vMotion moves a running VM; Storage vMotion moves its disks. Clones come from one hardened template, and a rebuild per environment breaks the build-once rule. Proxmox maps to nearly all of this, and DRS is the honest exception.
