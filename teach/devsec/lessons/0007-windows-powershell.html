PowerShell, mapped from Bash

Microsoft's definition is one sentence: a command-line shell, a scripting language, and a configuration management framework, cross-platform. One fact changes your habits: the pipeline carries .NET objects. The docs state it plainly: unlike shells that accept and return text, PowerShell accepts and returns objects, so there is no need to parse text output.

A cmdlet is one PowerShell command, named Verb-Noun. The verb says the action; the noun says the target. Get-Service, Set-ItemProperty, Invoke-WebRequest.

Bridge from your floor. Your Bash instincts transfer. One habit retires: awk and cut have no job here, because objects arrive whole. Filter with Where-Object; project with Select-Object.

The domain: identity and policy

Active Directory Domain Services (AD DS) is the directory for a Windows network. Per its overview: it stores user and computer accounts, one username and password works network-wide, and administration is policy-based. A domain join registers a server's computer account there. Identity flows from the domain after that.

A Group Policy Object (GPO) is a declared set of Windows settings, stored in the domain and pushed to member computers. Both PowerShell controls below arrive this way: the Turn on Script Execution policy and the Turn on PowerShell Script Block Logging policy. gpupdate forces a policy refresh on demand.

PowerShell also carries DSC, Desired State Configuration: configuration as code that enforces settings and reports on configuration drift.

Bridge. GPO and DSC are Terraform's shape on Windows: declared state, applied everywhere, corrected when it drifts. You already think this way.

Windows under STIGs

DISA's STIG library covers Windows client and server. The Windows set is among the largest, and most rules land as GPO settings: password and lockout policy, Defender on, script block logging on, allowlisting configured.

The scan loop matches Lesson 0003. Windows STIG content publishes in SCAP form, and DISA's SCAP Compliance Checker (SCC) plays the oscap role. The finding decision matches too: fix, or carry a POA&M entry.

Bridge. Rocky was one host hardened by hand. Windows at scale is the same loop, with the domain doing the delivery.

PowerShell with an audit trail

PowerShell is the admin tool and a favored attack path, so the STIGs watch PowerShell itself. Three controls, strongest last.

Execution policy gates which scripts run. Microsoft's own words on its page: the execution policy is defense in depth, a user bypasses it easily, and it prevents unintentional violations. It stops accidents. Set it by GPO anyway.

Script block logging records the content of script blocks as PowerShell processes them, interactive or automated: Event ID 4104 in the Operational channel. Module logging records pipeline execution for named modules. Protected Event Logging encrypts sensitive log content with a public key, decrypted only at the central collector.

Allowlisting (application control, CM-7 least functionality) decides what code runs at all. The strongest control, and the heaviest to operate.

Interview traps. The pipeline carries objects; text parsing has no job. Execution policy prevents accidents; allowlisting prevents execution. Script block logging is Event 4104; a logon is 4624. PowerShell 7 installs beside the built-in 5.1; know which one you are running. GPO carries the STIG baseline; hand-edited registry settings drift.
