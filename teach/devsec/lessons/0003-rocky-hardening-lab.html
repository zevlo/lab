DevSec Engineering · Lesson 0003

Lab: Harden Rocky Linux Against the STIG

Why this lesson. The postings require “Linux (RHEL, RockyOS) administration and hardening.” In an interview, “I have run oscap against the DISA STIG profile and remediated findings” must be a sentence you have earned. Today you earn it.

One win. You build one Rocky 9 VM on Proxmox, run a baseline STIG scan, fix three findings, re-scan, and watch the failure count drop. Measurable. Real.

Timebox. About 90 minutes, install included. The runbook holds the condensed commands.

Warm-up — retrieve first

Three questions from Lessons 0001-0002, from memory. Retrieval before a lab primes the vocabulary you will use inside it.

Which command lists the profiles inside an SCAP data stream?

A rule that fails its check produces what?

Which severity blocks operation until it is fixed?

Trap in question three. “Critical” is not a STIG severity. STIG uses High, Medium, Low. A confident wrong answer here is exactly what an interviewer probes.

The lab

Work through the steps in order. Tick each box as you finish; your progress is saved in this browser.

  • # on the VM
sudo dnf install -y openscap-scanner scap-security-guide
  • ls /usr/share/xml/scap/ssg/content/

    Trap, learned in the field. Rocky's data stream is ssg-rl9-ds.xml — rl for Rocky Linux — not ssg-rocky9-ds.xml. Guess the wrong name and oscap answers Unable to open file. Read the directory before you type the path.

  • oscap info /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml | grep -i stig
  • sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_stig \
  --results /tmp/results-before.xml \
  --report /tmp/report-before.html \
  /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml | tail -4
  • # on the Mac
scp user@vm-ip:/tmp/report-before.html . && open report-before.html

    Record two numbers: total failed rules, and High findings. Write them down. You will compare after fixing.

  • sudo tee /etc/issue <<'EOF'
Authorized use only. All activity may be monitored and recorded.
EOF
printf 'Banner /etc/issue\n' | sudo tee /etc/ssh/sshd_config.d/99-stig-banner.conf
sudo sshd -t && sudo systemctl reload sshd

    Pattern to keep. sshd -t validates before the reload applies. Broken SSH on a remote box is a resume-generating event. Validate, then apply — same instinct as terraform plan before apply.

  • printf 'PermitRootLogin no\n' | sudo tee /etc/ssh/sshd_config.d/99-stig-rootlogin.conf
sudo sshd -t && sudo systemctl reload sshd
    Before you reload. Open a second terminal and prove your admin user can log in and sudo. Only then reload. Never cut the branch you sit on.
  • sudo dnf update -y && sudo reboot
  • sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_stig \
  --results /tmp/results-after.xml \
  --report /tmp/report-after.html \
  /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml | tail -4

    Compare with your baseline numbers. Fewer findings — that delta is your work, measured.

Report your numbers

Bring these to your teacher at the next session:

Baseline: failed ___ of ___ · High ___ · After: failed ___ of ___ · High ___ · Remediate kept? yes / no / rolled back

Field report — first full run, Sep 2026. Baseline: failed 257 of 434 · High 11. After manual fixes (banner): failed 256 · High 11. After --remediate + reboot: failed 20 · High 4 — kept. 236 findings closed by one command, zero rollbacks. The survivors are the lesson: grub2 password pair (needs interactive input), FIPS (needs a conscious decision), vendor-support on Rocky (permanent, documented exception), five partition rules (build-time fixes, not in-place).

Say it in an interview

I hardened Rocky 9 against the DISA STIG with oscap: baseline scan, targeted fixes — banner, root login, patching — then re-scan to prove the delta.
Automatic remediation I treat like any deploy: snapshot first, measure blast radius, roll back if it breaks.
Primary source. The Red Hat 9 security hardening guide, chapter on compliance and vulnerability scanning. It documents the same oscap workflow on RHEL, and Rocky follows RHEL. Skim docs.rockylinux.org for Rocky-specific notes.

Your teacher is this agent. When you finish — or when a finding confuses you, or oscap errors out — bring it here. Real labs generate real questions; that is the point.
