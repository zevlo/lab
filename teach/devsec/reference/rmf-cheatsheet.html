RMF Cheat Sheet

Companion to Lesson 0001. Sources: NIST SP 800-37r2, SP 800-53/53A/53B, FIPS 199, SP 800-137, DoD Cyber Exchange.

The seven steps

#StepAnswersKey inputKey output
1PrepareAre we ready?Org policy, common controlsReadiness, tailoring rules
2CategorizeHow bad if it fails?FIPS 199Impact levels on C-I-A → category
3SelectWhich controls?SP 800-53B baselineTailored control set, in the SysSP
4ImplementAre controls in place?Control set, STIGsHardened system, updated SysSP
5AssessDo the controls work?SP 800-53A proceduresSAP (before), SAR (after)
6AuthorizeIs the risk acceptable?SAR, POA&MATO — or denial
7MonitorIs it still true?ISCM strategy (SP 800-137)Monitoring results, POA&M updates, ongoing authorization

The documents

DocumentAnswersWritten byWhen
SysSP — System Security PlanWhich controls, and how each is implementedBuild teamStep 3, maintained forever
SAP — Security Assessment PlanHow the assessment will runIndependent assessorBefore step 5
SAR — Security Assessment ReportWhat the assessment foundIndependent assessorAfter step 5
POA&M — Plan of Action and MilestonesOpen gaps, owners, due datesBuild team, accepted by AOFeeds step 6, burned down in step 7
RAR — Risk Assessment ReportThreats, vulnerabilities, likelihoodSecurity teamEarly, informs Select

Who is who

RoleDoes
Authorizing Official (AO)Accepts residual risk. Issues or denies the ATO. Never the build team.
System OwnerAccountable for the system across its life cycle.
Independent AssessorTests controls per SP 800-53A. Writes SAP and SAR.
ISSO / ISSMDoD security roles: Information System Security Officer / Manager. Day-to-day security of the system.
CCB — Change Control BoardReviews changes for security impact before deployment.
Risk ExecutiveOwns risk decisions across the organization, above any single AO.

Where the DevSecOps engineer plugs in

StepEngineering hook
PrepareKnow boundary, data types, approved tools. Put compliance targets in the backlog.
CategorizeKnow the category — it sets the rigor of everything downstream.
SelectMap control families (AC, AU, CM, SI) to pipeline capabilities early.
ImplementMost of the work: STIG hardening, secrets in Vault, image scanning.
AssessAutomate evidence: SCAP scans, audit logs, pipeline artifacts.
AuthorizeHonest POA&M entries and clean evidence packages feed the AO decision.
MonitorDrift detection, scheduled re-scans, patch pipelines → continuous compliance.

Interview one-liners

RMF is a life-cycle process: prepare, categorize by impact, select a control baseline, implement, assess independently, authorize by risk decision, monitor continuously.
An ATO is not a safety certificate. It is a senior official's decision to accept residual risk.
In DoD, DISA STIGs make the 800-53 controls concrete, eMASS holds the authorization package, and my job as a DevSecOps engineer is to automate the evidence.
