GitLab CI Cheat Sheet

Companion to Lesson 0006. Sources: Application security testing, SAST, Dependency scanning, Secret detection, CI/CD quick start, Merge request approvals. Control text: SP 800-53 via CPRT.

What is what

TermDefinition
Merge request (MR)One proposed change: a branch, a review, a pipeline, and approvals, in one place.
PipelineOne triggered run of the CI configuration, on push or MR.
StageA group of jobs. Stages run in order; jobs in one stage run in parallel.
JobOne script unit. Belongs to a stage.
RunnerThe agent that executes jobs.
rulesThe keyword deciding when a job runs.
includePulls shared configuration, including GitLab scanner templates.
CI/CD variableA value injected into jobs. Masked, protected.
Approval ruleRequired reviewers, by count, role, or CODEOWNERS. Without them, merging is impossible.
Prevent author approvalThe setting that blocks the MR author from approving their own change. CM-5.
SASTStatic application security testing. Scans your source code for insecure patterns.
Dependency scanningThe SCA class. Scans the dependency list for known CVEs, transitive packages included.
Secret detectionScans repository content and history for committed credentials.
Secret push protectionBlocks a push that contains a credential.
DASTDynamic application security testing. Probes the running application from outside.
Container scanningScans a built image for vulnerable packages.
CVSSThe industry severity score. Scanner severities: Critical, High, Medium, Low, Info, Unknown.

Scanner plumbing

include:
  - template: Jobs/SAST.gitlab-ci.yml
  - template: Jobs/Dependency-Scanning.gitlab-ci.yml
  - template: Jobs/Secret-Detection.gitlab-ci.yml

Templates add jobs in the test stage. Findings surface in the MR before merge. Continuous dependency scanning re-scans when the advisory database updates, with no pipeline run. FIPS-enabled scanner images exist for classified pipelines.

Interview traps

If you hearThe truth
“SAST covers the supply chain”SAST reads your source. Dependencies are dependency scanning's job.
“Critical is a STIG severity”STIG: High, Medium, Low. Critical is a CVSS word.
“Secret detection prevents leaks”Push protection blocks; detection reports. Vault prevents by keeping secrets out of code.
“The pipeline hardens the OS”Scanners gate the application. oscap gates the operating system.
“We approve our own MRs”Author approval is blocked by setting. Separation of duties.

Interview one-liners

GitLab CI maps from GitHub Actions: pipelines for workflows, stages for ordered groups, rules for on, includes for reusable workflows.
The MR is the unit of work: scanners run before merge, every finding gets a decision, approvals are required, and main stays releasable.
SAST reads the code we wrote. Dependency scanning reads the code we imported. Both run on every MR, and the pipeline must pass to merge.
An accepted finding carries a reason, an owner, and a date. The pipeline keeps its own POA&M.
