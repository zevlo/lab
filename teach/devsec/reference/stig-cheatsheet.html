STIG Cheat Sheet

Companion to Lesson 0002. Sources: DISA STIGs (cyber.mil), Red Hat security hardening guide, ComplianceAsCode.

What is what

TermDefinition
STIGSecurity Technical Implementation Guide. DISA's checklist of security requirements for one technology.
SRGSecurity Requirements Guide. The parent document; a STIG instantiates it per product.
RuleOne requirement. Fields: statement, discussion, check, fix, CCI, severity.
CCIControl Correlation Identifier. Maps one rule to one SP 800-53 control.
SCAPSecurity Content Automation Protocol. The standard that makes STIG content machine-readable.
FindingA rule that failed its check. Needs a fix, or an exception with a POA&M entry.

Severity

CurrentLegacyMeansResponse
HighCAT ICatastrophicFix immediately, or do not operate
MediumCAT IISeriousFix on schedule; most rules live here
LowCAT IIIMinorFix when convenient, or document

Workflow

#MoveHow
1ObtainDownload package from cyber.mil/stigs (XML + checklist)
2ReadDISA STIG Viewer; stigviewer.com is a browser convenience, never a citation
3Checkoscap scan, or manual check
4FixManual, script, or Ansible; re-scan to verify
5DocumentResults recorded; exceptions become POA&M entries

OpenSCAP on Rocky / RHEL

# install
dnf install -y openscap-scanner scap-security-guide

# list profiles
oscap info /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml

# scan (DISA STIG profile)
oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_stig \
  --results results.xml --report report.html \
  /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml

# scan and auto-remediate (test first!)
oscap xccdf eval --remediate \
  --profile xccdf_org.ssgproject.content_profile_stig \
  --results results.xml --report report.html \
  /usr/share/xml/scap/ssg/content/ssg-rl9-ds.xml

Content paths: /usr/share/xml/scap/ssg/content/. On RHEL the file is ssg-rhel9-ds.xml; on Rocky it is ssg-rl9-ds.xml (rl = Rocky Linux — there is no ssg-rocky9-ds.xml). ComplianceAsCode also publishes Ansible playbooks per profile.

STIG ↔ RMF touchpoints

RMF stepSTIG connection
SelectControls chosen in SP 800-53; STIG is the implementation guide for them
ImplementApply STIG fixes — most of the engineering work
Assessoscap scan results are assessment evidence for the SAR
AuthorizeOpen findings land in the POA&M; AO accepts the residual risk
MonitorScheduled re-scans detect drift and new findings

Typical rule → control mappings

STIG rule theme800-53 control
Logon bannerAC-8 — System Use Notification
Audit logging enabled and protectedAU family (AU-2, AU-9)
Prompt patchingSI-2 — Flaw Remediation
Account lockout on failuresAC-7 — Unsuccessful Logon Attempts
Removing unused accountsAC-2 — Account Management

Mappings vary per STIG release. Verify the CCI in the rule itself before citing.

Interview one-liners

A STIG is the concrete settings layer of the RMF: the control says what must be true in 800-53, and the STIG rule says which setting makes it true.
I would run oscap as a pipeline gate: fail the build on High findings, and route the rest to the POA&M with owners and dates.
