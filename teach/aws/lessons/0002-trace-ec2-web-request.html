Trace an EC2 web request

A running instance can still be unreachable. Trace each layer to find the first failed condition.

Tangible win

Given an unreachable EC2 web server, you can identify whether the first failure is in its launch settings, network path, machine health, or web process.

Read the launch recipe

An EC2 instance is a virtual server. Its launch settings define the server and its environment. AWS introduces the core EC2 concepts here.

Machine image

The AMI provides the starting operating system and software.

Instance type

The instance type sets compute, memory, and network capacity.

Subnet

The subnet sets the network location and route table.

Public IPv4

The public address gives internet clients a destination.

Security group

Inbound rules permit traffic by protocol, port, and source.

User data

User data can run setup commands when the instance launches.

AWS lists these choices in its instance configuration reference.

Trace from the client to the process

Do not treat “EC2 is down” as one problem. A request crosses several layers. Check each layer until you find the first failure.

HTTP request path
01 Address

The client uses the instance's current public IPv4 address.

02 Route

The subnet routes internet traffic to its internet gateway.

03 Rule

The security group permits TCP port 80 from the client.

04 Machine

The instance is running and its EC2 status checks pass.

05 Process

The web service is running and listening on TCP port 80.

A failure at any layer stops the request.

Important distinction

Running is not the same as healthy.

Instance state: running EC2 has started the virtual machine.
Status checks: passed EC2 detected no supported host or instance problem.
Application: responding The web process accepted and handled the request.

Each signal answers a different question. Passed status checks do not prove that your web process is running. AWS documents what status checks detect.

Work one incident

Observation
  • The instance state is running.
  • All EC2 status checks pass.
  • The subnet has a route to an internet gateway.
  • The instance has a public IPv4 address.
  • The security group permits only TCP port 22.
  • The web process listens on TCP port 80.

The first failed layer is the security group. The network reaches the instance, but no rule admits HTTP traffic on port 80. AWS provides web-server rule examples.
