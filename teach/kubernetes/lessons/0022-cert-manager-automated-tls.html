Lesson 0022 · Kubernetes Fundamentals · TLS automation

cert-manager: Automated TLS for Ingress

Lesson 0008 by hand — now with renewal and a control loop.

Lesson 0008 had you run openssl, create a TLS Secret, and point Ingress at secretName. That works once. At work and on a public homelab, certs expire — operators install cert-manager to request, store, and renew certificates automatically. The Ingress shape from 0008 does not change. What changes: something else owns the Secret lifecycle.

The Idea

cert-manager is a cluster add-on (like metrics-server in 0012 or Traefik in 0003). It watches custom resources and writes standard Kubernetes TLS Secrets [concepts]:

ResourceRole
Issuer / ClusterIssuerWhere certs come from — Let's Encrypt, a corporate CA, or selfSigned for labs
CertificateDesired cert: DNS names, target secretName, which Issuer to use
Secret (kubernetes.io/tls)Output — same keys as lesson 0008 (tls.crt, tls.key)
IngressConsumer — still references spec.tls.secretName; Traefik unchanged

The control loop:

Certificate (desired DNS names + secretName)
  → cert-manager asks Issuer
  → writes / updates TLS Secret
  → Ingress reads Secret for HTTPS
  → cert-manager renews before expiry
Same TLS rules as 0008. Certificate.spec.dnsNames must match Ingress.spec.tls.hosts and rules.host. Secret must live in the same namespace as Ingress and Certificate. HTTP routing still works when only TLS binding breaks.

Lab vs production issuer: Let's Encrypt needs a hostname the CA can reach on the public internet (HTTP-01 or DNS-01 challenge). OrbStack's *.k8s.orb.local names resolve on your Mac only — fine for Traefik, invisible to Let's Encrypt. This lab uses a selfSigned Issuer so the full cert-manager flow runs locally. Production swaps the Issuer for letsencrypt-prod (ClusterIssuer) — same Certificate and Ingress pattern.

Install once per cluster (Helm, like lesson 0014):

helm repo add jetstack https://charts.jetstack.io
helm repo update
helm upgrade --install cert-manager jetstack/cert-manager \
  -n cert-manager --create-namespace \
  --set crds.enabled=true
kubectl rollout status deployment/cert-manager -n cert-manager --timeout=120s
kubectl rollout status deployment/cert-manager-webhook -n cert-manager --timeout=120s

Lab — Issue, mount, break (~30 min)

OrbStack, context orbstack, Traefik from lesson 0003. Lab files in yaml/certmanager-lab/:

cd ~/projects/teach/kubernetes/yaml/certmanager-lab
ls

Expect namespace.yaml, stack.yaml, issuer.yaml, tls-stack.yaml, break/fix YAML pairs. Hostname: api.certlab.k8s.orb.local.

0

SCOPE — cluster add-on + lab namespace.

kubectl config use-context orbstack
kubectl get crd certificates.cert-manager.io 2>/dev/null || echo "cert-manager not installed"

If CRD missing, run the Helm install block above and wait for rollouts. Then:

kubectl apply -f namespace.yaml
kubectl config set-context --current --namespace=certmanager-lab
1

Baseline — app without TLS yet.

kubectl apply -f stack.yaml
kubectl rollout status deployment/api --timeout=60s
kubectl get pods,svc

One Running pod, Service api. No Ingress yet.

2

Issuer + Certificate + Ingress — automated Secret.

kubectl apply -f issuer.yaml
kubectl apply -f tls-stack.yaml
kubectl get issuer,certificate,ingress
kubectl wait --for=condition=Ready certificate/api-tls --timeout=90s
kubectl get secret api-tls

Issuer lab-ca Ready. Certificate api-tls Ready=True. Secret api-tls type kubernetes.io/tls with 2 data keys. Test HTTPS:

curl -sk https://api.certlab.k8s.orb.local/ | head -n 1
curl -s http://api.certlab.k8s.orb.local/ | head -n 1

nginx HTML over HTTPS (-k for self-signed) and HTTP. cert-manager created the Secret — you did not run openssl.

3

Break A — wrong DNS name on Certificate.

kubectl apply -f certificate-bad-dns.yaml
kubectl wait --for=condition=Ready certificate/api-tls --timeout=90s
curl -sk https://api.certlab.k8s.orb.local/ 2>&1 | head -n 5
curl -vk https://api.certlab.k8s.orb.local/ 2>&1 | grep -i subject

Certificate may still show Ready — cert-manager issued a cert, but for api-typo.certlab.k8s.orb.local. HTTPS may handshake with wrong subject or warn on hostname mismatch. HTTP still works.

Your turn:

kubectl get certificate api-tls -o yaml | grep -A3 dnsNames
kubectl describe ingress api | grep -A4 TLS

dnsNames typo vs Ingress tls.hosts / rules.host — same SNI mismatch class as lesson 0008, but fix is in the Certificate manifest, not openssl.

Fix:

kubectl apply -f certificate-fixed.yaml
kubectl wait --for=condition=Ready certificate/api-tls --timeout=90s
curl -vk https://api.certlab.k8s.orb.local/ 2>&1 | grep -i subject

Subject/CN matches api.certlab.k8s.orb.local.

4

Break B — Issuer reference typo; Certificate stuck.

kubectl apply -f certificate-bad-issuer.yaml
kubectl get certificate api-tls
kubectl describe certificate api-tls | tail -n 15

Certificate not Ready — Events mention Issuer not found (lab-ca-typo). Secret may still hold the previous cert until you fix the Certificate — do not trust HTTPS until Ready again.

kubectl get certificaterequest 2>/dev/null | tail -n 3

Recent CertificateRequest may show Failed or no successful issuance.

Fix:

kubectl apply -f certificate-fixed.yaml
kubectl wait --for=condition=Ready certificate/api-tls --timeout=90s
5

Break C — Ingress secretName typo (lesson 0008 replay). Certificate Ready; break only the Ingress binding:

kubectl apply -f ingress-bad-secret.yaml
curl -s http://api.certlab.k8s.orb.local/ | head -n 1
curl -vk https://api.certlab.k8s.orb.local/ 2>&1 | tail -n 10

HTTP still nginx HTML. HTTPS fails or shows wrong/default cert — Ingress points at api-tls-typo but Secret is api-tls.

kubectl get secret api-tls-typo
kubectl get secret api-tls

api-tls-typo NotFound; api-tls exists. cert-manager did its job; Ingress references the wrong name.

Fix:

kubectl apply -f ingress-fixed.yaml
curl -sk https://api.certlab.k8s.orb.local/ | head -n 1
6

Clean up lab namespace. Leave cert-manager installed — cluster add-on for future labs.

kubectl delete namespace certmanager-lab
kubectl config set-context --current --namespace=default
Production note: swap selfSigned Issuer for a ClusterIssuer with acme (Let's Encrypt). You need a real DNS name pointing at your ingress IP and often an Ingress annotation or DNS-01 solver. The Certificate + Ingress wiring you practiced here is the same.

Quiz

3. Certificate stuck; Events say Issuer lab-ca-typo not found. First fix?
