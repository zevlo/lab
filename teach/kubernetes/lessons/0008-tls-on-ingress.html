Lesson 0008 · Kubernetes Fundamentals

TLS on Ingress: Encrypting the Front Door

Certificates as Secrets; HTTPS at Traefik.

Lesson 0003 gave you HTTP routing through one door. Real homelab services and anything at work expect HTTPS — passwords, cookies, and API tokens shouldn't cross the wire in plaintext. TLS on Ingress is how you bolt encryption onto the routing table you already know, using the Secret machinery from lesson 0006 and the namespace discipline from lesson 0007.

The Idea

Ingress can terminate TLS: the client talks HTTPS to the Ingress controller (Traefik on OrbStack); Traefik decrypts and forwards plain HTTP to your Service inside the cluster [docs]. Two hops, two different trust boundaries:

HopEncrypted?
Browser → Traefik (hello.k8s.orb.local:443)Yes
Traefik → PodNo (by default — pod-to-pod TLS is a later topic)

The certificate lives in a TLS Secret — type kubernetes.io/tls, with keys tls.crt and tls.key. You reference it from the Ingress spec.tls block:

spec:
  tls:
  - hosts:
    - hello.k8s.orb.local
    secretName: hello-tls
  rules:
  - host: hello.k8s.orb.local
    http: ...

Three constraints worth memorizing:

  • Hostname match. tls.hosts must align with rules.host — the controller picks the cert via SNI (Server Name Indication) using the client's hostname [docs].
  • Same namespace. The Secret and Ingress (and the backend Service) must share a namespace — a lesson-0007 gotcha.
  • Port 443. Ingress TLS assumes HTTPS on 443; Traefik's Service already exposes it (you saw this in lesson 0003).

Locally you'll use a self-signed certificate — fine for homelab, browsers will warn. In production or a public homelab, operators use cert-manager to obtain and renew real certs (Let's Encrypt). Same Ingress shape; automated Secret creation.

The mental model in one line: the Ingress tls block tells Traefik which Secret holds the cert for which hostname — encryption at the door, routing unchanged.

Lab — Cert, Secret, HTTPS (~25 min)

Against OrbStack. Everything lives in namespace homelab. Work in a scratch directory for cert files (don't commit tls.key to git).

1

Orient. Confirm Traefik still holds ports 80 and 443:

kubectl config use-context orbstack
kubectl get svc traefik

Expect: LoadBalancer with ports 80 and 443. Set your kubectl aim for this lab:

kubectl create namespace homelab --dry-run=client -o yaml | kubectl apply -f -
kubectl config set-context --current --namespace=homelab
2

Deploy the backend — same nginx pattern as before:

kubectl create deployment hello --image=nginx:1.29 --replicas=2
kubectl expose deployment hello --port=80
kubectl get pods
kubectl get svc hello

Verify the app itself — not through Traefik yet (no Ingress exists, so Traefik would return 404 page not found). OrbStack lets you reach ClusterIP Services directly from your Mac:

curl -s http://$(kubectl get svc hello -o jsonpath='{.spec.clusterIP}') | head -n 3

Expect: nginx HTML. Your deployment and Service are fine — Traefik simply has no route for hello.k8s.orb.local until step 4 creates the Ingress.

3

Create a certificate. In your scratch directory:

openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt \
  -subj "/CN=hello.k8s.orb.local" \
  -addext "subjectAltName=DNS:hello.k8s.orb.local"

Load it into the cluster as a TLS Secret ([docs]):

kubectl create secret tls hello-tls --cert=tls.crt --key=tls.key
kubectl get secret hello-tls

Expect: type kubernetes.io/tls, DATA column shows 2 keys. The cert's CN/SAN must match the hostname you'll route — hello.k8s.orb.local.

4

Create ingress-tls.yaml — your lesson-0003 manifest plus a tls block:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: front-door
spec:
  ingressClassName: traefik
  tls:
  - hosts:
    - hello.k8s.orb.local
    secretName: hello-tls
  rules:
  - host: hello.k8s.orb.local
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: hello
            port:
              number: 80
kubectl apply -f ingress-tls.yaml
kubectl get ingress

Hit HTTPS — -k skips trust verification for your self-signed cert. Now Traefik has a route — test HTTP through the door too:

curl -sk https://hello.k8s.orb.local/ | head -n 3
curl -s http://hello.k8s.orb.local/ | head -n 3
curl -vk https://hello.k8s.orb.local/ 2>&1 | grep -E "subject:|issuer:|SSL connection"

Expect: nginx HTML over HTTPS; verbose output shows subject: CN=hello.k8s.orb.local (or similar). Browser: https://hello.k8s.orb.local works after accepting the warning — self-signed, not evil.

If HTTPS doesn't answer: same suspects as lesson 0003 — confirm Traefik is running, the Ingress and TLS Secret exist, and the hostname in your cert matches hello.k8s.orb.local exactly. HTTP on the same hostname still working while HTTPS fails often means a TLS/Secret problem, not a broken routing rule.
5

Break it. In ingress-tls.yaml, typo the Secret reference — change secretName: hello-tls to secretName: hello-tlss — and apply:

kubectl apply -f ingress-tls.yaml

Compare HTTP vs HTTPS — watch the right signal (TLS handshake, not routing):

curl -s http://hello.k8s.orb.local/ | head -n 1
curl -vk https://hello.k8s.orb.local/ 2>&1 | tail -15

Expect: HTTP still returns nginx (routing rule untouched). HTTPS fails or presents Traefik's default certificate — verbose curl may show SSL certificate problem, wrong subject, or handshake errors. The Ingress object still exists; only the TLS binding is broken. Diagnose:

kubectl describe ingress front-door
kubectl get secret hello-tlss   # not found
6

Fix it. Restore secretName: hello-tls, apply, confirm HTTPS again:

kubectl apply -f ingress-tls.yaml
curl -sk https://hello.k8s.orb.local/ | head -n 1

Clean up — delete cert files from disk yourself; remove cluster objects:

kubectl delete -f ingress-tls.yaml
kubectl delete deployment hello
kubectl delete service hello
kubectl delete secret hello-tls
kubectl delete namespace homelab
kubectl config set-context --current --namespace=default
Production path (not labbed today): install cert-manager, define a Certificate CR, it writes the TLS Secret, your Ingress references the same secretName. Homelab with a real domain: DNS points at your IP, Let's Encrypt validates, certs auto-renew.
