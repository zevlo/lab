Lesson 0019 · Kubernetes Fundamentals · Troubleshooting arc

Service and Ingress Path: When Pods Look Fine

Pods Running — traffic still dead. Walk the binding chain outward.

Lessons 0002 and 0003 taught Services and Ingress. Lesson 0017 Break D showed empty endpoints from a selector typo. Lesson 0018 drilled pod-layer failures. This lesson is the networking half of the funnel: when kubectl get pods looks healthy but HTTP does not, the answer is rarely "restart the pod." It lives in the RELATED layer — Service selector, targetPort, EndpointSlice, then Ingress backend — each hop validated in order [debug services].

The Idea

Traffic from your browser to a pod crosses four hops on OrbStack:

curl netlab.k8s.orb.local
  → Traefik (Ingress controller)
  → Service api:80
  → EndpointSlice (pod IP + targetPort)
  → Pod containerPort

Each hop has its own failure mode. The trap: pods can be Running 1/1 while every hop above the pod is wrong.

The inspection order when pods look fine:

STATUS  → pods Running? Ready column 1/1?
RELATED → EndpointSlice for the Service — any ready addresses?
SCOPE   → port-forward svc/<name> — does the Service layer work?
RELATED → describe ingress — backend name and port match a real Service port?
EndpointSlice is the tell. Lesson 0017 used it for selector breaks. An empty endpoints list with healthy pods means stop looking at the Deployment — fix the Service binding. Addresses present but traffic fails means look at targetPort or the app itself.

Requires Traefik from lesson 0003 (kubectl get svc traefik). Hostname netlab.k8s.orb.local resolves on OrbStack automatically.

Lab — Three breaks, one path (~25 min)

OrbStack, context orbstack. Lab files in yaml/network-troubleshoot-lab/:

cd ~/projects/teach/kubernetes/yaml/network-troubleshoot-lab
ls

Expect namespace.yaml, stack.yaml, selector-bad.yaml, selector-fixed.yaml, targetport-bad.yaml, targetport-fixed.yaml, ingress-bad.yaml, ingress-fixed.yaml. For each break: confirm pods are healthy before blaming them.

0

SCOPE — confirm cluster, Traefik, pin namespace.

kubectl config current-context
kubectl get svc traefik
kubectl apply -f namespace.yaml
kubectl config set-context --current --namespace=network-troubleshoot-lab

Expect orbstack. Traefik LoadBalancer on ports 80/443. Namespace created; following commands omit -n.

1

Baseline — healthy path end to end.

kubectl apply -f stack.yaml
kubectl get pods,svc,ingress
kubectl rollout status deployment/api --timeout=60s
curl -s http://netlab.k8s.orb.local | head -n 3

Expect pod Running 1/1, Service api, Ingress netlab with host netlab.k8s.orb.local. curl returns nginx HTML. Optional Service-only check:

kubectl port-forward svc/api 8080:80 &
curl -s localhost:8080 | head -n 3
kill %1

Port-forward works — pods and Service are fine before any break.

2

Break A — selector typo; pods innocent. (Lesson 0017 Break D, now through Ingress.)

kubectl apply -f selector-bad.yaml
kubectl get pods
curl -s -o /dev/null -w "%{http_code}\n" http://netlab.k8s.orb.local

Pods still Running 1/1. curl may return 502 or 503 from Traefik (exact code varies). Your turn: run the funnel — do not open selector-fixed.yaml yet.

kubectl get endpointslice -l kubernetes.io/service-name=api
kubectl get svc api -o yaml | grep -A3 selector
kubectl get pods --show-labels

EndpointSlice has no ready addresses (empty endpoints list). Selector says app: api-broken; pod labels say app: api. Ingress and Deployment are fine — the Service lost its backends.

Fix — restore selector in manifest:

kubectl apply -f selector-fixed.yaml
kubectl get endpointslice -l kubernetes.io/service-name=api
curl -s http://netlab.k8s.orb.local | head -n 3

EndpointSlice repopulates; curl returns nginx HTML again.

3

Break B — wrong targetPort; endpoints misleadingly full.

kubectl apply -f targetport-bad.yaml
kubectl get endpointslice -l kubernetes.io/service-name=api
kubectl port-forward svc/api 8080:80 &
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080
kill %1

EndpointSlice still lists the pod IP — unlike Break A. Port-forward fails or returns 000/502 because kube-proxy forwards to pod port 8080, but nginx listens on 80. Diagnose:

kubectl get svc api -o yaml | grep -E "port:|targetPort:"
kubectl get pod -l app=api -o yaml | grep containerPort

targetPort: 8080 vs containerPort: 80. Selector and labels match — the port map is wrong.

Fix:

kubectl apply -f targetport-fixed.yaml
kubectl port-forward svc/api 8080:80 &
curl -s localhost:8080 | head -n 3
kill %1

Port-forward and Ingress curl both work again.

4

Break C — Ingress points at a Service that does not exist. (Lesson 0003 port mismatch, different shape.)

kubectl apply -f ingress-bad.yaml
curl -s http://netlab.k8s.orb.local

Traefik error page or 502/503 — not nginx HTML. Pods and Service still healthy; port-forward to svc/api still works. Your turn:

kubectl describe ingress netlab
kubectl get svc

describe ingress shows backend api-typo:80. get svc lists api only — no Service named api-typo. The break is one hop above the Service.

Fix:

kubectl apply -f ingress-fixed.yaml
curl -s http://netlab.k8s.orb.local | head -n 3

nginx HTML returns. Same class of bug as lesson 0003's wrong backend port.number — always cross-check Ingress backends against kubectl get svc.

5

Clean up.

kubectl delete namespace network-troubleshoot-lab
kubectl config set-context --current --namespace=default
Work inside-out: confirm pods → EndpointSlice → port-forward Service → Ingress host. Skipping to Ingress when endpoints are empty sends you editing hostnames while the selector is wrong. At work, this sequence is the difference between a five-minute fix and an hour of pod restarts.

Quiz

1. Pods Running 1/1; Ingress returns 502; EndpointSlice for the backend Service is empty. Best first move?

2. EndpointSlice lists pod IPs; port-forward svc/api fails; pod containerPort: 80. Most likely cause?

3. port-forward svc/api returns nginx; curl http://netlab.k8s.orb.local fails. Pods and EndpointSlice healthy. Where next?

4. Pod STATUS Running, READY 0/1; readiness probe failing. Effect on traffic?

5. Teammate restarts pods three times; Ingress still 502; endpoints were empty the whole time. What should have happened first?
