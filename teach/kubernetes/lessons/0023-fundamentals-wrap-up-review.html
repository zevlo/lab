Fundamentals Wrap-Up Review

Twenty-two lessons, one mental model — prove it from memory.

You set out to deploy, expose, scale, and debug on a real cluster — at work and in a homelab. Twenty-two lessons later, the vocabulary is large but the machinery is small: declare desired state, let controllers reconcile, debug the gap. This lesson compresses the arc, drills cross-cutting scenarios, and points you at a longer sign-off quiz. No new objects — only integration.

The whole system in one pass

Kubernetes is not a bag of kubectl tricks. It is a control-loop platform [objects]: you write manifests; the API stores desired state; controllers (Deployment, ReplicaSet, HPA, cert-manager, …) continuously nudge reality toward that state; kubelets run containers on nodes. When something looks wrong, you walk the same path in reverse: SCOPE → STATUS → EVENTS → LOGS → RELATED (0017).

Three mnemonics worth keeping:
· Readiness = membership · Liveness = existence (lesson 0005)
· Preview ≠ deploy — kustomize build, helm template never touch the cluster (0013, 0014)
· HPA CPU % = usage ÷ requests — no requests → <unknown> (0012)

Homelab capstone (~20 min, optional)

On OrbStack, run this audit against whatever you have running — no new YAML required. Practice the funnel out loud.

  1. SCOPE: kubectl config current-context — confirm orbstack.
  2. Workloads: kubectl get deploy,sts,po -A — pick one app namespace; note Ready column vs desired.
  3. Networking: for one Service, kubectl get endpointslice -l kubernetes.io/service-name=<svc> — do ready addresses match Running pods?
  4. Ingress: if Traefik is installed, kubectl get ingress -A — trace host → backend Service → port.
  5. Resources: kubectl top nodes (if metrics-server installed) — if it fails, you know the install gap from lesson 0012.
  6. Storage: kubectl get pvc -A — any Pending? describe pvc if so.
  7. Add-ons: kubectl get pods -n cert-manager / -n kube-system — note what's installed vs not.
Fundamentals complete ≠ expert. Service meshes, operators, cluster bootstrap, and CKA-style multi-cluster ops stay out of scope per MISSION.md. What you have is the foundation to run real workloads and learn the next layer on top.
