Helm

Quick reference — charts, releases, values, rollback.

What it is

Helm packages Kubernetes manifests as charts (Go templates + default values.yaml), installs them as named releases, and tracks revisions for upgrade/rollback. Renders to plain YAML, then applies via the Kubernetes API — same control loop as kubectl apply.

Core terms

TermMeaning
ChartPackage: Chart.yaml, values.yaml, templates/
ReleaseNamed installed instance (helm install my-db ./postgres)
ValuesParameters → {{ .Values.field }} in templates
RevisionIncremented on each install/upgrade/rollback
RepositoryIndex of published charts (helm repo add)

Chart layout

my-chart/
├── Chart.yaml
├── values.yaml
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    └── _helpers.tpl

Preview vs deploy

helm template RELEASE ./chart -n NS --create-namespace   # render only
helm install RELEASE ./chart -n NS --create-namespace    # deploy
helm upgrade RELEASE ./chart -n NS -f staging.yaml       # new revision
helm rollback RELEASE 1 -n NS                            # revert
helm uninstall RELEASE -n NS

Third-party charts (add-on pattern)

helm repo add NAME URL
helm repo update
helm show values REPO/CHART              # read defaults first
helm upgrade --install RELEASE REPO/CHART \
  -n NAMESPACE -f overrides.yaml --set key=value

Override precedence

values.yaml (in chart) → -f files (left to right) → --set (highest). Use helm get values RELEASE -n NS to inspect what a release is running.

Helm vs Kustomize

HelmKustomize
MechanismGo templates + values.yamlOverlays + patches on YAML
LogicConditionals, loops, subchartsNo template language in core
Ship modelPackaged charts / reposPlain dirs in git
LifecycleRelease history + rollbackGit history; kubectl apply -k
Sweet spotVendor charts, complex appsSmall env diffs on your YAML

Diagnostics

SymptomLikely causeCheck
Template ran, cluster emptyUsed helm template not installhelm list -n NS
Upgrade OK, endpoints emptyRendered selector ≠ pod labelshelm template … | grep selector
connection refused on OrbStackWrong kubeconfig contextkubectl config use-context orbstack
Image not retaggedWrong values path or --set keyhelm get values RELEASE -n NS
Release stuck / wrong configBad upgrade revisionhelm history RELEASE -n NS → rollback
Rule of thumb: always helm template (or helm install --dry-run) before install/upgrade. If behavior surprises you, diff the rendered YAML — not just values.yaml.
