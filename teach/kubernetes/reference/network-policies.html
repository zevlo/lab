Network Policies

Quick reference — permit/deny at the pod network layer.

Default behavior

StatePod-to-pod traffic
No NetworkPolicy selects the podAll ingress and egress allowed (default permit)
At least one policy selects the pod for a directionOnly traffic explicitly allowed in that direction
Services ≠ policies. A Service routes to backends; a NetworkPolicy filters whether packets may arrive. Both can be correct while connections still fail.

Policy anatomy

spec:
  podSelector:        # pods this policy APPLIES TO (protected pods)
    matchLabels: …
  policyTypes: [Ingress, Egress]
  ingress:
  - from:             # allowed sources IN
    - podSelector: …
    - namespaceSelector: …
    ports: [{ protocol: TCP, port: 80 }]
  egress:
  - to:               # allowed destinations OUT
    - podSelector: …
    ports: …

Common selectors

FieldScope
podSelector in from/toPods in the same namespace as the policy
namespaceSelectorAll pods in matching namespaces (e.g. kubernetes.io/metadata.name: kube-system)
Combined namespaceSelector + podSelectorPods with labels in matching namespaces (AND)

Egress checklist

When restricting egress, pods usually need:

  • DNS — UDP/TCP port 53 to kube-dns in kube-system
  • App dependencies — target Services/pods on their ports
  • Image registry / external APIs — ipBlock or namespace rules if required
