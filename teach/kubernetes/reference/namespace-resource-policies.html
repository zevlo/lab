LimitRange & ResourceQuota

Quick reference — namespace guardrails above per-pod requests/limits.

Three layers

LayerObjectScopeQuestion it answers
Podresources in container specOne containerHow much does this container promise and may use? [lesson 0009]
NamespaceLimitRangeEach pod/PVC in namespaceWhat defaults apply? What min/max per container?
NamespaceResourceQuotaSum across namespaceHow much can all workloads here consume in total?

ResourceQuota manifest

apiVersion: v1
kind: ResourceQuota
metadata:
  name: team-a-quota
spec:
  hard:
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi
    pods: "20"
    count/deployments.apps: "10"

Common hard keys: requests.cpu, requests.memory, limits.cpu, limits.memory, pods, count/<resource> (object counts). cpu is shorthand for requests.cpu; memory for requests.memory.

LimitRange manifest

apiVersion: v1
kind: LimitRange
metadata:
  name: team-a-limits
spec:
  limits:
  - type: Container
    default:           # injected limit if omitted
      cpu: 500m
      memory: 256Mi
    defaultRequest:    # injected request if omitted
      cpu: 100m
      memory: 128Mi
    max:               # per-container ceiling
      cpu: "2"
      memory: 2Gi
    min:               # per-container floor
      cpu: 50m
      memory: 64Mi

Who enforces what

PolicyWhen checkedTypical failure
LimitRangePod admission (create/update)403 Forbidden — exceeds min/max; or defaults injected then validated
ResourceQuotaPod admission (create/update)403 Forbidden — would exceed namespace aggregate
ResourceQuota (via controller)ReplicaSet/Deployment scale-outReplicaSet FailedCreate — quota already at cap; Deployment looks healthy, pods missing
Neither policy retrofits running pods. Tightening a quota or LimitRange does not restart or evict existing pods — only new creates/updates are blocked. Plan capacity changes accordingly.

Quota + missing resources

When a namespace has a ResourceQuota on cpu or memory, every new pod must declare requests or limits for that resource — otherwise admission may reject it. A LimitRange with defaultRequest / default fills the gap so teams do not have to remember on every manifest.

Useful commands

kubectl get resourcequota,limitrange
kubectl describe resourcequota <name>    # Used / Hard
kubectl describe limitrange <name>     # defaults, min, max
kubectl describe rs <name>             # FailedCreate from quota
kubectl describe quota -n <ns>         # shorthand alias
