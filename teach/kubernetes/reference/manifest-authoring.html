Manifest Authoring

Quick reference — scaffold, strip, validate, apply.

Where YAML comes from

SourceWhen
Copy/edit existing repo manifestDefault at work — sibling service, chart, kustomize base
--dry-run=client -o yamlScaffold a kind you rarely write; homelab greenfield
MemorySmall edits to patterns you already know — not whole files

Scaffold commands

kubectl create deployment api --image=nginx:1.29 --replicas=2 \
  --dry-run=client -o yaml > deployment.yaml

kubectl create service clusterip api --tcp=80:80 \
  --dry-run=client -o yaml > service.yaml

Use create service clusterip, not expose deployment — expose requires the Deployment to already exist in the cluster.

Merge related objects in one file with --- between documents. Drop empty status: from client dry-run Service output. Add probes, resources, env — dry-run won't include those.

Strip before git commit

Never commit output from kubectl get … -o yaml blindly. Delete server-owned fields:

RemoveWhy
status: (entire block)System-written; spec/status split
resourceVersion, uid, generationIdentity/version metadata from the API
creationTimestampSet by server on create
managedFieldsServer-side apply bookkeeping

Client dry-run output is usually already clean. Cluster export is not.

Validate before apply

kubectl apply --dry-run=server -f app.yaml   # admission + schema; no write
kubectl diff -f app.yaml                     # file vs live cluster
kubectl apply -f app.yaml                    # declarative desired state
FlagRuns wherePersists?
--dry-run=clientLocal kubectlNo — generates YAML only
--dry-run=serverAPI serverNo — validates against admission
kubectl diffAPI server compareNo — shows unified diff

Apply succeeded but app broken?

Valid YAML + successful apply ≠ working app. Check relationships in the file:

SymptomLikely manifest bugCheck
Service unreachableSelector ≠ pod labelskubectl get endpoints, describe svc
Rollout stuckProbe too strict / bad targetPortkubectl describe pod, rollout status
Pending podResource requests too largedescribe pod Events

Next layer (not raw YAML)

Helm — charts + values.yaml (lesson 0014). Kustomize — base + overlays per env (lesson 0013). Both emit YAML you still apply (or they apply for you). Same control loop; less copy-paste.

Rule of thumb: scaffold with dry-run → edit spec → server dry-run + diff → apply → diagnose with describe/get/endpoints if behavior surprises you.
