Security context and Pod Security Standards

Quick reference — process privileges on the node, and how admission enforces them.

One sentence: A security context sets the Linux process (UID, capabilities, privileged mode). Pod Security Admission enforces a Pod Security Standards profile on a namespace. RBAC is a separate axis: API verbs, not the node.

Two axes

ControlQuestion it answers
ServiceAccount + RBACWho is this workload to the API, and which verbs may it call?
Security contextWhich user ID and Linux capabilities does the process have on the node?
Pod Security AdmissionDoes this namespace allow that Pod spec at all?

Pod versus container fields

spec.securityContext          → PodSecurityContext (UID, seccomp, fsGroup)
spec.containers[].securityContext → SecurityContext
                                  (overrides UID; privileged, caps, allowPrivilegeEscalation)

Container fields override overlapping Pod fields. Volumes follow the Pod fsGroup, not the container UID fields.

Restricted profile (minimum to remember)

FieldRequired value
runAsNonRoottrue (Pod or every container)
runAsUserNot 0
allowPrivilegeEscalationfalse
capabilities.dropMust include ALL
capabilities.addEmpty, or only NET_BIND_SERVICE
seccompProfile.typeRuntimeDefault or Localhost (must be set)
privilegedNot true (already required by baseline)

For the full control list, see Pod Security Standards.

Namespace labels

pod-security.kubernetes.io/enforce: restricted
pod-security.kubernetes.io/enforce-version: v1.33   # pin in production
pod-security.kubernetes.io/warn: restricted
pod-security.kubernetes.io/audit: restricted
ModeEffect
enforceRejects the Pod. Does not reject the Deployment object.
warnUser-facing warning. Workload objects included.
auditAudit annotation. Workload objects included.
Diagnosis: if kubectl apply -f deploy.yaml succeeds but replicas never become Ready, read ReplicaSet events for FailedCreate and violates PodSecurity. That is admission, not a crash loop.

Common spec conflicts

SpecResult
runAsNonRoot: true and runAsUser: 0Kubelet refuses to start the container.
runAsNonRoot: true, no UID, image runs as rootSame: the image USER is still 0.
privileged: trueMost isolation is off. allowPrivilegeEscalation is effectively true.
