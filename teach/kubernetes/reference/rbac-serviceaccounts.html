RBAC & ServiceAccounts

Quick reference — identity for pods, permissions for the API.

One sentence: A ServiceAccount is who the Pod is; a Role lists verbs on resources; a RoleBinding attaches that Role to that ServiceAccount in a namespace.

Identity vs permission

ObjectJob
ServiceAccountNamespaced identity for Pods (and automation). Not a human user.
Role / ClusterRolePermission set: apiGroups + resources + verbs. Additive only — no deny rules.
RoleBinding / ClusterRoleBindingGrants a role to subjects (User, Group, ServiceAccount).
Pod.spec.serviceAccountName → ServiceAccount (who)
Role / ClusterRole          → rules (what)
RoleBinding / ClusterRoleBinding → subjects + roleRef (grant)

Scope cheat sheet

BindingRole kindWhere permissions apply
RoleBindingRole (same ns)That namespace only
RoleBindingClusterRoleStill only the RoleBinding's namespace
ClusterRoleBindingClusterRoleCluster-wide (all namespaces / cluster objects)
Trap: A RoleBinding that references a ClusterRole does not grant cluster-wide access. Namespace of the binding wins.

ServiceAccount subject form

subjects:
- kind: ServiceAccount
  name: secret-reader
  namespace: rbac-lab   # required when binding outside the SA's ns;
                       # in same-ns RoleBinding, often set explicitly anyway
roleRef:
  kind: Role           # or ClusterRole
  name: secret-reader
  apiGroup: rbac.authorization.k8s.io

Impersonation string for checks: system:serviceaccount:<namespace>:<sa-name>

Diagnose with auth can-i

# As a ServiceAccount (not as your admin kubeconfig user)
kubectl auth can-i list secrets \
  --as=system:serviceaccount:rbac-lab:secret-reader \
  -n rbac-lab

kubectl auth can-i get pods --as=system:serviceaccount:rbac-lab:secret-reader -n rbac-lab
# expect: no  (unless Role grants pods)

Your OrbStack admin context can often do everything — that does not mean the Pod can. Always pass --as=… when checking workload identity.

Defaults worth remembering

  • Every namespace has a default ServiceAccount. Pods without serviceAccountName get it.
  • default has no special RBAC powers beyond discovery — grant least privilege to a dedicated SA.
  • Tokens mounted into Pods are short-lived projected tokens (TokenRequest), not long-lived Secret tokens.
  • roleRef on a binding is immutable — change the role by deleting and recreating the binding.
