Persistent Storage

Quick reference — PV, PVC, StorageClass, binding.

What it is

Pods are ephemeral — a container's root filesystem is recreated on every restart. PersistentVolumeClaims request durable storage that outlives any single pod. A StorageClass tells the cluster how to provision that storage dynamically.

Three objects

ObjectScopeRole
PersistentVolume (PV)ClusterActual storage chunk (NFS, cloud disk, hostPath…)
PersistentVolumeClaim (PVC)NamespaceApp's request: size, access mode, storage class
StorageClassClusterProvisioner + defaults (reclaim policy, binding mode)

Binding flow

PVC created  →  controller finds matching PV
              OR  StorageClass provisioner creates PV  →  Bound
Pod mounts PVC via volumes.persistentVolumeClaim.claimName

Pod wiring

spec:
  containers:
  - name: app
    volumeMounts:
    - name: data
      mountPath: /var/lib/data
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: my-pvc

Access modes

ModeAbbrevMeaning
ReadWriteOnceRWOOne node read/write (most common — databases)
ReadOnlyManyROXMany nodes read-only
ReadWriteManyRWXMany nodes read/write (needs shared filesystem)

PVC spec (minimal)

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: local-path
  resources:
    requests:
      storage: 1Gi

Volume types compared

VolumeSurvives pod restart?Use for
emptyDirNo (deleted with pod)Scratch space, sidecar handoff
ConfigMap / SecretN/A (config, not app data)Settings files (patterns)
PVCYes (bound to PV)Databases, uploads, app state

OrbStack / local clusters

kubectl get storageclass
# If empty, install local-path provisioner once:
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.30/deploy/local-path-storage.yaml

StorageClass local-path uses WaitForFirstConsumer — PVC stays Pending until a pod that mounts it is scheduled.

Diagnostics

SymptomLikely causeCheck
PVC Pending foreverNo StorageClass / wrong namekubectl describe pvc NAME events
PVC Pending, SC existsWaitForFirstConsumer — no pod yetSchedule a pod mounting the PVC
Pod Pending, unbound PVCsPVC not Boundkubectl get pvc; fix SC or size
Data gone after pod restartUsed emptyDir not PVCPod spec volumes section
Helm chart DB won't startPVC can't bindkubectl get pvc -n RELEASE
Rule of thumb: the PVC is the contract; the PV is the backing store; the pod is temporary — mount the PVC, don't bake state into the container layer.
