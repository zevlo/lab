Configuration Patterns

Quick reference — ConfigMaps, Secrets, and how pods consume them.

Which Object?

DataObjectWhy
Log level, feature flags, nginx.conf, HTML templatesConfigMapNon-confidential; safe in manifests and logs
Passwords, API tokens, TLS private keys, registry credsSecretConfidential; kept out of images and pod specs
Secrets are not magic encryption. Values are base64-encoded at rest in etcd by default — readable by anyone with API or etcd access. Use RBAC, encryption at rest, and external secret stores in production.

Minimal YAML Snippets

ConfigMap — key/value and multi-line file content:

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  LOG_LEVEL: info
  app.properties: |
    cache.ttl=300
    retries=3

Secret — values must be base64 (or use kubectl create secret generic):

apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
stringData:          # plain text; API encodes for you
  API_TOKEN: s3cr3t

Env var from ConfigMap key:

env:
- name: LOG_LEVEL
  valueFrom:
    configMapKeyRef:
      name: app-config
      key: LOG_LEVEL

Volume mount (live-updating files):

volumeMounts:
- name: config-vol
  mountPath: /etc/app
  readOnly: true
volumes:
- name: config-vol
  configMap:
    name: app-config
