cert-manager

Quick reference — automated TLS Secrets for Ingress.

Control loop

Issuer / ClusterIssuer  →  who signs certs
Certificate             →  desired DNS names + secretName
Secret (kubernetes.io/tls)  →  output (tls.crt, tls.key)
Ingress                 →  spec.tls.secretName (consumer)

Install (Helm, once per cluster)

helm repo add jetstack https://charts.jetstack.io
helm upgrade --install cert-manager jetstack/cert-manager \
  -n cert-manager --create-namespace \
  --set crds.enabled=true

Lab issuer (local)

apiVersion: cert-manager.io/v1
kind: Issuer
metadata:
  name: lab-ca
  namespace: certmanager-lab
spec:
  selfSigned: {}

Certificate + Ingress wiring

apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: api-tls
spec:
  secretName: api-tls          # must match Ingress tls.secretName
  issuerRef:
    name: lab-ca
    kind: Issuer
  dnsNames:
  - api.certlab.k8s.orb.local  # must match Ingress tls.hosts + rules.host

Diagnostics

Let's Encrypt fails on OrbStackCA cannot reach *.k8s.orb.localUse real public DNS for ACME; selfSigned locally

Core commands

kubectl get issuer,certificate -n <ns>
kubectl describe certificate <name> -n <ns>
kubectl get certificaterequest -n <ns>
kubectl wait --for=condition=Ready certificate/<name> -n <ns>
kubectl get secret <secretName> -n <ns>
Production: ClusterIssuer with ACME (Let's Encrypt) + HTTP-01 or DNS-01. Optional Ingress annotation cert-manager.io/cluster-issuer: … auto-creates Certificate (ingress-shim).
