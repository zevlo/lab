Horizontal Pod Autoscaler

Quick reference — automatic replica count from metrics.

What it does

HPA is a controller that watches metrics and patches a workload's spec.replicas to keep utilization near a target. It scales the Deployment (or StatefulSet, etc.) — the Deployment's ReplicaSet then creates or removes pods, same as manual kubectl scale.

ComponentRole
HPA controllerReads metrics → computes desired replicas → updates workload spec.replicas
metrics-serverAggregates pod CPU/memory usage from kubelets; powers kubectl top and resource metrics for HPA
Deployment / ReplicaSetCreates pods to match the replica count HPA sets
SchedulerPlaces new pods using requests — HPA does not bypass allocatable limits

CPU utilization formula

For type: Resource / cpu / Utilization:

utilization = (sum of pod CPU usage) / (sum of pod CPU requests) × 100%

Every pod in the metric must declare resources.requests.cpu. Missing requests → metrics show <unknown> and HPA cannot scale on CPU.

Manifest (autoscaling/v2)

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: php-apache
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: php-apache
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50

Imperative shortcut (same object):

kubectl autoscale deployment php-apache --cpu-percent=50 --min=1 --max=5

OrbStack setup (one-time)

OrbStack does not include metrics-server. Install it, then enable pod-level stats:

helm repo add metrics-server https://kubernetes-sigs.github.io/metrics-server/
helm upgrade --install metrics-server metrics-server/metrics-server \
  --namespace kube-system --create-namespace

Kubelet configuration (OrbStack Settings → Kubernetes → Kubelet Configuration):

apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
featureGates:
  PodAndContainerStatsFromCRI: true

Restart Kubernetes in OrbStack after editing. Verify: kubectl get apiservice v1beta1.metrics.k8s.io → Available; kubectl top pod -A works.

HPA vs manual scale

kubectl scale changes replicas immediately, but HPA reconciles on its loop (default ~15s). If you scale above maxReplicas, HPA scales back down. If you scale below minReplicas, HPA scales back up. Long term, HPA owns replica count while it exists.

Interactions

Policy / objectEffect on HPA
ResourceQuota (pods or CPU requests)HPA may request more replicas than quota allows — ReplicaSet FailedCreate, partial scale-out
Node allocatableNew pods may stay Pending if requests exceed free capacity — HPA desired > running
RollingUpdatePod template changes do not delete HPA; it keeps adjusting replicas on the new template
ReadinessNew pods join Service EndpointSlices only when Ready — scale-up ≠ instant traffic capacity

Useful commands

kubectl get hpa
kubectl describe hpa <name>           # Conditions, Events, current metrics
kubectl top pod                         # sanity-check metrics pipeline
kubectl get deploy <name> -w            # watch replica count during load
kubectl autoscale deployment <name> --cpu-percent=50 --min=1 --max=5
Homelab note: On OrbStack you may need to install metrics-server and enable the PodAndContainerStatsFromCRI kubelet feature gate. A single node still has finite allocatable CPU — HPA may hit the ceiling before maxReplicas. That is real behavior, not a lab bug.
