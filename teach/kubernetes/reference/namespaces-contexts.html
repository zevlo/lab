Namespaces & Contexts

Quick reference — scope, DNS, and kubectl targeting.

Namespace scope

In a namespaceCluster-scoped (no namespace)
Pod, Deployment, Service, ConfigMap, Secret, IngressNode, Namespace, StorageClass, PersistentVolume, ClusterRole

Names are unique within a namespace, not cluster-wide. Two Deployments can both be named web in different namespaces.

Built-in namespaces: default, kube-system, kube-public, kube-node-lease. Avoid creating namespaces with the kube- prefix.

Cross-namespace DNS

FromTo reach Service api in namespace prod

Different namespaceapi.prod.svc.cluster.local (FQDN required)

kubectl targeting

GoalCommand
One requestkubectl get pods -n homelab
All namespaceskubectl get pods -A
Default for this shellkubectl config set-context --current --namespace=homelab
See current targetkubectl config view --minify
Switch cluster+defaultskubectl config use-context orbstack

Context = cluster + user + default namespace

kubectl config get-contexts
kubectl config current-context
kubectl config view --minify

Config lives in ~/.kube/config (OrbStack also writes under ~/.orbstack/k8s/). A context binds which cluster you talk to, as which user, defaulting to which namespace when you omit -n.

Homelab habit

Don't run real workloads in default. Create purpose namespaces (homelab, media, monitoring) and set your context default, or always set metadata.namespace in manifests.
